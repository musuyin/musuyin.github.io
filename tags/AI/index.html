    Agent 模型调用

    一次模型请求由消息、工具定义和生成配置共同组成。上下文由应用或服务会话机制显式维护，不能因为模型名称相同就假设它记得上一轮，也不能把输出上限当作输入窗口。

  • 2026-10-28

    Agent 工具调用

    工具调用有模型契约与执行实现两部分：模型看到名称、描述和参数形状，运行时负责校验、授权、执行并回填结果。MCP 统一接入协议，不自动替 Host 完成权限控制。

  • 2026-09-18

    Hello World

    跨语言互操作依赖线上契约：字段、方法、状态机、错误与流事件都必须一致。SDK 是语言适配层，注册、健康与路由是控制面，两者都不能替代协议本身的兼容测试。

  • 2026-09-15

    LangChain 核心原理与使用

    Tool Calling 只产生工具请求，工具是否能执行仍由运行时校验。学习 LangChain 时先观察完整消息序列，再引入 createagent、结构化输出和中间件，避免把框架接口误当成业务正确性保证。

  • 2026-09-15

    LangChain 与 LangGraph 工程实践

    生产变更助手的关键是分配决定权：模型提取候选请求，确定性代码校验与授权，有权限的人审批，执行服务以稳定 operationid 处理副作用。图把这些环节连接起来，但不接管每类数据的权威所有权。

  • 2026-09-15

    LangChain 与 LangGraph 学习总览

    按应用层与运行时层理解两套工具：LangChain 封装模型、消息、工具与常见 Agent 接口；LangGraph 表达状态、节点、路由和可恢复执行。先完成最小工具循环，再学习持久化与审批，比先记 API 名称更容易建立联系。

  • 2026-09-15

    LangGraph 核心原理与使用

    把图理解为对 State 的逐步变换：Node 产生更新，Reducer 决定如何合并，Edge 决定下一步。Checkpoint 记录进度；Interrupt 恢复时节点会重新执行，因此恢复能力必须与副作用幂等一起设计。

  • 2026-09-14

    Skill

    Skill 的延迟加载分开处理“发现候选流程”和“读取流程正文”。向量筛选、意图分类和任务结束后裁剪是可选设计；它们不是所有 Agent 框架都会采用的固定流水线。

  • 2026-09-11

    记忆机制

    记忆设计先决定信息的生命周期，再决定存储和取回方式。当前输入、上下文历史、结构化事实与长期资料承担不同职责；向量检索只是召回手段，不能代替有效期、来源和冲突管理。

  • 2026-09-11

    Multi-Agent

    多智能体系统让多个 Agent 分工完成同一目标。收益来自上下文与职责拆分，是否值得采用取决于任务能否形成清晰的子问题和验收接口。

  • 2026-09-07

    RAG

    RAG 的检索目标是可追溯、权限正确且足够完整的证据。解析、分块、索引、召回、重排和上下文组装构成同一链路，任何一环丢掉来源或条件都可能影响回答。

  • 2026-09-03

    项目行为与AI面试场景

    行为面试应把项目事实、方案判断和协作方式连成一条可追问的证据链。文中的项目和性能数字属于原稿提供的材料，使用前仍需能解释测量口径与本人负责范围。

  • 2026-07-23

    心得

    Harness 的主线是组织输入、可靠调用模型，并把模型请求接到真实环境。各章可以按它们改变哪一段执行链来复习。

  • 2026-07-23

    Comprehensive

    综合系统把前面的机制放回同一个循环：请求组装决定模型看到什么，执行管线决定能做什么，持久状态决定如何继续。学习重点是机制之间的先后和冲突，而不是代码体量。

  • 2026-07-22

    Error Recovery

    恢复策略取决于失败类型：输出截断、输入超限和临时服务故障需要不同处理。重试是带上限的状态迁移，不能只把相同请求无限重发。

  • 2026-07-22

    Sandbox

    并行目录隔离解决覆盖冲突，操作系统沙箱解决越权访问，两者目标不同。多用户场景还需要考虑身份、凭据、共享对象库和进程资源。

  • 2026-07-22

    Agent Team

    持续协作需要比临时子任务更多的生命周期管理。文件收件箱传递消息，Lead 和队友各自消费通知，权限请求还要能回到有权决定的入口。

  • 2026-07-22

    Team Protocols

    团队协议为消息增加可验证的请求—响应关系：请求标识、期望响应类型和完成状态共同决定一次协商是否结束。关闭、审批等操作因此可以先收尾再退出。

  • 2026-07-22

    Worktree Isolation

    Worktree 把任务映射到独立工作目录与分支，避免多个 Agent 相互覆盖工作区文件。它隔离版本开发状态，不能限制 Bash 越界访问，也不能代替容器安全边界。

  • 2026-07-22

    Autonomous Agents

    自治 Agent 在 WORK 与 IDLE 之间循环：空闲时扫描依赖满足且未认领的任务，认领后执行，完成后继续寻找工作。自治提高调度效率，但仍依赖共享状态的一致更新。

  • 2026-07-22

    Background Tasks

    后台执行把启动与收集结果分离：主循环先获得任务标识，工作完成后通过通知重新进入上下文。生命周期、输出存储和失败回收必须一起考虑。

  • 2026-07-22

    Cron Scheduler

    Cron 负责判断何时产生工作，队列负责把工作交给执行循环。调度器与 Agent 不应互相阻塞，持久任务和会话任务也要区分保存范围。

  • 2026-07-22

    MCP Plugin

    MCP 接入把工具发现、Schema 和调用统一到协议接口，Agent 仍通过原有工具分发路径使用它们。插件接入扩展能力，也扩展了需要验证的信任边界。

  • 2026-07-22

    Task System

    任务系统把目标、状态、依赖和 owner 放进可恢复的记录。先检查依赖，再原子认领，完成后解锁下游；这些语义比展示一个待办列表更严格。

  • 2026-07-22

    Skill 设计

    好的 Skill 描述任务和触发场景，正文再交代输入、流程、交付与检查。比较两个 Skill 时，应看模型能否据此选择并完成任务，而不是仅比较格式是否完整。

  • 2026-07-21

    Memory

    持久记忆与压缩摘要承担不同生命周期：摘要维持当前任务，文件与索引保存跨会话知识。读取选择、提取写入与低频整理共同决定记忆是否有用。

  • 2026-07-21

    Hooks

    Hook 把日志、校验和其他扩展放到稳定执行点，减少主循环中的业务分支。阅读时区分调用前、调用后和停止阶段，并追踪 Hook 的阻止结果如何影响后续流程。

  • 2026-07-21

    Todo Write

    Todo 把当前任务的步骤和状态显式放进模型可见上下文，帮助偏离后的回到目标。它改善注意力管理；跨 Agent 的依赖、认领和持久恢复需要后面的任务系统。

  • 2026-07-21

    Context Compact

    上下文压缩按成本分层：先裁剪和占位，再把大结果落盘，最后才用模型总结历史。每次压缩都要追踪被删信息是否仍能通过文件、索引或摘要找回。

  • 2026-07-21

    Skill Loading

    Skill 加载把“有哪些知识”与“知识正文”分开。模型先看到触发信息，用到时再读取具体流程，避免所有任务都携带无关手册。

  • 2026-07-21

    Subagent

    子 Agent 的直接收益是隔离探索过程：子任务只接收必要输入，父任务拿回结果，避免把全部中间对话堆进主上下文。上下文隔离不等于进程、文件或权限隔离。

  • 2026-07-21

    System Prompt

    系统提示词应从已知运行状态组装：按段描述能力和约束，按模式选择需要的内容，再利用稳定部分的缓存。不要让关键词猜测替代当前权限、工具和项目的真实状态。

  • 2026-07-21

    Permission

    权限判断控制工具能否执行，不能由提示词中的安全承诺代替。教学版用 deny、ask、allow 展示顺序；生产分析进一步区分验证、规则来源、自动审批与向父 Agent 冒泡。

  • 2026-07-20

    Claude Code 指令手册

    这份手册按交互、会话、上下文、权限和扩展整理命令。复习时先区分普通对话、终端执行与斜杠命令，再查相应入口；快捷键和命令是否可用取决于版本与终端环境。

  • 2026-06-12

    Agent Loop

    最小循环把人工转发变成程序反馈：发送消息与工具定义，保存模型响应，执行工具，再把结果交回模型。理解时同时跟踪 messages 的增长和循环何时停止。

  • 2026-06-12

    Brief

    用“模型选择行动，Harness 提供执行条件”串起课程：消息循环是主干，工具、权限、上下文和协作机制分别解决不同的工程约束。课程中的 Claude Code 源码分析属于特定快照，文件行号和常量应作为阅读线索。

  • 2026-06-12

    Tool Use

    工具扩展包含两个契约：Schema 告诉模型如何请求，handler 决定程序实际执行什么。查表分发让循环保持稳定，但参数验证和权限检查仍必须发生在真实执行之前。

  • 2026-04-17

    Agent

    Agent 如何把一个目标转化成行动，又由谁判断任务已经完成？从模型、工具和运行时的分工入手，再看工作流、规划和验收如何约束执行。可从 智能体学习路径 找到相关主题。

  • 2025-10-02

    硅谷小智

    硅谷小智将对话记忆、预约工具、RAG 与流式响应组成一条服务链。先确认用户与会话隔离，再区分知识问答与修改预约的工具调用；流式输出还需要前后端接口同时适配。

  • 2025-10-02

    LangChain4j

    LangChain4j 通过模型适配、AI Services、记忆、工具和检索组件组织 Java LLM 应用。学习时先跑通单次模型调用，再逐步引入会话隔离、持久化、工具执行与 RAG，避免把所有能力混成一个接口。
