Git Worktree

2026-09-02

#Git

手头的功能还没做完，又要从 main 开始修一个问题时，可以用 git worktree 给修复任务开一个独立目录。原目录里的未提交改动会留在原地，修复目录可以单独切分支、测试和提交。

工作目录如何隔离

同一仓库的 worktree 共享 Git 对象、本地分支引用和默认仓库配置。每个 worktree 有自己的 HEAD、暂存区和工作目录。Git 默认只允许一个 worktree 检出某个本地分支。遇到分支已占用时，用 git worktree list 找到对应目录。Git worktree 文档

workspace/
├── project/                 main
└── project-fix-issue-123/    fix/issue-123

从主干开始一项修复

在已有的仓库目录更新远程引用，然后从 origin/main 创建分支和目录。当前 worktree 可以继续停留在原分支上。

git fetch origin
git worktree add -b fix/issue-123 ../project-fix-issue-123 origin/main
cd ../project-fix-issue-123
git status --short --branch

-b 创建新分支。创建后先确认当前分支为 fix/issue-123，再修改和测试。提交修复后，使用 git push -u origin fix/issue-123 推送该分支，然后创建 PR。

让主目录回到主干

如果主目录当前检出了需要保留的功能分支，先用 git status --short --branch 检查状态。需要随分支转移的改动先提交到该功能分支。确认工作目录干净后，再切换到 main，释放该功能分支供新 worktree 检出。

git switch main
git pull --ff-only origin main
git worktree add ../project-feature feat/example

如果 --ff-only 因分支分叉而失败，先用 git log --oneline origin/main..main 检查本地独有提交，确认它们应该保留在哪个分支，再继续同步。临时修改也可以单独建一个短期分支，减少主目录切换时的干扰。

同步功能分支与处理冲突

在功能 worktree 中更新远程引用。若该分支由自己维护，且团队采用 rebase 工作流，可把功能提交重放到最新的 origin/main 上。

git fetch origin
git rebase origin/main

遇到冲突时，用 git status 找到冲突文件。修改并验证后，将已解决的文件加入暂存区，再运行 git rebase --continue。需要恢复到本次 rebase 开始前的状态时，运行 git rebase --abort。如果 Git 提示跳过已经应用的提交，检查相应补丁是否已在上游，再验证重放后的结果。Git rebase 文档

已推送的分支在 rebase 后通常需要更新远程历史。确认该分支允许重写，并检查远程新增提交后，可用 git push --force-with-lease origin fix/issue-123。不带显式预期值的 lease 以本地远程跟踪引用为准。后台 fetch 会刷新该引用，需要锁定已核对的提交时，可使用带显式预期提交的 --force-with-lease=<refname>:<expect>。Git push 文档

查看与清理 worktree

git worktree list

列表显示路径、提交和检出的分支，也可能显示 detached HEAD。若目标分支已经在列表中，直接进入对应目录。若临时 worktree 处于 detached HEAD，需要保留新提交时，在该目录创建一个分支来引用这些提交。

PR 合并后，确认功能 worktree 干净且分支上的工作已经保留。在主目录执行清理。

git worktree remove ../project-fix-issue-123
git fetch --prune origin
git branch -d fix/issue-123

git branch -d 会检查合并状态。若 PR 通过 squash 合并而 Git 拒绝删除分支，先核对功能改动和本地独有提交。已经手动删除目录时，可以先用 git worktree prune --dry-run --verbose 查看待清理的记录，再用 git worktree prune 清理到期的失效记录。仍存在的工作目录使用 git worktree remove 清理。Git worktree 文档
