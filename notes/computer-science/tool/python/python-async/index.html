Python 异步编程：async/await/yield

2026-05-26

#Python#异步

理解主线

async def 创建协程函数，调用先得到协程对象；await 交出当前协程的执行机会，异步生成器再用 yield 按次产生结果。把创建、调度和消费分开，才能读懂流式链路。

背景：为什么需要异步

程序运行时有两类操作：CPU 密集型（计算）和 IO 密集型（网络请求、读写磁盘、查数据库）。IO 操作的特点是：发出请求之后，CPU 只是在等待，什么也不做。

同步方式下，等待是阻塞的——后面的任务必须排队：

调 Claude API（等 3 秒）→ 查数据库（等 1 秒）→ 总共 4 秒

异步方式下，等待期间 CPU 可以去处理其他任务：

调 Claude API（发出请求，不等）
查数据库（发出请求，不等）
等两个都回来 → 总共 3 秒

核心思想：等待 IO 的时候，把 CPU 让出去干别的事。

async def

协程函数（coroutine function）的声明方式。async def 告诉 Python：这个函数内部可能会暂停，让出 CPU 给别人用。

普通函数 async def 函数
调用后 立刻执行，必须等完 返回一个协程对象，不执行
能否暂停 否 能，通过 await 暂停
使用场景 CPU 计算 IO 操作、网络请求 
# 普通函数：调用即执行
def fetch_sync():
    return "done"

# 协程函数：调用返回协程对象，需要被 await 或放入事件循环才执行
async def fetch_async():
    return "done"

await

在 async def 函数内部使用，表示**“我在等，别人可以先跑”**。

执行到 await 时，当前协程主动暂停，将控制权交还给 asyncio 事件循环；事件循环可以去运行其他协程，等待的结果回来后再恢复执行。

类比：餐厅点菜后，服务员（CPU）不会站在你桌旁干等，而是去服务其他桌。你的菜好了再回来通知你。

async def stream(self, inp):
    # 暂停，等 Anthropic 服务器响应
    # 暂停期间，事件循环可以处理其他请求
    async with self._client.messages.stream(...) as sdk_stream:
        ...

常见错误：忘写 await

result = some_async_func()        # 错：只拿到协程对象，函数根本没执行
result = await some_async_func()  # 对：真正执行并等待结果

yield

把函数变成生成器（generator），每次产出一个值，调用方拿到一个、处理一个，不需要等全部完成。

# 普通函数：全部算完才返回
def get_all():
    return [1, 2, 3]

# 生成器函数：每次 yield 一个，调用方按需消费
def gen():
    yield 1   # 产出 1，暂停
    yield 2   # 产出 2，暂停
    yield 3   # 产出 3，结束

结合 async 就是 async generator，是流式输出场景的核心：

async def stream(self, inp):
    yield AgentStartEvent(...)        # 立刻推给前端："开始了"
    async for event in sdk_stream:
        yield BlockDeltaEvent(...)    # 每收到一个 token，立刻推出去
    yield AgentDoneEvent(...)         # 最后推："完了"

对比不用 yield 的错误方式——用户体验是“转圈等待，一次性刷出所有内容”：

async def stream_bad(self, inp):
    events = []
    async for event in sdk_stream:
        events.append(event)    # 全部收集
    return events               # 全部完成才返回，前端一卡一卡

yield 的关键价值：边生产边消费，实现真正的实时流式输出。

三者组合：完整链路示例

以 AgentHub 项目的流式输出为例，三个关键字协同工作：

Claude API
  —[yield]→  ClaudeAdapter.stream()
  —[async for + await]→  ThreadService._run_thread()
  —[await]→  StreamService.push_event()
  —→  SSE 队列  —→  前端

ThreadService 消费 Adapter 产出的事件：

# async for 隐含了 await，每个事件到来就处理一次
async for event in adapter.stream(stream_input):
    await stream_service.push_event(conversation_id, event)

ClaudeAdapter 产出事件：

async def stream(self, inp):
    yield AgentStartEvent(...)
    async with self._client.messages.stream(...) as s:  # await 等 API 建立连接
        async for event in s:                            # 边收 SDK 事件边处理
            yield BlockDeltaEvent(...)                   # 立刻向上层传递
    yield AgentDoneEvent(...)

每产出一个 token，整条链路就推送一次，用户看到的是字符逐渐出现的实时效果，而不是等待后一次性刷出。
