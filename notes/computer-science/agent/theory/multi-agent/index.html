Multi-Agent

2026-09-11

#AI#Agent

理解主线

多智能体系统让多个 Agent 分工完成同一目标。收益来自上下文与职责拆分，是否值得采用取决于任务能否形成清晰的子问题和验收接口。

为什么拆分

单个 Agent 的上下文有限，长流程容易积累无关细节；让同一参与者兼顾搜索、编码和评审，也会增加职责切换成本。多 Agent 可以分工，但结果仍需要沟通与整合。

协作模式

模式 工作方式 阅读重点
顺序流水线 A 的产物交给 B，再交给 C 上游输出是否满足下游输入
并行扇出 调度者分发独立子任务，最后汇总 子任务是否独立、谁负责合并
辩论或评审 各自提出方案，再互评或由裁判比较 比较依据与验收条件是否明确

代码评审和方案选型适合讨论取舍，但参与者数量本身不能证明结论正确，仍应回到证据。

组织方式

中心化方案由调度者分配任务、跟踪进度并汇总结果，责任与排障入口较清楚。去中心化方案让 Agent 自行协商、直接通信，需要把协调规则和共享状态表达清楚。

复习

对同一任务先划定独立子任务，再选择协作模式，说明各参与者的输入、产物，以及失败或输出冲突时由谁处理。
