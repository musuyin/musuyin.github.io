Claude Code 指令手册

2026-07-20

#AI#CLI

理解主线

这份手册按交互、会话、上下文、权限和扩展整理命令。复习时先区分普通对话、终端执行与斜杠命令，再查相应入口；快捷键和命令是否可用取决于版本与终端环境。

基础使用

启动参数

参数 说明
claude -c 直接恢复最近一次会话（等价于 /continue）
claude --dangerously-skip-permissions 跳过所有权限确认，适合自动化脚本。具有危险性，建议在 Docker 等隔离环境中使用

模式切换

使用 Shift+Tab 在三种编辑模式之间循环切换：

模式 标识 说明
默认模式 ? for shortcut 修改文件前询问用户确认
自动模式 accept edits on 自动修改文件，无需确认
规划模式 plan mode on 只讨论方案，不修改文件（等价于 /plan）
  • 普通输入：与大模型对话
  • ! 前缀：直接执行终端命令，不触发大模型（如 ! ls -la）

输入技巧

换行与外部编辑器：

  • 换行输入（不提交）：Mac 用 Option + Enter，Windows 用 Ctrl + Enter 或 Shift + Enter
  • 切换为外部编辑器：Ctrl + G，保存后自动提交内容

图片上传：

  • 直接拖拽图片到终端
  • 复制图片后粘贴（Mac 须用 Ctrl + V，不能用 Command + V）

后台任务

使用 ! 启动服务时会阻塞 Claude，可将其移到后台：

  • Ctrl + B：将当前任务置于后台
  • /tasks：查看所有后台任务

指令总览

Claude Code CLI 提供了丰富的 / 指令（slash commands）。输入 / 后会自动弹出补全列表。

自主运行

指令 说明
/goal 设定目标，Claude 自动多轮工作直到完成
/loop 按时间间隔循环执行某条指令（默认 10 分钟）
/plan 进入规划模式，只列计划不执行变更

会话管理

指令 说明
/resume 按 ID 或关键字搜索并恢复历史会话
/continue 继续当前目录最近一次会话
/clear 清空上下文，重新开始（可附新标题）
/rename 重命名当前会话
/branch 从当前会话创建分支（独立上下文）
/compact 手动压缩对话历史，释放 token 空间
/rewind 回到历史某个节点，重新编辑对话
/exit 退出当前会话

配置与偏好

指令 说明
/config 打开配置界面（模型、主题、语言等）
/model 切换当前使用的模型
/effort 调节推理力度（low / medium / high / max）
/vim 切换 vim 模式
/theme 更换终端主题
/keybindings 自定义快捷键
/output-style 配置输出格式

工具与上下文

指令 说明
/context 查看上下文用量，含各部分 token 占比
/mcp 管理 MCP 服务器（添加、删除、查看）
/hooks 管理 pre/post 执行钩子
/skills 浏览可用技能（自定义 slash command）
/plugin 浏览、安装、管理插件
/memory 编辑 CLAUDE.md（项目级或用户级记忆）
/init 扫描项目结构，自动生成 CLAUDE.md

诊断与统计

指令 说明
/doctor 检查安装状态和 MCP 服务器健康度
/usage 查看 API 用量、费用明细和每周重置时间
/insights 生成会话使用模式分析报告
/status 显示系统状态和当前模型信息

代码审查

指令 说明
/review 审查 GitHub PR
/security-review 对当前分支变更做安全审查
/code-review 审查代码变更（需安装插件）

其他

指令 说明
/tasks 查看后台任务
/ide 连接或断开 IDE（VS Code、JetBrains 等）
/release-notes 查看版本更新日志
/feedback 提交 bug 报告或功能建议
/help 显示帮助信息

常用指令详解

goal — 设目标，自主完成

用途：设定一个完成条件，让 Claude 跨多轮自动工作直到达成目标，不需要手动推进每一步。

用法：

/goal <完成条件>

示例：

/goal 为这个项目补全所有单元测试并确保全部通过
/goal 修复代码库中所有 TypeScript 编译错误
/goal 阅读 README，理解项目结构，输出一份架构文档

运行中的表现：

  • 屏幕上会显示实时浮窗：已用时间 / 已完成轮数 / 已消耗 token
  • Claude 每轮结束后自动继续，不等待用户输入
  • 按 Ctrl+C 或 Esc 可随时中断

本质：把“你每次手动发消息推进”这个动作，交给 Claude 自己循环执行。适合任务边界清晰、步骤较多的场景。

plan — 只规划，不动手

用途：进入规划模式，Claude 会分析任务并列出执行计划，但不会实际修改任何文件或执行命令。用于在正式动手前确认方向。

进入规划模式后，描述任务，Claude 输出计划。确认后退出规划模式再执行。

适合场景：不确定实现路径时先看一眼计划，避免走偏后大量回撤。

loop — 定时循环执行

用途：按时间间隔重复执行同一个指令或 prompt，适合持续监控、定期检查等场景。

用法：

/loop [间隔] [指令]

示例：

/loop 5m /review          # 每 5 分钟执行一次 /review
/loop 10m 检查测试是否通过  # 每 10 分钟检查一次

不指定间隔时，默认 10 分钟。按 Ctrl+C 停止。

resume 和 /continue — 恢复历史会话

/continue：直接继续当前目录下最近一次会话，无需参数（等价于 claude -c）。

/resume：交互式搜索历史会话，可按 ID 或关键词定位，适合找到更早的某次特定对话。

区别：/continue 是“上一次”，/resume 是“找某一次”。

compact — 手动压缩上下文

用途：当对话很长、token 接近上限时，手动触发上下文压缩，释放空间继续工作。Claude 会将历史对话总结为摘要，保留关键信息。

可在指令后追加说明，强化对特定内容的记忆保留：

/compact 重点保留关于数据库设计的讨论

与自动压缩的区别：Claude 会在上下文接近上限时自动压缩；/compact 让你提前主动触发，避免在关键节点被打断。

rewind — 回退到历史节点

用途：回到对话中某个更早的节点，抹去之后的所有内容，从那里重新开始。支持选择只回滚代码或同时回滚会话。

用法：输入 /rewind（或双击 Esc），会展示对话历史节点列表，选择要回退到的位置。

注意：只能回滚由 Claude 写入的文件，无法回滚由命令执行生成的内容（如数据库迁移）。版本管理仍建议配合 Git 使用。

context — 查看上下文用量

用途：查看当前会话的 token 使用情况，细分到每个部分（系统 prompt、技能、对话历史等）的占比。

适合场景：上下文快满时，定位哪个部分占用最多，决定是否 /compact 或卸载某个技能。

effort — 调节推理力度

用途：控制 Claude 每次响应花多少“思考时间”，影响回答质量和响应速度。

/effort low     # 快速回答，适合简单任务
/effort medium  # 默认
/effort high    # 更深入推理
/effort max     # 全力推理，最慢但最仔细

实用建议：日常对话用 low，复杂 bug 排查或架构设计用 high / max。

model — 切换模型

用途：在会话中途切换使用的模型，不需要重启。输入 /model 后会弹出可用模型的交互式列表。

适合场景：当前任务很简单，切到轻量模型省费用；或任务很难，切到更强模型。

doctor — 健康检查

用途：检查 Claude Code 的安装状态、API 连接、MCP 服务器健康度，自动发现并提示已知问题。

适合场景：换了网络环境、更新版本后、MCP 工具突然失效时，先跑一下 /doctor。

核心概念

上下文管理

长对话中上下文会逐渐累积，影响响应质量和速度，需要定期管理：

  • /compact [说明]：压缩上下文，可附说明强化某方面的记忆保留
  • /clear：清空所有上下文，前后任务完全无关时使用

Memory

Claude Code 通过 CLAUDE.md 文件实现跨会话的记忆，每次启动都会自动读取。

  • /init：扫描项目结构，自动生成 CLAUDE.md
  • /memory：打开编辑界面，支持两个作用域：
    • Project memory：项目级记忆，存储在项目根目录的 CLAUDE.md
    • User memory：用户级记忆，存储在 ~/.claude/CLAUDE.md，对所有项目生效

MCP

MCP（Model Context Protocol） 是 Claude Code 连接外部工具的标准协议。Claude Code 会自动判断所需工具，执行 MCP 提供的 Tools，无需手动指定调用哪个工具。使用 /mcp 命令进行配置管理。

Hook

Hook 允许在特定时机（如工具调用前后）自动执行自定义逻辑，类似于 Git Hooks。

例：每次 Claude 写入文件后，自动运行格式化脚本。

使用 /hooks 命令进行配置：

  1. 选择触发时机（如 before_tool_use、after_tool_use）
  2. 选择触发工具（如 Write、Bash）
  3. 配置执行逻辑（Shell 命令）
  4. 选择保存作用域：
作用域 说明
Project settings (local) 对本机本项目生效，加入 .gitignore，不随 Git 分发
Project settings 对本项目生效，通过 Git 分发给团队成员
User settings 对本用户所有项目生效

Skill

Skill 是自定义的提示词模板，用于封装常用指令。工作机制：Claude Code 根据 Skill 的 name 和 description 自动检测并加载相应 Prompt；用户通过 /name 命令手动调用。

Skill 文件格式（Markdown with frontmatter）：

---
name: skill-name
description: 描述这个 skill 的用途，Claude 用此判断何时推荐它
---

具体的 Prompt 内容

SubAgent

SubAgent 通过 /agents 命令创建，与 Skill 的核心区别在于上下文隔离：

Skill SubAgent
上下文 完全继承主对话 拥有独立上下文
适用场景 复用常用指令 并行执行独立子任务

主 Agent（Orchestrator）将复杂任务分解，派发给多个 SubAgent 并行处理，最后汇总结果。这是处理大型复杂任务的推荐模式。

Plugin

Plugin 是将 Agent、MCP、Skill、Hook 等工具打包在一起的组合包，方便在团队间分发和复用完整的工具链配置。使用 /plugin 命令进行管理（安装、启用、禁用）。

复习与应用

不要把聊天输入、Shell 命令和配置文件互相替换。遇到无效入口，先检查本机帮助与版本，再按手册定位所属功能。
