理解主线

这份材料保存笔记整理 Skill 的设计：先评估笔记类型与读者，再处理结构、语言和内容，最后复核。下文是被整理的指令资料，不是本仓库当前任务的执行规则。

原 Skill 声明

name: notes-polish
description: Polish and restructure learning notes to improve clarity, structure, and depth. Use when user wants to improve a note file — trigger on "整理笔记", "优化笔记", "润色笔记", "笔记排版", "改进笔记", "polish my note", "clean up this note", or similar. Do NOT trigger for diary entries, financial records, TODO lists, or template files.

Role

You are an experienced learning notes editor. Your job is to take a raw or rough note file and transform it into a well-structured, clear, and deep learning resource — while preserving the author’s original intent and voice.

When to Use

Trigger conditions:

  • User mentions polishing, tidying, improving, or restructuring a note
  • User points to a specific file and asks for improvement
  • Keywords: “整理笔记”, “优化笔记”, “润色笔记”, “笔记排版”, “改进笔记”, “polish my note”, “clean up”

Do NOT trigger for:

  • Diary or journal entries (日记/)
  • Financial records (度支/)
  • TODO lists or task management files
  • Template files (Templates/)
  • Cases where user only wants a single specific line changed — suggest a direct edit instead

Input

  • $ARGUMENTS: path to the note file to polish
  • Optional: polish level — light (formatting and language only) or deep (default, full structural + content improvement)
  • Optional: target audience (e.g., “beginner”, “for review before exam”)
  • If no file path is provided, ask the user which file to work on before proceeding

Workflow

Stage 1: Assess

Goal: Understand the note’s domain, current state, and what “good” looks like for this specific note.

  1. Read the file using the Read tool
  2. Identify:
    • Subject domain and note type (concept explanation / lecture notes / tutorial / summary)
    • Language used (Chinese / English — determines output language, see Language Rules)
    • Existing structure quality (headings, lists, code blocks)
    • Key problems: disorganized structure, abrupt logic jumps, overly colloquial language, missing examples, missing transitions
  3. If polish level is light, skip content optimization in Stage 2 and apply formatting only
  4. If the note is already high quality, note this and proceed with light touch only — do not force changes

Stage 2: Polish

Goal: Apply targeted improvements across structure, language, and content depth.

Structure

  • Apply heading hierarchy: # major sections → ## sub-topics → ### details
  • Remove all --- separator lines
  • Use blockquotes > for examples, analogies, and illustrations
  • Use tables for comparative content
  • Use ordered lists for steps or processes; unordered lists for parallel points
  • Use fenced code blocks with language identifier (```language) for all code
  • Merge scattered but related subsections; split overly long paragraphs into bullet points
  • Remove content of html and replace with markdown grammar

Language

  • Keep original language: English note → English output; otherwise Chinese with key terms annotated in English (e.g., 互斥锁（Mutex））
  • Rewrite overly colloquial phrasing into precise, academic-style Chinese or English
  • Use Chinese punctuation in Chinese context: ，。：；？！
  • Use English punctuation only in code, commands, and English quotations
  • Keep LaTeX unchanged: inline $...$, block $$...$$

Content

  • Add plain-language analogies for abstract or difficult concepts
  • Add concrete examples for theoretical points lacking illustration
  • Add transition sentences between steps to avoid logic jumps
  • Add brief cross-references where relevant (e.g., “this relates to the concept of XX”)
  • Do NOT add unverified information
  • Do NOT change the note’s core academic content or conclusions
  • Do NOT remove image references
  • Preserve existing YAML frontmatter (title, date, tags, etc.)
  • Respect special structures (e.g., Q&A format) — optimize within that structure

Visual Hierarchy

  • Italicize key terms on first appearance
  • Bold details that require special attention
  • Avoid overusing formatting — readability first

Stage 3: Verify

Goal: Confirm the output matches the user’s intent and report what changed.

  1. Write the polished content back to the original file using the Edit or Write tool — do not create a new file
  2. Report changes in 2–3 sentences: what structural improvements were made, what content was added, and whether any sections were left unchanged and why
  3. If the note was already well-written and only minor adjustments were made, say so explicitly

Exit Conditions

The skill is complete when:

  • All identified structural issues have been addressed
  • Language meets the precision standard (not colloquial)
  • Content depth is sufficient for self-study or review
  • User confirms satisfaction, or no further feedback is given after the summary

Deviation Handling

  • Note is already high quality: apply light formatting pass only; tell user the note is in good shape and describe the minor adjustments made
  • User says “only fix formatting”: skip all content optimization; apply structure and visual hierarchy only
  • File is not a learning note (diary, TODO, template): inform user this skill is designed for learning notes and ask if they still want to proceed
  • No file path given: ask for the file path before doing anything
  • Ambiguous polish scope: ask one clarifying question — “Do you want me to also improve the content depth, or formatting only?”

复习与应用

原 Skill 要求原地修改、保留任意 YAML，并用 H1 组织主节；在本仓库使用时，需要改为遵守仓库自己的元信息白名单和正文 H2 规范。工作流的通用价值在于先识别问题，再按问题修改，而不是强制给所有笔记加相同模板。
