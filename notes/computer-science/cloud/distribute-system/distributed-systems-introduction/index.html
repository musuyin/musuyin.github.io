#分布式#MIT6824

理解主线

分布式系统通过协作提供一个服务，收益来自并行、复制和部署位置，复杂度来自并发与局部失败。分析系统时同时画数据分区、复制关系和失败后可继续的路径。

Distributed system: a group of computers cooperating to provide a service

Why Use Distributed System

  • To increase capacity via parallel processing
  • To tolerate faults via replication
  • To match distribution of physical devices
  • To increase security via isolation

Challenges

  • Concurency
  • Complex interactions
  • Partial failure
  • Performance bottlenecks

Infrastructure

  • Storage
  • Communication
  • Computation

Goal

Hide the complexity of distribution from applications.

Performance

A common goal: scalable throughput

  • Increase the number of computers to increase the performance.
  • NNN x servers -> NNN x total throughput via parallel CPU, RAM, disk, net.
  • Scaling gets harder as NNN grows
    • e.g. load imbalance.

Fault Tolerance

A large number of servers, big network -> constant failures

Hide failures:

  • High availability: Service continues despite failures.
  • Recoverability: Service can recover from breakdown.

Tools:

  • Non-volatile storage: Avoid having to write the non-volatile storage too much
  • Replication: If one server crashes, can proceed using the other(s).

Consistency

  • General-purpose infrastructure needs well-defined behavior.
    • e.g. read(x) yields the value from the most recent write(x).
  • Guaranteeing specified behavior is hard.
    • e.g. “replica” servers are hard to keep identical.

Two kind of consistency

  • Strong Consistency: having reads actually see, be guaranteed to see the most recent write.
    • Very expensive to implement.
  • Weak Consistency

Tradeoffs

Fault-tolerance, consistency, and performance are enemies.

  • Fault tolerance and consistency require communication but communication is often slow and hard to scale up
    • e.g., send data to backup server
    • e.g., check if cached data is up-to-date
  • Many designs sacrifice consistency to gain speed.
    • e.g. read(x) might not yield the latest write(x)

Implementation

  • RPC
  • Threads
  • Concurrency control

复习与应用

用容量扩展与故障容忍两个需求分别解释为什么要分布式；增加机器为什么也可能降低可用性？
