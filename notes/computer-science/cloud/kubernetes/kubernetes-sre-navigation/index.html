SRE运维实践导航

2026-08-13

#Cloud#Kubernetes

理解主线

这份导航把对象知识映射到可靠性实践：发布、容量、观测、安全、故障域和恢复各有验收证据。学习时用一项真实服务逐项补齐，避免把配置清单当成已经具备的能力。

Kubernetes SRE 运维实践导航

目标：把基础对象知识转为可执行的 SRE 能力：安全发布、可观测、容量保护、故障恢复与复盘。

建议学习顺序

基础对象（L01-L06）
├── 应用交付：L08 工作负载 → L10 高可用
├── 流量链路：L04 Service → L07 网络进阶
├── 容量治理：L02 Pod → L09 调度与资源治理
├── 生产保障：L11 安全 → L12 可观测性
└── 平台运维：L13 集群运维

生产运维最小基线

  • 可用性：Deployment 配置合理的 readinessProbe、livenessProbe/startupProbe、滚动更新策略和 PodDisruptionBudget。
  • 资源：关键服务配置 CPU/内存 requests 与 limits；监控 CPU throttling、OOMKilled、重启次数与 Pending 时长。
  • 可观测性：服务采用 RED（请求率、错误率、延迟），节点/容器采用 USE（利用率、饱和度、错误）；告警必须附带 Runbook。
  • 变更安全：变更可审计、可灰度、可回滚；发布后以核心 SLI 在稳定观察窗口内回归为验收标准。
  • 安全：使用 Namespace、最小权限 RBAC、专用 ServiceAccount、Pod Security Admission、NetworkPolicy 与外部密钥管理；禁止将真实密钥提交到 Git。
  • 故障域：关键服务至少跨 Node 分散，有条件时跨可用区；PDB、优雅终止和 Node drain 流程经过演练。
  • 灾备：etcd、PV 业务数据和关键配置分别备份，定期验证恢复并记录 RPO/RTO。

通用排障顺序

# 先看状态、事件和近期变更
kubectl get pods -A -o wide
kubectl get events -A --sort-by=.lastTimestamp
kubectl rollout history deployment/<name> -n <namespace>

# 再看单个工作负载的声明、事件和日志
kubectl describe pod/<pod> -n <namespace>
kubectl logs pod/<pod> -n <namespace> --all-containers --previous
kubectl get pod/<pod> -n <namespace> -o yaml

# 最后验证服务后端和连通性
kubectl get endpointslice -n <namespace> -l kubernetes.io/service-name=<service>
kubectl run netcheck -n <namespace> --rm -it --restart=Never --image=curlimages/curl -- sh

操作前确认影响范围；故障时优先恢复服务，再定位根因。删除、重启、扩容和回滚均需记录时间、操作者与验证指标。

建议完成的实践案例

  • 模拟 CrashLoopBackOff：通过日志、事件、探针与退出码定位并修复。
  • 完成一次 Deployment 灰度发布和回滚：记录 maxSurge、maxUnavailable、观察指标与回滚条件。
  • 模拟 Service 无后端：利用 selector、readiness 和 EndpointSlice 排查。
  • 模拟 PVC Pending 或挂载失败：区分 StorageClass、PV/PVC 绑定和 CSI 事件。
  • 配置 Namespace 默认拒绝 NetworkPolicy，再逐项放行 DNS、入口与业务依赖。
  • 对同一服务完成 Ingress 和 Gateway API 路由，并根据 status.conditions 排障。
  • 发布一个 StatefulSet：验证稳定 DNS、独立 PVC、分区更新和故障替换。
  • 创建失败的 CronJob：排查时区、并发策略、超时、退出码与重试。
  • 为 Namespace 配置 LimitRange 与 ResourceQuota，并观察 admission 拒绝信息。
  • 使用 HPA 产生 Pending Pod，观察 Node 自动扩容链路与缩容保护。
  • 执行 Pod SIGTERM 和 Node drain 演练，验证 PDB、优雅终止与核心 SLI。
  • 为普通业务启用 Restricted Pod Security，并用最小权限 ServiceAccount 访问指定资源。
  • 为一个核心 API 定义 SLI/SLO、错误预算、多窗口告警与 Runbook。
  • 创建 etcd 快照，在隔离环境完成恢复演练并记录 RPO/RTO。
