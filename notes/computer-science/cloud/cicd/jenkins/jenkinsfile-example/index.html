Example of a Jenkinsfile

2026-08-07

#Jenkins#Cloud#DevOps

理解主线

这份示例通过共享库与参数把基础设施操作接入 Jenkins。先找参数校验与 ACTION 分支，再看代码检出、配置修改、提交或 PR；共享库和内部镜像是运行前置条件。

@Library(value='piper-lib-os', changelog=false)
@Library(value='piper-lib', changelog=false)
@Library(value='haas-jenkins-lib', changelog=false)

_

def pythonDockerImage = 'dockerio.int.repositories.xxx/python:3.14.6'

pipeline {
    agent any
    options {
        skipDefaultCheckout()
        timestamps()
        disableConcurrentBuilds(abortPrevious: false)
    }
    parameters {
        string(name: 'LANDSCAPE', description: 'Landscape name (e.g. hc-eu14)')
        string(name: 'CLUSTER_TYPES', description: 'Space-separated cluster types (e.g. hdl hana orchestration dmi). For delete: leave empty to remove the whole landscape entry.')
        string(name: 'JIRA_TICKET', defaultValue: 'INT', description: 'Jira ticket to prefix commit and PR titles (e.g. HDBAAS2-12345). Defaults to INT.')
    }
    stages {
        stage('Init') {
            steps {
                script {
                    if (!env.ACTION) {
                        error("ACTION environment variable must be set to 'allocate' or 'delete' in the pipeline config.")
                    }
                    checkout scm
                    setupPipelineEnvironment script: this,
                        appContainer: [
                            githubOrg: 'DBaaS',
                            githubRepo: 'csi-team-yellow'
                        ]
                }
            }
        }
        stage('Maintain CIDR') {
            steps {
                checkout scm
                cloneRepository('Docs', 'DBaaS', 'master', 0)
                withCredentials([usernamePassword(credentialsId: 'jaasId', usernameVariable: 'GITHUB_USER', passwordVariable: 'GITHUB_TOKEN')]) {
                    dockerExecute(script: this, dockerImage: pythonDockerImage) {
                        sh """
                            pip install -r tests/requirements.txt --quiet
                            python3 scripts/network-cidr-automation/maintain_cidr.py ${env.ACTION} \\
                                --landscape ${params.LANDSCAPE} \\
                                ${params.CLUSTER_TYPES ? "--cluster-types ${params.CLUSTER_TYPES}" : ""} \\
                                --network-cidr-file Docs/docs/overviews/networkCIDR.yaml
                        """
                    }
                    script {
                        def branch = "${env.ACTION}-cidr-${params.LANDSCAPE}-${env.BUILD_NUMBER}"
                        sh """
                            cd Docs
                            git config user.email "jenkins@sap.com"
                            git config user.name "Jenkins"
                            git checkout -b "${branch}"
                            git add docs/overviews/networkCIDR.yaml
                            git commit -m "[${params.JIRA_TICKET}] ${env.ACTION.capitalize()} network CIDR for ${params.LANDSCAPE}"
                            git push "https://\${GITHUB_USER}:\${GITHUB_TOKEN}@github.com/musuyin/Docs.git" "${branch}"
                        """
                        def prBody = "Automated CIDR ${env.ACTION} for landscape '${params.LANDSCAPE}'${params.CLUSTER_TYPES ? " (cluster types: '${params.CLUSTER_TYPES}')" : ""}"
                        def prResponse = sh(
                            script: """curl -s -X POST \\
                                -H "Authorization: token \${GITHUB_TOKEN}" \\
                                -H "Content-Type: application/json" \\
                                -d "{\\"title\\": \\"[${params.JIRA_TICKET}] ${env.ACTION.capitalize()} network CIDR for ${params.LANDSCAPE}\\", \\"head\\": \\"${branch}\\", \\"base\\": \\"master\\", \\"body\\": \\"${prBody}\\"}" \\
                                https://github.com/api/v3/repos/musuyin/Docs/pulls""",
                            returnStdout: true
                        ).trim()
                        def pr = readJSON(text: prResponse)
                        sh """
                            curl -s -X POST \\
                                -H "Authorization: token \${GITHUB_TOKEN}" \\
                                -H "Content-Type: application/json" \\
                                -d '{"labels": ["AutoMerge", "cidr-automation"]}' \\
                                https://github.com/api/v3/repos/musuyin/Docs/issues/${pr.number}/labels
                        """
                        env.PR_NUMBER = "${pr.number}"
                    }
                }
            }
        }
        stage('Wait for Merge') {
            steps {
                withCredentials([usernamePassword(credentialsId: 'jaasId', usernameVariable: 'GITHUB_USER', passwordVariable: 'GITHUB_TOKEN')]) {
                    script {
                        echo "Waiting for PR #${env.PR_NUMBER} to be merged..."
                        timeout(time: 60, unit: 'MINUTES') {
                            sleep(900)
                            while (true) {
                                sleep(60)
                                def response = sh(
                                    script: """curl -s -H "Authorization: token \${GITHUB_TOKEN}" https://github.com/api/v3/repos/musuyin/Docs/pulls/${env.PR_NUMBER}""",
                                    returnStdout: true
                                ).trim()
                                def prStatus = readJSON(text: response)
                                echo "PR #${env.PR_NUMBER} merged: ${prStatus.merged}"
                                if (prStatus.merged) break
                            }
                        }
                        echo "PR #${env.PR_NUMBER} merged successfully."
                    }
                }
            }
        }
    }
    post {
        cleanup {
            cleanWs(cleanWhenAborted: true, cleanWhenFailure: true, cleanWhenNotBuilt: true, cleanWhenSuccess: true, cleanWhenUnstable: true, disableDeferredWipeout: true, deleteDirs: true)
            deleteDir()
        }
    }
}

The parts that are truly generic and reusable as-is:

  • The @Library imports and setupPipelineEnvironment — standard Piper boilerplate
  • withCredentials + dockerExecute — environment isolation pattern
  • The entire git checkout -b / commit / push block — unchanged for any PR-based workflow
  • The GitHub API calls to create the PR and add labels — only the repo URL changes
  • The Wait for Merge stage — completely generic, only references env.PR_NUMBER
  • The post { cleanup } block — always the same

So yes: drop in a different script, adjust the parameters and file paths, and the whole pipeline works for any automation that follows the “mutate a file in a repo → PR → automerge” pattern.

复习与应用

追踪一次操作的输入、修改范围与最终产物，确认失败是否会继续写仓库。原代码保留为项目实例，没有在本轮连接内部服务验证。
