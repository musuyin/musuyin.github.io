Gitlab CI

2025-11-26

#CICD#部署

理解主线

先读 stages 和 job 的依赖，再读各阶段的镜像、变量、脚本与部署目标。原稿是一份具体环境的 CI 示例，原有环境地址与凭据值已替换为示例主机和 CI 变量；仍有配置与缩进问题，应作为分析材料而非直接可用的流水线。

https://gitlab.cn/docs/jh/

参考文件

image: registry.example.invalid:5005/docker/ci-tools:latest
variables:
  HARBOR_USERNAME: "${HARBOR_USERNAME_FROM_CI}"
  HARBOR_PASSWORD: "${HARBOR_PASSWORD_FROM_CI}"
  HARBOR_REGISTRY: "https://registry.example.invalid"
  DOCKER_IMAGE_NAME: "registry.example.invalid/test/$CI_REGISTRY_IMAGE:${CI_COMMIT_REF_SLUG}-${CI_COMMIT_SHA}"
stages:
  - build
  - test
  - prod
build:
  stage: build
  image: docker:latest
  script:
    - |
      echo "Building Docker image for $CI_COMMIT_BRANCH branch..."
      docker build -t $CI_REGISTRY_IMAGE .
      echo "Pushing Docker image to Harbor..."
      docker login -u $HARBOR_USERNAME -p $HARBOR_PASSWORD $HARBOR_REGISTRY
      echo "succeed login Harbor"
      docker push $CI_REGISTRY_IMAGE
  artifacts:
    expire_in: 60 days
  only:
    - main
    - test
    - dev
deploy:test:
  stage: test
  variables:
    DEPLOY_DESTINATION: "root@registry.example.invalid"
    DEPLOY_PATH: "/opt/okx/marketservice/test"
  script:
    - envsubst '${CI_REGISTRY_IMAGE}' < deployments/docker-compose.yaml > /tmp/docker-compose.yaml
    - scp /tmp/docker-compose.yaml $DEPLOY_DESTINATION:$DEPLOY_PATH/docker-compose-${CI_COMMIT_SHA}.yaml
    - ssh $DEPLOY_DESTINATION "ln -sf $DEPLOY_PATH/docker-compose-${CI_COMMIT_SHA}.yaml $DEPLOY_PATH/docker-compose.yaml && cd $DEPLOY_PATH && docker compose -f docker-compose.yaml up -d"
  when: manual
  only:
    - main
    - test
deploy:prod:
  stage: test
  variables:
    DEPLOY_DESTINATION: "root@registry.example.invalid"
    DEPLOY_PATH: "/opt/okx/marketservice/prod"
  script:
    - envsubst '${CI_REGISTRY_IMAGE}' < deployments/docker-compose.yaml > /tmp/docker-compose.yaml
    - scp /tmp/docker-compose.yaml $DEPLOY_DESTINATION:$DEPLOY_PATH/docker-compose-${CI_COMMIT_SHA}.yaml
    - ssh $DEPLOY_DESTINATION "ln -sf $DEPLOY_PATH/docker-compose-${CI_COMMIT_SHA}.yaml $DEPLOY_PATH/docker-compose.yaml && cd $DEPLOY_PATH && docker compose -f docker-compose.yaml up -d"
  when: manual
  only:
    - main
    - dev

预定义变量

变量名 值示例 说明
CI_REGISTRY_IMAGE registry.gitlab.com/jyokx/project 项目默认镜像仓库（不含标签）
CI_REGISTRY registry.gitlab.com 镜像仓库地址
CI_COMMIT_SHA a3d5e8f1b2c 当前提交的 Git SHA
CI_COMMIT_REF_NAME main, develop 当前分支或标签名
CI_COMMIT_BRANCH feature/login 当前分支名（仅分支 pipeline）
CI_COMMIT_TAG v1.0.0 当前标签名（仅标签 pipeline）
CI_PROJECT_NAME okx-marketservice 项目名称
CI_PROJECT_PATH jyokx/okx-marketservice 项目路径（命名空间/项目）
CI_PROJECT_URL https://gitlab.com/jyokx/okx-marketservice 项目网页地址
CI_PIPELINE_ID 123456 当前流水线 ID
CI_JOB_ID 789012 当前任务 ID
CI_JOB_NAME deploy:test 当前任务名称
CI_ENVIRONMENT_NAME production 当前环境名（如果定义了  environment）
CI_SERVER_URL https://gitlab.com GitLab 实例地址

复习与应用

逐项检查变量作用域、镜像标签在 build/push/deploy 间是否一致、敏感值是否改由受保护变量注入。示例尚未在本轮通过 GitLab CI Lint。
