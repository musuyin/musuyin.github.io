Prometheus

2026-08-12

#Cloud#Prometheus#可观测性#面试

理解主线

Prometheus 将抓取的指标组织为带标签的时间序列，PromQL 在时间与维度上计算，告警规则再把符合条件的状态交给告警处理链。采集、存储、查询与通知应分别定位。

可观测性三大支柱

在分布式系统中，服务出问题时需要三类数据才能定位根因：

支柱 回答的问题 工具
Metrics（指标） 系统现在状态怎么样？（CPU 多少、QPS 多少） Prometheus
Logs（日志） 发生了什么事？（错误信息、请求记录） Loki / ELK
Traces（链路追踪） 一个请求经过了哪些服务？每步耗时多少？ Jaeger / Zipkin

Prometheus + Grafana 主要解决 Metrics 这一层。

Prometheus

是什么

Prometheus 是一个开源的指标监控系统，负责：

  1. 定期从目标（应用、K8s 节点、中间件）拉取（Pull）指标数据
  2. 将指标存储在本地时序数据库中
  3. 提供 PromQL 查询语言用于分析数据
  4. 触发告警规则，将告警推送给 Alertmanager

Pull 模型（核心设计）

Prometheus 主动去拉数据，而不是被动等应用推数据过来：

Prometheus Server
      │  每隔 15s 主动 HTTP GET /metrics
      ▼
应用暴露的 /metrics 端点
（返回文本格式的指标数据）

优点：Prometheus 控制采集频率；应用挂了 Prometheus 能感知（拉不到数据）。

应用需要集成 Exporter 暴露 /metrics 端点：

  • 应用自带（Go/Java/Python 有官方 SDK）
  • 独立 Exporter（node-exporter 暴露 Linux 系统指标，kube-state-metrics 暴露 K8s 资源指标）

指标类型

类型 说明 示例
Counter 只增不减的累计值 请求总数、错误总数
Gauge 可增可减的瞬时值 CPU 使用率、内存占用、Pod 数量
Histogram 将数值分桶统计分布 请求延迟分布（P50/P95/P99）
Summary 类似 Histogram，客户端计算分位数 响应时间百分位

PromQL 基础

PromQL 是 Prometheus 的查询语言，面试常考基本用法：

# 查询当前 CPU 使用率（Gauge）
node_cpu_seconds_total

# 计算 QPS（Counter 在 5 分钟内的增长速率）
rate(http_requests_total[5m])

# 过滤特定标签
http_requests_total{job="student-mgmt", status="500"}

# 计算错误率
rate(http_requests_total{status=~"5.."}[5m])
  / rate(http_requests_total[5m])

# P99 延迟
histogram_quantile(0.99, rate(http_request_duration_seconds_bucket[5m]))

告警（Alertmanager）

Prometheus 本身只检测规则，告警通知由 Alertmanager 负责（去重、分组、路由到邮件/Slack/PagerDuty）：

# 告警规则示例
groups:
  - name: student-mgmt
    rules:
      - alert: HighErrorRate
        expr: rate(http_requests_total{status=~"5.."}[5m]) > 0.05
        for: 2m          # 持续 2 分钟才触发（避免抖动）
        labels:
          severity: critical
        annotations:
          summary: "错误率超过 5%"

在 K8s 中的部署

K8s 环境通常使用 kube-prometheus-stack（Helm Chart），一键安装：

  • Prometheus Server
  • Alertmanager
  • node-exporter（每个 Node 采集系统指标）
  • kube-state-metrics（采集 K8s 资源状态）
  • Grafana（自带预置 Dashboard）
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm install monitoring prometheus-community/kube-prometheus-stack

Prometheus vs 其他监控方案

对比项 Prometheus Datadog / New Relic
费用 开源免费 商业付费
数据存储 本地（默认 15 天） 云端长期
查询语言 PromQL 各自专有
生态 CNCF 标准，K8s 原生集成 SaaS，开箱即用
适用场景 自建集群、成本敏感 企业级、省运维

面试高频问题

Q：可观测性三大支柱是什么？ Metrics（指标，Prometheus）、Logs（日志，Loki/ELK）、Traces（链路追踪，Jaeger）。三者分别回答“系统状态怎样”、“发生了什么”、“请求在哪慢/出错”。

Q：Prometheus 的 Pull 模型是什么？有什么优点？ Prometheus 主动定期 HTTP 拉取目标的 /metrics 端点，而非应用主动推送。优点：Prometheus 控制采集频率；目标服务挂掉时 Prometheus 能直接感知（拉取失败即可告警）；不需要在每个应用里配置监控服务地址。

Q：Counter 和 Gauge 的区别？ Counter 只增不减，用于累计值（请求总数、错误总数），通常配合 rate() 计算速率；Gauge 可增可减，用于瞬时值（CPU 使用率、当前连接数、Pod 数量），直接读取当前值即可。

Q：如何计算 QPS 和错误率？

# QPS
rate(http_requests_total[5m])
# 错误率
rate(http_requests_total{status=~"5.."}[5m]) / rate(http_requests_total[5m])

Q：Grafana 和 Prometheus 的分工？ Prometheus 负责采集、存储指标数据，并执行告警规则；Grafana 负责可视化，对接 Prometheus 作为数据源绘制 Dashboard。Grafana 本身不存数据，只负责展示。

Q：什么是自定义 Exporter？实际项目中如何使用？

标准 Exporter 模式是 Prometheus 生态的核心扩展机制。当监控目标不能直接暴露 /metrics（如云厂商 API、第三方服务、私有协议），就需要开发一个中间层 Exporter：

云服务器 API（原始指标数据）
        │  调用云厂商 SDK / REST API
        ▼
Cloud Provider Exporter（CPE）
        │  用 prometheus SDK 将数据转换为 /metrics 格式
        │  本地缓存数据，防止 Prometheus 拉取时网络抖动丢数据
        ▼
本地 /metrics 端点（标准 Prometheus 格式）
        │  Prometheus Pull（每 15s）
        ▼
Prometheus Server → Grafana

CPE 的设计要点：

  • 解耦：Prometheus 只需访问本地的 CPE，不直接对外请求云 API，规避网络不稳定问题
  • 缓存：CPE 将最近一次采集的数据存在内存缓存中，即使 Prometheus 拉取时云 API 临时不可用，也能返回上次的数据，不丢指标
  • 转换：将云 API 返回的原始格式（JSON/XML）转换为 Prometheus 的文本格式（metric_name{label="value"} value）

Go 实现骨架（使用官方 prometheus SDK）：

var cpuUsage = prometheus.NewGaugeVec(
    prometheus.GaugeOpts{
        Name: "cloud_server_cpu_usage",
        Help: "CPU usage of cloud server instances",
    },
    []string{"instance_id", "region"},
)

func collectMetrics() {
    // 调用云 API 获取数据
    data := cloudAPI.GetCPUMetrics()
    // 写入 Gauge，Prometheus 拉取时直接读缓存值
    cpuUsage.WithLabelValues(data.InstanceID, data.Region).Set(data.Value)
}

func main() {
    prometheus.MustRegister(cpuUsage)
    go func() {
        for { collectMetrics(); time.Sleep(30 * time.Second) }
    }()
    http.Handle("/metrics", promhttp.Handler())
    http.ListenAndServe(":9100", nil)
}

这个模式与 node-exporter（采集 Linux 系统指标）、mysql-exporter（采集 MySQL 指标）的原理完全相同——都是在 Prometheus 和实际数据源之间架一个标准化的转换层。
