OpenStack

2026-11-09

#Cloud#OpenStack#IaaS

理解主线

以“创建一台虚拟机”为线索，先区分 Keystone 的身份认证、Nova 的实例管理、Placement 的资源记录，以及 Neutron、Glance 和 Cinder 的协作职责。再分开检查 API 接受请求、实例运行、业务网络和应用可用这几层状态。理解这些边界后，再把 OpenStack 放到 Terraform 的资源管理与 Gardener 的集群生命周期管理之间定位。

OpenStack 的定位

OpenStack 是一组开源云基础设施服务。它把服务器、网络和存储组织成资源池，通过应用程序接口（API）提供按需申请和管理能力。

它主要提供基础设施即服务（IaaS，Infrastructure as a Service），常用于私有云，也能支撑公有云。云运营团队维护底层硬件和 OpenStack 服务；用户在权限与配额范围内创建虚拟机、网络和存储。

创建虚拟机的工作主线

用户提交镜像、规格和网络配置。OpenStack 验证身份，选择计算节点，准备磁盘和网络，再启动虚拟机。

flowchart TD
    U[用户：Horizon 或 openstack 命令行工具] --> K[Keystone：认证与服务目录]
    U -->|携带令牌提交创建请求| N[Nova：管理虚拟机生命周期]
    N --> S[nova-scheduler：选择计算节点]
    S -->|查询容量与记录资源分配| P[Placement：资源清单与用量]
    N --> C[nova-compute：执行节点上的操作]
    C --> G[Glance：读取镜像]
    C --> E[Neutron：准备网络端口]
    C -->|使用云硬盘时| V[Cinder：准备块存储卷]
    C --> H[虚拟化驱动与 Hypervisor]
    H --> VM[虚拟机]

此图展示逻辑依赖，省略 nova-conductor 和消息通信细节。实际调用顺序受启动方式、服务版本和网络后端影响。

  1. 用户通过 Keystone 获取令牌和服务目录。服务目录提供各服务的 API 地址。
  2. 用户向 nova-api 提交请求。Nova 验证权限、配额和请求参数。
  3. nova-conductor 协调构建流程。nova-scheduler 根据 Placement 的资源信息及调度约束选择节点。
  4. Nova 为实例建立资源分配记录，并把构建任务交给目标节点的 nova-compute。
  5. Nova 与 Glance、Neutron 协作，获取镜像并准备网络端口。使用云硬盘时，还与 Cinder 协作。
  6. nova-compute 通过虚拟化驱动启动实例。常见实现使用 libvirt 管理 KVM/QEMU 虚拟机。
  7. 用户查询实例状态，并测试网络和应用。ACTIVE 表示实例处于运行状态，不代表应用已经可用。

创建通常是异步过程。API 接受请求后，实例可能经历 BUILD，再进入 ACTIVE 或 ERROR。

核心服务与职责

服务 管理对象 主要职责
Keystone 身份、项目、角色、服务目录 认证用户并提供服务发现；各服务按策略执行授权
Nova 实例（Server） 创建、调度、启动、停止和删除虚拟机
Placement 资源提供者、容量、资源分配 跟踪计算等资源的清单和用量，为调度提供依据
Neutron 网络、子网、端口、路由器、安全组 提供网络连接、地址管理和网络访问规则
Glance 镜像（Image） 管理镜像元数据，并通过存储后端提供镜像数据
Cinder 云硬盘（Volume） 创建、挂载和管理持久化块存储
Swift 容器与对象（Container / Object） 通过对象存储 API 保存和读取数据
Horizon Web 操作界面 调用服务 API，让用户通过浏览器管理资源

Nova 管理虚拟机生命周期；Hypervisor 执行虚拟机。Hypervisor 是管理虚拟机运行的虚拟化软件。Placement 提供资源信息和分配记录，调度决策由 nova-scheduler 执行。

Glance、Cinder 和 Swift 管理不同类型的数据。Glance 和 Cinder 可以使用不同后端，也可以共享 Ceph 等存储系统。共享后端不改变服务职责。

数据类型 服务 使用方式 生命周期要点
系统镜像 Glance 作为创建实例或启动卷的模板 通常独立于实例保存
本地实例磁盘 Nova 管理 作为实例的根盘或临时盘 通常随实例删除而删除，取决于启动方式
持久化块存储 Cinder 作为磁盘挂载到实例 能独立于实例保留；删除行为取决于配置
对象存储 Swift 通过 API 读取和写入对象 对象独立于实例保存

OpenStack 按需部署服务。Swift 并非所有云都安装；Glance 或 Cinder 使用 Ceph，也不代表该云提供 Swift。

常见扩展服务包括：

  • Heat：根据模板编排多个基础设施资源。
  • Octavia：提供负载均衡服务。
  • Ironic：管理裸金属服务器的部署和生命周期。
  • Manila：提供共享文件系统服务。

资源与隔离概念

  • Project（项目）：资源归属、权限范围和配额的管理单位。用户可通过角色加入多个项目。
  • Role（角色）：授权策略使用的身份属性。实际权限还取决于服务策略和请求范围。
  • Quota（配额）：项目能申请的资源上限。配额充足不代表底层资源足够。
  • Region（区域）：服务目录中的区域标识，用于选择服务端点。区域划分由云运营团队定义。
  • Availability zone（可用区）：服务暴露给用户的资源分组。实际故障隔离程度取决于部署设计。
  • Flavor（规格）：实例所需的虚拟 CPU、内存和磁盘等配置，也可包含调度约束。
  • Image（镜像）：实例的操作系统模板。镜像中的初始化工具和配置影响密钥注入及网络设置。
  • Port（端口）：Neutron 中代表网络接入点的对象，包含地址和安全组等配置。
  • Fixed IP（固定 IP）：分配给端口的子网内地址，不代表公网地址。
  • Floating IP（浮动 IP）：可关联到端口固定 IP 的外部网络地址。是否公网可达取决于外部网络。
  • Security group（安全组）：作用于端口的网络访问规则集合，不替代实例内部防火墙。

部署架构与通信

一个逻辑服务可能包含多个进程，并部署在多台机器上。常见节点职责如下，实际部署可以合并或拆分这些职责。

  • 控制节点：运行 API、认证、调度和协调进程，并连接数据库与消息队列。
  • 计算节点：运行 nova-compute、虚拟化软件及相关网络组件，承载虚拟机。
  • 网络节点或网关节点：处理路由、外部网络连接等功能。某些网络实现将部分功能分布到计算节点。
  • 存储节点：提供镜像、块存储或对象存储的后端容量。

服务之间主要通过 API 协作。Nova 等服务内部还使用远程过程调用（RPC）和消息队列，把任务交给工作进程。RabbitMQ 是常见消息队列实现，MariaDB/MySQL 是常见数据库选择。

数据库保存资源状态，消息队列传递任务。虚拟机的业务流量不经过消息队列。生产部署还需单独设计 API、数据库、消息队列、网络和存储的高可用性。

虚拟机的网络访问路径

在常见 IPv4 租户网络中，外部客户端可以通过浮动 IP 访问实例：

客户端 → 外部网络 → 路由或网关的地址转换
      → 浮动 IP 对应的实例固定 IP → 实例网卡 → 应用监听端口

Neutron 的网络后端实现路由和转发；Horizon、Keystone 和 Nova API 不转发这条业务流量。实际路径可以经过集中网关，也可以使用分布式路由。

访问成功还需要外部路由、安全组、实例防火墙和应用监听配置共同允许连接。浮动 IP 绑定成功只说明地址关联完成。实例也可以通过直连外部网络等方式提供访问，无须使用浮动 IP。

配置与基本使用

使用前，云运营团队提供 API 地址、身份凭证、项目权限和可用资源。以下示例使用 python-openstackclient 提供的 openstack 命令。

配置认证

安装客户端：

python3 -m pip install python-openstackclient

加载云运营团队提供的 OpenRC 文件，将路径替换为实际文件路径：

source /path/to/project-openrc.sh

OpenRC 设置 OS_AUTH_URL、项目和认证方式等环境变量。常见密码认证文件还要求你输入密码。认证是否需要域、区域等参数，取决于云的配置。

客户端也支持 clouds.yaml。如果你已配置名为 lab 的云，可以通过 openstack --os-cloud lab ... 选择它。凭证文件应保存在笔记仓库之外。

查看可用资源

openstack catalog list
openstack image list
openstack flavor list
openstack network list
openstack security group list
openstack keypair list
openstack server list

结果受项目权限和云配置限制。查询成功说明对应 API 可用，不证明实例创建或业务网络可用。

创建并检查实例

将镜像、规格、网络、安全组和密钥对名称替换为实际值。示例要求这些资源已存在；安全组需要允许你使用的访问方式。

openstack server create \
  --image ubuntu-image \
  --flavor small \
  --network private-net \
  --security-group web-sg \
  --key-name lab-key \
  --wait \
  web-01

openstack server show web-01
openstack port list --server web-01
openstack console log show web-01
openstack server event list web-01

--wait 等待实例创建完成，不等待应用启动。密钥对用于实例登录；镜像需要支持相应的密钥注入机制。控制台日志和事件详情可能受权限限制。

该示例未配置浮动 IP 或应用。你需要按实际网络设计建立访问路径，再测试应用端口与请求结果。客户端参数和 API 功能应对照所用版本检查。

与 Kubernetes、Gardener 和 Terraform 的关系

OpenStack 可以提供 Kubernetes 节点使用的虚拟机、网络和存储。Kubernetes 再管理这些节点上的 Pod 和应用资源。

物理服务器、网络与存储
  → OpenStack 创建基础设施资源
  → Kubernetes 节点运行在虚拟机或裸金属上
  → Kubernetes 管理 Pod、Service 和应用
  • Terraform：通过 OpenStack Provider 调用 API，创建和管理实例、网络、云硬盘等资源。它管理基础设施配置。
  • Gardener：通过 OpenStack 扩展管理 Kubernetes 集群所需的基础设施。它管理集群生命周期。
  • OpenStack Cloud Controller Manager：Kubernetes 的云控制器组件。配置相应集成后，它可处理节点云信息、负载均衡器等云资源操作。
  • Cinder CSI 驱动：通过容器存储接口（CSI，Container Storage Interface）连接 Kubernetes 与 Cinder，创建和挂载持久化卷。参见 L05-Storage。
  • Helm：打包和部署 Kubernetes 应用资源。其作用位于 Kubernetes 应用部署层。

安装 OpenStack 不会自动安装这些集成。Kubernetes 的 Pod 网络仍由容器网络接口（CNI，Container Network Interface）插件负责；Neutron 通常提供节点网络，也可通过专门集成参与容器网络。

常见问题与排查方向

现象 优先检查 状态的含义与限制
API 返回 401 或 403 认证参数、令牌、项目范围、角色和服务策略 认证失败与授权不足需要分别判断
实例长时间处于 BUILD 实例事件、Nova 工作进程、消息队列、镜像及网络准备 API 已接受请求，但构建尚未完成
创建失败，提示 No valid host Placement 容量、规格约束、可用区及计算服务状态 调度没有找到满足条件的节点
实例为 ACTIVE，但无法连接 路由、端口绑定、浮动 IP、安全组、实例防火墙及应用监听 实例运行状态不等于网络或应用可用
云硬盘挂载失败 Cinder 状态、后端连接、可用区及计算节点的存储连接 卷创建成功不等于实例挂载成功
删除实例后云硬盘仍存在 卷的删除策略及是否还有数据需要保留 独立保留的卷可能符合预期

用户先检查可见的资源状态、事件和控制台日志。云运营团队再沿请求 ID 检查服务日志、消息队列和后端状态。

复习

沿创建实例请求说明 Keystone、Nova、Placement、Glance、Neutron 和 Cinder 各自提供什么能力。为什么配额充足仍可能出现 No valid host？实例已是 ACTIVE 且浮动 IP 已绑定，仍无法访问应用时，应如何区分路由、安全组、实例防火墙与应用监听的问题？

比较 Glance 镜像、Nova 本地磁盘、Cinder 卷与 Swift 对象的用途及删除生命周期。再解释 OpenStack、Terraform、Gardener、Kubernetes 和 Helm 分别管理哪一层资源，为什么安装 OpenStack 不等于完成 Kubernetes 云集成。
