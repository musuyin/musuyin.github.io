SRE 基础阶段计划

2026-09-30

#SRE

理解主线

阶段计划按服务运行链组织练习：先操作系统和证据采集，再服务交付与观测，最后用演练检验恢复能力。每阶段的结果应落在实验记录，而不是仅勾选阅读。

学习原则：Linux、操作系统和网络部分不从通识原理重新讲起，而是围绕服务运行、证据采集、容量判断、故障隔离和安全变更展开。每周先阅读对应笔记，再在 实践项目：可靠的个人服务 中完成实验。

Linux 使用与 Shell

学习文档：Linux 与 Shell 运维实践

  • 学习：目录结构、文件权限、用户与组、标准输入输出、管道、重定向、grep、find、tar、ssh。
  • 实验：创建普通用户；用 SSH 密钥登录；编写脚本备份指定目录并保留最近 7 个备份。
  • 验收：能解释 chmod 644、sudo、|、> 与 >> 的含义；脚本重复执行不会误删最新备份。

进程、资源与日志

学习文档：进程、资源与日志排障

  • 学习：进程/线程、信号、systemd、journalctl、CPU/内存/磁盘/文件描述符。
  • 实验：把一个简单 HTTP 服务注册为 systemd 服务，设置开机自启和失败自动重启。
  • 验收：能用 ps、top/htop、ss、df、du、journalctl 找到服务状态、端口和失败原因。

网络与 Web

学习文档：网络与 Web 链路排障

  • 学习：IP、子网、路由、DNS、TCP、TLS、HTTP 请求/响应、状态码、反向代理。
  • 实验：使用 curl、dig、ping、traceroute、ss 分析一次请求；用 Nginx 反向代理本地服务。
  • 验收：能区分 DNS 解析失败、TCP 连接失败、HTTP 5xx 和 TLS 证书问题。

服务部署与数据保护

学习文档：服务部署与数据保护

  • 学习：Nginx、环境变量、配置文件、日志轮转、数据库基础、备份与恢复、最小权限。
  • 实验：部署带持久化数据的服务；为它配置访问日志、错误日志、HTTPS（测试证书亦可）和每日备份。
  • 验收：从备份恢复一份数据；说明配置、程序和数据分别放在哪里；不把密钥提交到 Git。

Docker 与交付

学习文档：Docker 与可靠交付

  • 学习：镜像、容器、卷、网络、Dockerfile、Compose、镜像标签。
  • 实验：容器化练习服务与 Nginx，使用 Docker Compose 启动；通过健康检查判断服务是否正常。
  • 验收：新机器只需获取代码和执行一条启动命令即可运行；数据重启后仍然存在。

自动化与 CI/CD

学习文档：自动化与 CI/CD 实践

  • 学习：Bash 编程、Python 基础、幂等性、Ansible 基础、CI/CD 的构建/测试/发布步骤。
  • 实验：用 Ansible 或脚本自动安装 Docker、上传配置、部署 Compose 服务；在 Git 平台配置测试或镜像构建流水线。
  • 验收：重复执行部署不会造成额外副作用；失败时脚本返回非零状态并输出有用错误。

监控、日志与告警

学习文档：监控、日志与告警实践

  • 学习：黄金信号（延迟、流量、错误、饱和度）、指标类型、日志字段、告警分级。
  • 实验：部署 Prometheus、Node Exporter 与 Grafana；建立 CPU、内存、磁盘、HTTP 成功率和延迟看板；为磁盘空间和服务不可用设置告警。
  • 验收：主动停止服务或写满测试磁盘后，能看到指标变化、收到告警并定位原因。

SRE 方法与故障演练

学习文档：SRE 方法与故障演练

  • 学习：SLI、SLO、SLA、错误预算、事件响应、无责复盘、变更风险。
  • 实验：为练习服务定义一个 SLO，例如「30 天内成功请求比例 ≥ 99.9%」；模拟一次故障并记录响应过程。
  • 验收：完成一篇复盘，包含时间线、影响、根因、缓解措施、后续行动项；区分根因与触发因素。

完成基础阶段后

选择一个方向深入 4–8 周：

  • Kubernetes 平台：Ingress、存储、HPA、Helm、GitOps。
  • 可观测性：PromQL、日志聚合、追踪、告警降噪。
  • 云运维：IAM、网络、负载均衡、Terraform、成本控制。
  • 数据库可靠性：复制、高可用、备份恢复、慢查询与容量。
  • 安全运维：补丁、密钥管理、审计、漏洞扫描、最小权限。

复习与应用

选择一周任务，分别列出需要提交的配置、运行证据和恢复记录；未完成的练习保留计划状态。
