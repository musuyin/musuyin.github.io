实践项目：可靠的个人服务

2026-09-30

理解主线

实践项目的交付物是一条可重复、可观测、可恢复的服务链。应用功能可以简单，但 HTTPS、部署、指标、备份与恢复需要真实运行结果支持。

项目目标

部署一个可通过 HTTPS 访问的小型服务，并让它具备可重复交付、监控告警、数据备份和故障恢复能力。服务内容不重要：待办应用、个人 API、状态页都可以；可靠性实践才是目标。

交付清单

  • 一个 Git 仓库，包含应用代码、README 和 .env.example。
  • Dockerfile 与 Docker Compose 配置。
  • Nginx 反向代理和 TLS 配置。
  • systemd 或容器编排启动方案，支持重启恢复。
  • 结构化应用日志和 Nginx 访问/错误日志。
  • Prometheus 指标、Grafana 看板及两条有意义的告警。
  • 自动化部署脚本或 Ansible Playbook。
  • 数据备份脚本、恢复演练记录和恢复时间。
  • 一份 SLI/SLO 定义，以及一次故障演练复盘。

推荐实施顺序

  1. 本机写出只有健康检查接口的最小服务，例如 GET /healthz 返回 200。
  2. 在 Ubuntu 虚拟机部署服务，确认进程、端口与日志可查。
  3. 用 Nginx 暴露服务，之后再添加 TLS。
  4. 使用 Docker Compose 让应用、反向代理和依赖可一键启动。
  5. 为主机和应用接入监控，先做看板，再做少量可操作的告警。
  6. 将部署过程自动化，并验证重复执行。
  7. 模拟故障、恢复服务并写复盘；根据复盘补足文档和监控。

故障演练菜单

所有实验均在本地或测试环境执行。

  • 停止应用进程：验证重启策略、可用性检测和告警。
  • 修改反向代理上游端口：练习从 502 排查至配置错误。
  • 消耗测试磁盘空间：验证磁盘告警、日志增长与清理策略。
  • 制造高延迟或 5xx：观察延迟、错误率、资源使用率之间的关系。
  • 删除测试数据后恢复备份：验证备份确实可恢复，而非只验证「备份文件存在」。
