学习路线

2026-09-30

理解主线

这条路线以独立维护一个小型线上服务为目标，再扩展到可靠性与容量管理。先补足能部署、能观测、能恢复的基础能力，再深化 Kubernetes 等复杂基础设施。

目标：具备独立部署、监控、排障和改进一个小型线上服务的能力；再逐步学习以可靠性为核心的 SRE 方法。

先明确方向

运维是保障系统能稳定运行的工程实践，重点是 Linux、网络、部署、监控与故障处理。SRE（Site Reliability Engineering）是在这些基础上，用软件工程方法管理可靠性、容量和重复劳动。

学习顺序应是：基础设施能力 → 交付与可观测性 → 云原生 → 可靠性工程。不要一开始只背 Kubernetes、Prometheus 概念；每个主题都要在自己的实验环境中做出可验证的结果。

能力地图

阶段 要学什么 达标产出
Linux 与网络 Shell、文件/权限、进程、systemd、DNS、TCP/HTTP、排查工具 一份常用命令与排障实验记录
服务部署 Git、Nginx、应用进程、日志、TLS、数据库与备份 一台服务器部署 HTTPS 服务并可回滚
自动化与交付 Bash、Python、Ansible、Docker、CI/CD、配置管理 一键部署脚本或流水线
可观测性 指标、日志、链路；Prometheus、Grafana、告警 服务看板、告警规则和故障演练记录
云原生 Kubernetes 核心对象、网络、存储、Helm、发布策略 在 Kind/Minikube 发布并扩缩容服务
SRE 实践 SLI/SLO、错误预算、容量规划、事故响应、复盘 为服务定义 SLO 并完成一次无责复盘

推荐节奏

每周投入 6–8 小时，采用 30% 阅读、70% 动手：

  • 读：只解决当前实验遇到的问题，记录关键概念和命令。
  • 做：每周完成一个可运行的实验，保留代码、配置、截图或命令输出。
  • 写：实验结束写「目标、环境、步骤、验证、踩坑、改进」六项。
  • 复盘：故意制造故障（进程停止、磁盘满、错误配置、延迟升高），再按现象排查。

建议先连续完成基础阶段，再决定主攻方向：平台工程/Kubernetes、云运维、监控可观测性、数据库运维或安全运维。

起步实验环境

优先在本机完成，不要直接在生产环境试错：

  • 本机：macOS/Linux + Git + VS Code/Obsidian + Docker Desktop。
  • Linux：Ubuntu Server 虚拟机（UTM、VirtualBox 或云服务器），建议 2 vCPU / 4 GB 内存起。
  • 云原生：Kind 或 Minikube；Kubernetes 初期不必购买云集群。
  • 代码：建立一个小型 Web 服务（Python Flask/FastAPI 或 Node.js 均可）作为全程练习对象。

学习资料原则

优先官方文档和可验证实验：

  • Linux：Ubuntu Server 文档、man 手册、Linux Journey。
  • 网络：Cloudflare Learning、MDN HTTP 文档。
  • Docker/Kubernetes：Docker Docs、Kubernetes 官方教程。
  • 可观测性：Prometheus 与 Grafana 官方文档。
  • SRE：Google《Site Reliability Engineering》《The Site Reliability Workbook》（可在线阅读）。

资料不是待办清单。以「完成一个项目需要什么，就查什么」为准。
