Cloud Native

2026-08-12

#Cloud#面试

理解主线

云原生把弹性、自动化、可观测性和故障恢复放进应用设计。容器和 Kubernetes 提供基础机制，服务拆分、交付流程和可靠性实践决定它们是否产生实际收益。

Cloud Native 全景

Cloud Native 是什么

Cloud Native（云原生）是一种构建和运行应用的理念与方法论，由 CNCF（云原生计算基金会）定义，核心是：让应用天生适合在云环境中运行——弹性、可观测、自动化、高可用。

它包含四个支柱：

支柱 含义
容器化 应用打包为容器镜像，环境一致，可移植
微服务 应用拆分为独立服务，独立部署、独立扩缩容
声明式 API 描述“期望状态”而非“操作步骤”，K8s YAML 就是典型
DevOps / CI/CD 自动化构建、测试、部署，快速迭代

Cloud Native ≠ 只是“K8s + 插件”。K8s 是最核心的基础设施层，但 Cloud Native 还包括工程实践（微服务拆分、GitOps、可观测性设计等）。不过在实践中，K8s 确实是整个生态的轴心，其他工具围绕它组成完整的工程体系。

DevOps 是什么

DevOps 是开发（Development）与运维（Operations）的融合，本质是一种工作文化和协作模式，不是某个具体工具。

它解决什么问题？

传统软件开发中开发团队和运维团队是割裂的：

传统模式（Dev 和 Ops 对立）：

开发团队                      运维团队
  写完代码 ──"扔过墙"──→      负责部署和维护
  关心：快速迭代、加新功能      关心：稳定、不出故障
  
结果：
  - 开发说"我本地没问题"，运维说"生产挂了不关我事"
  - 代码攒几个月才发一次版
  - 出了故障互相甩锅

DevOps 打破这堵墙：开发和运维共同负责整个生命周期——从写代码到线上稳定运行。

DevOps 的三个核心实践：

实践 含义 工具体现
CI/CD 自动化构建/测试/部署，让变更快速安全地到达生产 Jenkins、GitHub Actions、ArgoCD
IaC 基础设施即代码，像管理应用代码一样管理服务器和云资源 Terraform、Ansible
可观测性 监控、日志、告警，让运行状态透明可感知，快速发现和修复问题 Prometheus、Grafana、Loki

DevOps 与 CI/CD 的关系：

CI/CD 是 DevOps 的具体工程实现手段之一，不是全部。DevOps 是理念，CI/CD 是落地工具。

DevOps（理念）
    ├── CI/CD（自动化流水线）
    ├── IaC（基础设施代码化）
    ├── 可观测性（监控/日志/告警）
    ├── 微服务（服务解耦，独立部署）
    └── 文化：Dev 和 Ops 共担责任，快速反馈，持续改进

DevOps 在 Cloud Native 中的位置：

Cloud Native 把 DevOps 作为四大支柱之一，因为容器化和微服务带来了更复杂的部署和运维——没有 DevOps 工程实践（CI/CD 流水线、IaC、可观测性），管理成百上千个微服务几乎不可能。

各层工具说明：

可观测性（Observability）

工具 职责
Prometheus 指标采集与存储（Pull 模型，时序数据库）
Grafana 可视化仪表盘，对接 Prometheus/Loki 等数据源
Loki 日志聚合（Prometheus for logs）
Jaeger / Zipkin 分布式链路追踪，分析请求在微服务间的调用链

可观测性三大支柱：Metrics（指标）、Logs（日志）、Traces（链路追踪）。

包管理

工具 职责
Helm K8s 的包管理器，将一组 YAML 打包为 Chart，一键安装/升级/回滚

集群生命周期管理

工具 职责
Gardener SAP 开源，管理大规模多云 K8s 集群（用 K8s 管理 K8s）
Cluster API CNCF 标准，声明式管理集群生命周期

Service Mesh（服务网格）

工具 职责
Istio / Linkerd 在服务间通信层注入 sidecar proxy，实现流量管理、mTLS、可观测性，无需修改业务代码

CI/CD & GitOps

工具 职责
ArgoCD / Flux GitOps 工具，Git 仓库即唯一真相，自动同步集群状态
Jenkins 传统 CI/CD，Pipeline 驱动构建/测试/部署

安全

工具 职责
OPA / Gatekeeper 策略即代码，在 K8s 准入时执行自定义规则
cert-manager 自动管理 TLS 证书（申请/续期）
Falco 运行时安全检测，识别异常行为

面试角度的理解

“Cloud Native 的核心基础设施是 Kubernetes，它解决了容器编排问题。围绕 K8s，可观测性层（Prometheus + Grafana）解决监控问题，Service Mesh 解决服务间通信问题，Helm 解决配置管理问题，Gardener/Cluster API 解决多集群管理问题，CI/CD 工具解决自动化发布问题。整体是一个以 K8s 为轴心、各层工具协同的工程体系，而非单一产品。”

Cloud Native 工具全景

开发者写代码
    │
    ▼ git push → Jenkins CI
    构建 → 测试 → 打镜像 → 推送 ECR/Harbor
    │
    ▼ Helm CD / ArgoCD GitOps
    helm upgrade → K8s Deployment 滚动更新
    │
    ▼ 运行在 K8s 上（由 Gardener 管理的 Shoot 集群）
    Pod / Service / Ingress
    │
    ▼ 可观测性
    Prometheus 采集指标 → Grafana Dashboard / 告警
    │
    ▼ 底层基础设施（由 Terraform 管理）
    VPC / IAM / 云账号 / Vault 密钥
层次 工具 管什么
CI/CD 流程 Jenkins / GitHub Actions 构建、测试、触发部署
应用部署 Helm + ArgoCD（GitOps） K8s 内的应用版本管理
集群管理 Gardener K8s 集群生命周期（创建/升级）
基础设施 Terraform 云账号/网络/IAM/State 后端
可观测性 Prometheus + Grafana 指标采集、告警、可视化
容器编排 Kubernetes Pod 调度、服务发现、自动扩缩
