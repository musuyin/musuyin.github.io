2026-05-08

#编译原理

阅读线索

符号表记录名字的类型、作用域和位置，静态语义分析据此检查合法性。中间代码再把表达式和控制结构转换为更接近执行的操作序列。

符号表

符号表的作用

符号表（Symbol Table）是编译器中存储程序各种名字（标识符）信息的数据结构，贯穿编译的各个阶段。

编译阶段 对符号表的操作
词法分析 将识别到的标识符字符串存入符号表
语法分析 验证名字的使用是否符合语法
语义分析 填写/查询名字的类型、作用域等属性
代码生成 查询名字的存储位置，生成地址

三大核心作用：

  1. 记录名字的属性：类型、作用域、存储位置等
  2. 支持语义检查：变量是否声明、类型是否匹配
  3. 辅助代码生成：确定变量的存储位置和大小

符号的常见属性

不同种类的名字存储的属性不同。

变量/常量

属性 说明
名字（Name） 标识符字符串，如 count
类型（Type） int、float、数组类型、指针类型等
作用域（Scope） 全局 / 局部 / 块级
存储类别 auto、static、extern、register
偏移量（Offset） 在栈帧或数据段中的相对地址
初始值 常量或静态变量的初始值

函数/过程

属性 说明
名字 函数名
返回类型 返回值类型
参数列表 参数的个数和各参数类型
入口地址 函数体代码的起始地址

类型定义（结构体、类）

属性 说明
字段列表 各字段的名字和类型
大小 总占用字节数
对齐方式 内存对齐要求

符号表的表现

符号表本质是一个字典，需要高效支持插入和查找。常见实现方式：

线性表

用数组或链表顺序存储所有记录。

操作 时间复杂度
插入 O(1)O(1)O(1)（追加到末尾）
查找 O(n)O(n)O(n)（顺序扫描）

适用于名字数量少的小型语言或教学编译器。

散列表（Hash Table）

用哈希函数将名字映射到表中位置，是实际编译器最常用的方式。

def hash(name):
    h = 0
    for c in name:
        h = (h * 31 + ord(c)) % TABLE_SIZE
    return h

冲突处理：

  • 开放定址法：冲突时探查下一个空槽
  • 链地址法（最常用）：每个槽维护一个链表
操作 平均 最坏
插入 O(1)O(1)O(1) O(n)O(n)O(n)
查找 O(1)O(1)O(1) O(n)O(n)O(n)

GCC、LLVM 等工业编译器均使用散列表。

二叉搜索树

按名字字典序组织，平衡 BST（AVL 树、红黑树）保证 O(log⁡n)O(\log n)O(logn) 的查找，适合需要按序枚举名字的场景。

符号表体现作用域与可见性

作用域的概念

作用域（Scope）是拥有共同有效范围的符号所在的程序单元。作用域之间可以嵌套（一个作用域被另一个包围），但不会交错——两个作用域要么嵌套，要么不相交。

int x = 1;        // 全局作用域
{
    int x = 2;    // 块级作用域（嵌套在全局内）
    printf("%d", x);  // 输出 2
}
printf("%d", x);  // 输出 1

开作用域与闭作用域

对于程序中的某一特定点，作用域分为两类：

当前作用域：该点所在的作用域。

开作用域（Open Scope）：当前作用域，以及所有包含它的外层作用域，合称该点的开作用域。

即从当前作用域一路向外，直到最顶层，沿途经过的所有作用域都是开作用域。

闭作用域（Closed Scope）：不属于开作用域的作用域——既不是当前作用域，也不是包含它的外层作用域（例如其他函数内部的作用域，或与当前块并列的兄弟块）。

类比：站在一栋楼的某一层（当前作用域），你能看到这一层和所有更低的楼层（开作用域）；相邻栋的楼层和高于你的楼层你都看不到（闭作用域）。

示例：

作用域结构：
  全局 (G)
   ├── 函数 f (F)
   │    ├── 块 1 (B1)  ← 当前点在这里
   │    └── 块 2 (B2)
   └── 函数 g (Fg)

若当前点在 B1 内：

  • 开作用域：B1、F、G（当前 + 所有外层）
  • 闭作用域：B2、Fg（与当前点无包含关系）

可见性规则

可见性（Visibility）是指在程序某一特定点，哪些符号是可访问的（即可见的）。

常用的可见性规则：

  1. 只有开作用域中声明的符号才可访问——闭作用域中的符号在当前点不可见。

  2. 最近声明优先——若同一名字在多个开作用域中都有声明，取离当前点最近的那个声明作为解释（即内层遮蔽外层）。

  3. 新的声明只能出现在当前作用域——不能在外层或闭作用域中添加新声明。

示例：

int x = 1;           // G 中声明 x
void f() {
    int x = 2;       // F 中声明 x，遮蔽 G 中的 x
    {
        // 当前点：B1
        // 开作用域：B1、F、G
        // 可见的 x：F 中的 x=2（最近声明）
        printf("%d", x);  // 输出 2
    }
}

符号表对开/闭作用域的实现

用嵌套符号表栈直接对应开/闭作用域的概念：

当前栈（从栈顶到栈底）：
  当前作用域的符号表   ← 栈顶
  外层作用域的符号表
  ...
  全局符号表           ← 栈底
  • 栈中所有符号表对应该点的开作用域
  • 不在栈中的符号表对应闭作用域
  • 查找名字时从栈顶向下搜索，天然满足“最近声明优先”规则
  • 进入新作用域时压栈，离开时弹栈
class ScopeManager:
    def __init__(self):
        self.stack = [{}]  # 全局作用域

    def enter_scope(self):
        self.stack.append({})

    def exit_scope(self):
        self.stack.pop()

    def define(self, name, info):
        self.stack[-1][name] = info  # 只在当前作用域定义

    def lookup(self, name):
        for table in reversed(self.stack):  # 从内向外（最近优先）
            if name in table:
                return table[name]
        return None  # 不在任何开作用域中 → 不可见

符号表操作

插入（Insert）：在当前作用域添加新条目，同一作用域内重复定义报错。

查找（Lookup）：从当前作用域向外逐层查找，未找到则报“未定义名字”。

删除（Delete）：通常不显式删除单个条目，而是离开作用域时整体弹出。

实现块结构作用域的常用方法：嵌套的符号表栈。

全局符号表
   ↓
函数 f 的符号表
   ↓
f 内的块级符号表
  • 进入新作用域：压入一张新的符号表
  • 离开作用域：弹出当前符号表（该作用域的名字消失）
  • 查找规则：从当前作用域向外逐层查找，最近优先

静态语义分析

静态语义分析（Static Semantic Analysis）在编译时（不运行程序）检查程序语义的正确性，是语法分析之后、代码生成之前的重要阶段。

与动态语义的区别：静态语义在编译时检查（如类型错误），动态语义在运行时体现（如除零错误）。

主要任务

  1. 声明检查：变量使用前是否已声明
  2. 类型检查：运算符的操作数类型是否相容，函数实参与形参类型是否匹配
  3. 控制流检查：break/continue 是否在循环内，函数是否有返回值
  4. 唯一性检查：同一作用域内是否有重复声明
  5. 作用域检查：名字的使用是否在其作用域内

类型检查

类型系统基础

每个表达式都有一个类型，类型检查验证运算是否对类型合法。

类型相容（Type Compatibility）：某些不同类型之间可以隐式转换（Implicit Conversion / Coercion），例如：

int+float⇒float\text{int} + \text{float} \Rightarrow \text{float}int+float⇒float（int 自动提升为 float）

类型强制（Type Coercion）：编译器自动插入类型转换指令。

表达式的类型推导

对表达式 e1 op e2e_1\ \text{op}\ e_2e1​ op e2​，类型检查规则：

  1. 递归推导 e1e_1e1​ 和 e2e_2e2​ 的类型 T1T_1T1​、T2T_2T2​
  2. 查类型相容表，确定结果类型 TTT
  3. 若 T1T_1T1​、T2T_2T2​ 不相容，报类型错误

示例：a + b，aaa 为 int，bbb 为 float

lookup("a") → type = int
lookup("b") → type = float
int + float → 将 a 强制转换为 float，结果类型 float

函数调用检查

  • 实参个数是否与形参个数一致
  • 各实参类型是否与对应形参类型相容
  • 非 void 函数是否有返回值

常见类型错误

错误类型 示例
操作数类型不匹配 "hello" + 1（字符串加整数）
函数参数类型错误 f(1, 2) 但 f 只接受一个参数
对非数组下标访问 x[0] 但 x 是 int
赋值类型不匹配 将 float 赋给 bool* 指针

中间代码生成

中间代码（Intermediate Code）是编译器前端（分析）和后端（代码生成）之间的“通用表示”，与具体机器无关。

优点：

  • 可移植：mmm 种语言 × nnn 种平台，只需 m+nm+nm+n 个模块（而非 m×nm\times nm×n）
  • 易优化：在中间代码层面做机器无关优化
  • 模块化：前后端解耦

常见的中间表示形式

抽象语法树（AST）

抽象语法树（Abstract Syntax Tree）是语法树的精简版，去掉了所有不影响语义的成分（括号、分隔符等）。

与语法树的区别：

语法树（分析树） 抽象语法树（AST）
节点 包含所有文法符号 只保留有语义意义的节点
括号 有 无（通过树结构体现优先级）
用途 分析过程的中间产物 语义分析和代码生成的基础

示例：表达式 a + b * c

    +
   / \
  a   *
     / \
    b   c

树的结构已经体现了乘法优先于加法，不需要括号。

有向无环图（DAG）

DAG（Directed Acyclic Graph）是 AST 的压缩形式——对公共子表达式共享节点，而不是重复创建。

示例：a + a * b + a * b

AST 中 a * b 出现两次，各有一棵子树；DAG 中 a * b 只有一个节点，两处加法共享它。

DAG 可以直接帮助识别公共子表达式，为后续优化做准备。

三地址码

详见下节。

逆波兰表达式（后缀表达式）

运算符写在操作数后面，不需要括号，用栈即可求值。

a+b∗c⇒a b c ∗ +a + b * c \Rightarrow a\ b\ c\ *\ +a+b∗c⇒a b c ∗ +

适合简单表达式翻译，实际编译器更多用三地址码。

生成抽象语法树

构造方法

在语法分析的同时，通过语义动作构造 AST 节点：

  • 每个产生式归约时，创建对应的 AST 节点
  • 子节点来自子产生式的节点
  • 根节点就是整个 AST 的根
E → E₁ + T  { E.node = mknode('+', E₁.node, T.node) }
E → T        { E.node = T.node }
T → T₁ * F  { T.node = mknode('*', T₁.node, F.node) }
T → F        { T.node = F.node }
F → (E)      { F.node = E.node }
F → id       { F.node = mkleaf(id, id.entry) }
F → num      { F.node = mkleaf(num, num.val) }

示例

输入 a * b + c，构造 AST：

归约 F→a  → 叶节点 a
归约 T→F  → 节点 a
归约 F→b  → 叶节点 b
归约 T→T*F → mknode('*', a, b)
归约 F→c  → 叶节点 c
归约 T→F  → 节点 c
归约 E→E+T → mknode('+', *, c)

最终 AST：
      +
     / \
    *   c
   / \
  a   b

生成三地址码

什么是三地址码

每条指令最多三个操作数，形如：

x=y op zx = y\ \text{op}\ zx=y op z

其中 xxx、yyy、zzz 是变量、常量或编译器生成的临时变量（t1,t2,…t_1, t_2, \ldotst1​,t2​,…）。

三地址码的常见形式

形式 含义
x=y op zx = y\ \text{op}\ zx=y op z 二元运算
x=op yx = \text{op}\ yx=op y 一元运算（取反、类型转换）
x=yx = yx=y 赋值
goto LLL 无条件跳转
if x relop yx\ \text{relop}\ yx relop y goto LLL 条件跳转
param xxx；call p,np, np,n 函数调用（nnn 个参数）
return xxx 函数返回
x=y[i]x = y[i]x=y[i]；x[i]=yx[i] = yx[i]=y 数组访问

四元式表示

三地址码常用四元式（Quadruple）表示：(op, arg1, arg2, result)(\text{op},\ \text{arg1},\ \text{arg2},\ \text{result})(op, arg1, arg2, result)

四元式 op 速查表

算术运算：

op 含义 arg1 arg2 result
+ 加 操作数1 操作数2 结果
- 减 操作数1 操作数2 结果
* 乘 操作数1 操作数2 结果
/ 除 操作数1 操作数2 结果
uminus 一元取负 操作数 — 结果

赋值：

op 含义 arg1 arg2 result
= 赋值 右值 — 左值变量

关系运算（条件跳转）：

op 含义 arg1 arg2 result
j< 若 arg1 < arg2 则跳转 操作数1 操作数2 目标标号
j<= 若 arg1 ≤ arg2 则跳转 操作数1 操作数2 目标标号
j> 若 arg1 > arg2 则跳转 操作数1 操作数2 目标标号
j>= 若 arg1 ≥ arg2 则跳转 操作数1 操作数2 目标标号
j= 若 arg1 = arg2 则跳转 操作数1 操作数2 目标标号
j<> 若 arg1 ≠ arg2 则跳转 操作数1 操作数2 目标标号

无条件跳转：

op 含义 arg1 arg2 result
j 无条件跳转 — — 目标标号

函数调用：

op 含义 arg1 arg2 result
param 压入参数 参数值 — —
call 调用函数 函数名 参数个数 —
return 函数返回 返回值（可空） — —

数组操作：

=[] 数组取值 数组名 下标 结果变量
[]= 数组赋值 右值 下标 数组名

记忆规律：

  • 条件跳转的 op = j + 关系符号，result 填跳转目标
  • 无条件跳转三个格全填 —，只有 result 是目标
  • 一元运算 arg2 填 —，赋值同理

翻译 a = b * -c + b * -c：

编号 op arg1 arg2 result
(0) uminus c — t1
(1) * b t1 t2
(2) uminus c — t3
(3) * b t3 t4
(4) + t2 t4 t5
(5) = t5 — a

表达式的三地址码生成

通过语义动作，在归约时调用 newtemp() 和 emit() 生成三地址码：

E → E₁ + T  {
    E.place = newtemp();
    emit(E.place '=' E₁.place '+' T.place)
}
E → T        { E.place = T.place }
T → T₁ * F  {
    T.place = newtemp();
    emit(T.place '=' T₁.place '*' F.place)
}
T → F        { T.place = F.place }
F → (E)      { F.place = E.place }
F → id       { F.place = id.name }

辅助函数：

  • newtemp()：分配新的临时变量 tit_iti​
  • emit(指令)：输出一条三地址码

控制流语句的三地址码生成

赋值和算术表达式只需顺序生成，控制流需要生成跳转指令。

if-then-else：

    生成 B 的代码（真跳 L1，假跳 L2）
L1: 生成 S₁ 的代码
    goto Lnext
L2: 生成 S₂ 的代码
Lnext: ...

while：

Lbegin: 生成 B 的代码（真跳 Lbody，假跳 Lnext）
Lbody:  生成 S 的代码
        goto Lbegin
Lnext:  ...

回填技术（Backpatching）

单遍扫描时，生成跳转指令时目标地址尚未确定，用回填解决：

  1. 生成跳转指令时暂时留空目标地址
  2. 用链表记录所有待填写的跳转指令
  3. 目标地址确定后，回头填写所有相关指令

关键属性：

  • B.truelist：BBB 为真时待填目标的指令列表
  • B.falselist：BBB 为假时待填目标的指令列表

辅助函数：

  • makelist(i)：创建只含指令 iii 的列表
  • merge(p1, p2)：合并两个列表
  • backpatch(p, i)：将列表 ppp 中所有指令的目标填为 iii

总结

概念 要点
符号表 存储名字属性，支持语义检查和代码生成
作用域管理 嵌套符号表栈，进/出作用域时压/弹，最近优先查找
静态语义分析 声明检查、类型检查、控制流检查
类型检查 推导表达式类型，检查相容性，插入类型转换
AST 语法树的精简版，去掉无语义意义的符号

例 1：写出表达式的三地址码

题目：写出表达式 A:=B∗(−C+D)A := B * (-C + D)A:=B∗(−C+D) 的三地址码。

分析

按运算优先级，表达式的计算顺序为：

  1. 先算一元取负：−C-C−C
  2. 再算加法：−C+D-C + D−C+D
  3. 再算乘法：B∗(−C+D)B * (-C + D)B∗(−C+D)
  4. 最后赋值给 AAA

每步引入一个新的临时变量 tit_iti​。

三地址码

编号 指令 说明
(1) t1 = uminus C 一元取负：t1=−Ct_1 = -Ct1​=−C
(2) t2 = t1 + D 加法：t2=t1+D=−C+Dt_2 = t_1 + D = -C + Dt2​=t1​+D=−C+D
(3) t3 = B * t2 乘法：t3=B×t2=B×(−C+D)t_3 = B \times t_2 = B \times (-C+D)t3​=B×t2​=B×(−C+D)
(4) A = t3 赋值：A:=t3A := t_3A:=t3​

四元式表示

编号 op arg1 arg2 result
(1) uminus C — t1
(2) + t1 D t2
(3) * B t2 t3
(4) = t3 — A

例 2：控制流语句翻译为四元式

题目：将以下语句翻译成四元式：

while A<C and B<D do
  if A=1 then C:=C+1
         else while A<=D do A:=A+2

结构分析

外层 while（条件：A<C and B<D）
  └── if-else
        ├── then：C := C+1
        └── else：内层 while（条件：A<=D）
                    └── A := A+2

布尔条件的翻译策略：

  • A<C and B<D：用短路求值翻译，A<C 为假时直接跳出，不再计算 B<D
  • if 条件和 while 条件均生成条件跳转指令

四元式

编号 op arg1 arg2 result 说明
(1) j< A C (3) A<C 为真跳 (3)，继续判断 B<D
(2) j — — (15) A<C 为假，短路，跳出外层 while
(3) j< B D (5) B<D 为真跳 (5)，进入循环体
(4) j — — (15) B<D 为假，跳出外层 while
(5) j= A 1 (7) A=1 为真，跳 then 分支
(6) j — — (10) A≠1，跳 else 分支
(7) + C 1 t1 then：t1 = C+1
(8) = t1 — C C := t1
(9) j — — (1) then 结束，回外层 while 头
(10) j<= A D (12) 内层 while：A<=D 为真进入体
(11) j — — (1) A<=D 为假，内层 while 结束，回外层 while 头
(12) + A 2 t2 内层 while 体：t2 = A+2
(13) = t2 — A A := t2
(14) j — — (10) 回内层 while 头
(15) — — — — 外层 while 出口

控制流图

(1)(2)(3)(4) ← 外层 while 条件（and 短路）
      ↓ 真（进入循环体）
  (5)(6) ← if 条件
  ↙ 真       ↘ 假
(7)(8)(9)   (10)(11) ← 内层 while 条件
  ↓               ↓ 真
  │           (12)(13)(14)
  │               ↓（回 10）
  └──────┐
         ↓
       回 (1)（外层 while 头）
         ↓ 假
       (15) 出口

关键点说明

  1. and 短路：(1)(2) 翻译 A<C，为假直接跳 (15)；(3)(4) 翻译 B<D，为假也跳 (15)，不需要计算完整布尔值。

  2. then 分支结束后：(9) 无条件跳回 (1)，跳过 else 分支。

  3. 内层 while 退出：(11) 跳回 (1)（外层 while 头），而不是 (15)——内层 while 结束后继续执行外层 while 的下一次判断。

  4. 外层 while 出口 (15)：既是 A<C 为假的出口，也是 B<D 为假的出口。
