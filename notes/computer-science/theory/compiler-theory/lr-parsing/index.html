#编译原理

阅读线索

LR 分析沿输入移进，并把已识别的句柄归约成非终结符。项目集刻画当前可能位置，ACTION 和 GOTO 表决定下一步，向前看符号用于减少不确定选择。

LR 分析概述

什么是 LR 分析

LR 分析（LR Parsing）是一种强大的自底向上语法分析方法。

LR 的含义：

  • L（Left-to-right）：从左到右扫描输入
  • R（Rightmost derivation in reverse）：构造最右推导的逆序（规范归约）
  • (k)：向前看 kkk 个输入符号（通常 k=0k=0k=0 或 k=1k=1k=1）

LR 分析是最右推导的逆过程，也就是规范归约。

LR 分析的基本思想

自底向上分析

从输入串（叶节点）出发，逐步归约（Reduce）到文法的开始符号（根节点）。

核心问题：

  1. 何时归约？（识别句柄）
  2. 用哪个产生式归约？

句柄（Handle）

句柄是句型中最左边的直接短语，也就是下一步应该归约的部分。

回顾：如果有推导 S⇒∗αAδ⇒αβδS\Rightarrow^*\alpha A\delta\Rightarrow\alpha\beta\deltaS⇒∗αAδ⇒αβδ，其中 A→βA\rightarrow\betaA→β，则 β\betaβ 是句型 αβδ\alpha\beta\deltaαβδ 相对于产生式 A→βA\rightarrow\betaA→β 的句柄。

移进-归约分析

LR 分析使用移进-归约技术：

  • 移进（Shift）：将输入符号压入栈
  • 归约（Reduce）：将栈顶的符号串（句柄）按某个产生式归约为非终结符
  • 接受（Accept）：归约到开始符号且输入读完
  • 报错（Error）：发现语法错误

LR 分析算法

输入：输入串 www，LR 分析表 输出：www 的规范归约序列（最右推导的逆序）或错误信息

    栈 = [s₀]  // s₀ 是初始状态
    输入指针 ip 指向 w 的第一个符号

repeat:
    s = 栈顶状态
    a = ip 指向的符号

    根据 ACTION[s, a] 执行动作：

    case sₙ (移进):
        将 a 和 sₙ 压入栈
        ip++

    case rₙ (归约):
        设第 n 个产生式为 A → β
        从栈顶弹出 |β| 个符号对（共 2|β| 个元素）

        将 A 和 s' 压入栈
        输出: 用 A → β 归约

    case acc (接受):
        输出: 分析成功
        return

    case error (错误):
        输出: 语法错误
        调用错误处理程序
        return

LR(0) 分析

LR(0) 是最基础的 LR 分析方法，它不需要向前看输入符号。

LR(0) 项目（Item）

定义

LR(0) 项目是在产生式右部的某个位置添加一个点 ·，表示当前的分析进度。

对于产生式 A→XYZA\rightarrow XYZA→XYZ，有 4 个 LR(0) 项目：

  1. A→⋅XYZA\rightarrow\cdot XYZA→⋅XYZ（还没开始匹配）
  2. A→X⋅YZA\rightarrow X\cdot YZA→X⋅YZ（已匹配 XXX）
  3. A→XY⋅ZA\rightarrow XY\cdot ZA→XY⋅Z（已匹配 XYXYXY）
  4. A→XYZ⋅A\rightarrow XYZ\cdotA→XYZ⋅（全部匹配完成，可以归约）

项目的分类

  1. 移进项目：A→α⋅aβA\rightarrow\alpha\cdot a\betaA→α⋅aβ（点后面是终结符 aaa）

    • 表示期望看到 aaa，准备移进

  2. 归约项目：A→α⋅A\rightarrow\alpha\cdotA→α⋅（点在最右边）

    • 表示已匹配完整个右部，可以归约为 AAA

  3. 待约项目：A→α⋅BβA\rightarrow\alpha\cdot B\betaA→α⋅Bβ（点后面是非终结符 BBB）

    • 表示期望推导出 BBB，需要考察 BBB 的产生式

  4. 初始项目：S′→⋅SS'\rightarrow\cdot SS′→⋅S（增广文法的初始项目）

增广文法（Augmented Grammar）

为了处理接受状态，我们引入增广文法。

原文法：开始符号为 SSS

增广文法：引入新的开始符号 S′S'S′，添加产生式：

S′→S S'\rightarrow S S′→S

作用：当归约到 S′→S⋅S'\rightarrow S\cdotS′→S⋅ 且输入为 $ 时，表示接受。

定义

对于项目集 III，其闭包 CLOSURE(I)\text{CLOSURE}(I)CLOSURE(I) 是通过不断添加新项目得到的：

  • 对于 BBB 的每个产生式 B→γB\rightarrow\gammaB→γ

算法

def CLOSURE(I):
    J = I.copy()
    repeat:
        for each 项目 A → α·Bβ in J:
            if B 是非终结符:
                for each 产生式 B → γ:
                    if B → ·γ not in J:
                        J.add(B → ·γ)
    until J 不再变化
    return J

识别活前缀的有限自动机

活前缀（Viable Prefix）

活前缀是在移进-归约分析过程中，某时刻分析栈里可能出现的内容。

形式化定义：符号串 α\alphaα 是文法 GGG 的一个活前缀，当且仅当存在最右句型使得：

S⇒rm∗αβw S \Rightarrow^*_{rm} \alpha\beta w S⇒rm∗​αβw

其中 α\alphaα 是栈的当前内容，www 是剩余输入串（终结符串），β\betaβ 是二者之间的部分（可为空）。

关键性质：活前缀不包含句柄右边的任何符号——也就是说，活前缀最多到句柄的末尾为止，不会越过句柄。这是 LR 分析“不出错”的保证：只要栈里是活前缀，分析就还有希望继续。

类比：活前缀就像一条“尚未走错的路”——不管后续输入是什么，当前栈的内容还有可能导向成功的归约；一旦栈的内容不再是活前缀，就说明已经出错了。

LR(0) 项目 A→α⋅βA \rightarrow \alpha \cdot \betaA→α⋅β 的含义是：

  • 已将 α\alphaα 移入栈中（α\alphaα 是当前栈顶的部分内容）
  • 期望接下来看到 β\betaβ，然后可以归约为 AAA

每个项目集对应一批活前缀：处于项目集 III 时，栈中的符号串正好是 III 所代表的那些活前缀之一。

SLR(1) 分析

SLR(1)（Simple LR(1)）是 LR(0) 的改进版，通过向前看一个符号并使用 FOLLOW 集来解决部分冲突。

SLR(1) 的改进思想

LR(0) 在归约时，对所有输入符号都执行归约，这过于“激进”。

SLR(1) 的改进：归约项目 A→α⋅A\rightarrow\alpha\cdotA→α⋅ 只在下一个输入符号 ∈\in∈ FOLLOW(A) 时才归约。

原因：如果 AAA 能归约，那么归约后 AAA 后面跟的符号必定在 FOLLOW(A)\text{FOLLOW}(A)FOLLOW(A) 中。

从 LR(0) 冲突到 SLR(1) 验证

LR(0) 项目集规范族可以直接复用，不需要重新画。只需针对有冲突的状态，用 FOLLOW 集检查冲突能否消解。

SLR(1) 的冲突：

  • FOLLOW(R)={$,=}\text{FOLLOW}(R)={\text{\textdollar}, =}FOLLOW(R)={$,=}
  • 看到 = 时，移进和归约都可能

  • [S→L⋅=R, $][S\rightarrow L\cdot = R,\ \text{\textdollar}][S→L⋅=R, $]：看到 = 移进
  • [R→L⋅, $][R\rightarrow L\cdot,\ \text{\textdollar}][R→L⋅, $]：只有看到 $ 才归约

结果：没有冲突！

LR(1) 文法的定义

文法 GGG 是 LR(1) 文法，当且仅当构造的 LR(1) 分析表没有冲突。

定理：LR(1) 分析能识别所有确定性上下文无关语言。

LR(1) 的问题

问题：LR(1) 项目集规范族的规模非常大。

  • 一个 LR(0) 项目可能对应多个 LR(1) 项目（向前看符号不同）
  • 项目集数量可能是 LR(0) 的 10 倍甚至更多
  • 分析表巨大，占用大量内存

解决方案：LALR(1) 分析（压缩 LR(1) 状态）

LALR(1) 分析

LALR(1)（Look-Ahead LR(1)）是 LR(1) 和 SLR(1) 的折中方案：

  • 分析能力：强于 SLR(1)，弱于 LR(1)
  • 状态数：与 LR(0) 相同（远少于 LR(1)）

LALR(1) 的基本思想

核心思想：将 LR(1) 项目集中核心相同的项目集合并。

核心（Core）

LR(1) 项目 [A→α⋅β, a][A\rightarrow\alpha\cdot\beta,\ a][A→α⋅β, a] 的核心是 A→α⋅βA\rightarrow\alpha\cdot\betaA→α⋅β（去掉向前看符号）。

两个 LR(1) 项目集的核心相同，当且仅当它们包含的项目去掉向前看符号后完全相同。

合并规则

如果两个 LR(1) 项目集 IiI_iIi​ 和 IjI_jIj​ 的核心相同，则合并为一个 LALR(1) 项目集：

方法：对于核心相同的项目，合并向前看符号。

例如：

  • Ii={[A→α⋅β, a], [B→γ⋅δ, c]}I_i={[A\rightarrow\alpha\cdot\beta,\ a],\ [B\rightarrow\gamma\cdot\delta,\ c]}Ii​={[A→α⋅β, a], [B→γ⋅δ, c]}
  • Ij={[A→α⋅β, b], [B→γ⋅δ, d]}I_j={[A\rightarrow\alpha\cdot\beta,\ b],\ [B\rightarrow\gamma\cdot\delta,\ d]}Ij​={[A→α⋅β, b], [B→γ⋅δ, d]}

合并后：

  • Iij={[A→α⋅β, {a,b}], [B→γ⋅δ, {c,d}]}I_{ij}={[A\rightarrow\alpha\cdot\beta,\ {a, b}],\ [B\rightarrow\gamma\cdot\delta,\ {c, d}]}Iij​={[A→α⋅β, {a,b}], [B→γ⋅δ, {c,d}]}

LALR(1) 构造方法

方法 1：从 LR(1) 项目集族合并

  1. 构造完整的 LR(1) 项目集族
  2. 合并核心相同的项目集
  3. 构造 LALR(1) 分析表

方法 2：直接构造（效率更高）

  1. 构造 LR(0) 项目集族
  2. 为每个项目添加向前看符号（传播和自发生成）
  3. 构造 LALR(1) 分析表

LALR(1) 的特点

优点

  1. 状态数少：与 LR(0)/SLR(1) 相同，远少于 LR(1)
  2. 分析能力强：强于 SLR(1)，能处理绝大多数实际文法
  3. 广泛使用：Yacc、Bison 等工具采用 LALR(1)

缺点

  1. 可能引入新的归约-归约冲突：合并项目集时，可能使原本不冲突的变成冲突

    • LR(1) 无冲突 ⇏\not\Rightarrow⇒ LALR(1) 无冲突
    • 但实践中很少遇到

  2. 错误检测延迟：可能在错误位置后才检测到错误（但不影响正确性）

二义性文法在 LR 分析中的应用

某些二义性文法虽然理论上不是 LR 文法，但通过优先级和结合性规则可以转化为等价的 LR 分析器。

二义性表达式文法

典型的二义性文法：

E→E+EE→E∗EE→(E)E→id \begin{aligned} E &\rightarrow E + E \\ E &\rightarrow E * E \\ E &\rightarrow (E) \\ E &\rightarrow\text{id} \end{aligned} EEEE​→E+E→E∗E→(E)→id​

问题：id+id∗id\text{id} + \text{id} * \text{id}id+id∗id 有两棵不同的语法树。

冲突示例

某个 LR(1) 项目集：

[E→E⋅+E, ∗][E→E+E⋅, ∗][E→E⋅∗E, $] \begin{aligned} &[E\rightarrow E\cdot + E,\ *] \\ &[E\rightarrow E + E\cdot,\ *] \\ &[E\rightarrow E\cdot * E,\ \text{\textdollar}] \end{aligned} ​[E→E⋅+E, ∗][E→E+E⋅, ∗][E→E⋅∗E, $]​

移进-归约冲突：看到 * 时，

  • 移进：继续 E→E⋅∗EE\rightarrow E\cdot * EE→E⋅∗E
  • 归约：完成 E→E+E⋅E\rightarrow E + E\cdotE→E+E⋅

如何选择？ 取决于 * 的优先级和结合性。

优先级和结合性规则

优先级（Precedence）

运算符的优先级决定冲突时的选择：

运算符 优先级
* 高
+ 低

规则：

  • 如果当前运算符优先级高于栈顶运算符：移进
  • 如果当前运算符优先级低于栈顶运算符：归约

结合性（Associativity）

同优先级运算符的结合性：

  • 左结合（Left Associative）：a+b+c=(a+b)+ca + b + c = (a + b) + ca+b+c=(a+b)+c

    • 遇到相同运算符时：归约

  • 右结合（Right Associative）：a=b=c=a=(b=c)a = b = c = a = (b = c)a=b=c=a=(b=c)（赋值）

    • 遇到相同运算符时：移进

Yacc/Bison 中的声明

在 Yacc/Bison 中，使用 %left、%right、%nonassoc 声明：

%left '+' '-'      // + 和 - 左结合，优先级相同
%left '*' '/'      // * 和 / 左结合，优先级高于 + -
%right '='         // = 右结合
%nonassoc UMINUS   // 一元负号，不可结合

顺序：后声明的优先级更高。

消解冲突的规则

对于移进-归约冲突：

  1. 根据优先级：

    • 当前输入符号优先级 > 栈顶产生式优先级：移进
    • 当前输入符号优先级 < 栈顶产生式优先级：归约

  2. 根据结合性（优先级相同时）：

    • 左结合：归约
    • 右结合：移进
    • 不可结合：报错

对于归约-归约冲突：

  • 无法通过优先级和结合性解决
  • 必须改写文法

示例：使用优先级解决冲突

二义性文法 + 优先级声明：

%left '+'
%left '*'

%%
E : E '+' E
  | E '*' E
  | '(' E ')'
  | ID
  ;

冲突解决：

栈内容 输入 冲突 优先级比较 决策
E + E * 移进/归约 * > + 移进
E * E + 移进/归约 + < * 归约
E + E + 移进/归约 + = +，左结合 归约

结果：正确处理优先级和结合性。

悬挂 else 问题

文法：

S→if E then SS→if E then S else SS→other \begin{aligned} S &\rightarrow\text{if}\ E\ \text{then}\ S \\ S &\rightarrow\text{if}\ E\ \text{then}\ S\ \text{else}\ S \\ S &\rightarrow\text{other} \end{aligned} SSS​→if E then S→if E then S else S→other​

冲突：

if E1 then if E2 then S1 else S2

某个项目集：

[S→if E then S⋅, else][S→if E then S⋅else S, $] \begin{aligned} &[S\rightarrow\text{if}\ E\ \text{then}\ S\cdot,\ \text{else}] \\ &[S\rightarrow\text{if}\ E\ \text{then}\ S\cdot\text{else}\ S,\ \text{\textdollar}] \end{aligned} ​[S→if E then S⋅, else][S→if E then S⋅else S, $]​

移进-归约冲突：看到 else，

  • 归约：完成第一个 if
  • 移进：else 匹配第二个 if

解决：优先移进（else 匹配最近的 if）

Yacc/Bison 默认：移进优先。

LR 分析的错误处理

错误检测

LR 分析器在以下情况检测到错误：

  • ACTION 表为空：ACTION[s,a]\text{ACTION}[s, a]ACTION[s,a] 没有定义
  • 即当前状态和输入符号的组合非法

LR 分析器能在第一时间检测到错误（不会延迟）。

错误恢复策略

应急恢复（Panic Mode）

策略：丢弃栈中的状态，直到找到可以继续的状态。

方法：

  1. 扫描栈，找到一个包含同步非终结符（如 stmt、expr）的状态
  2. 丢弃输入符号，直到找到后继符号（如 ;、}）
  3. 继续分析

短语层恢复

策略：根据当前状态和输入符号，局部修改（插入、删除、替换）。

实现：在 ACTION 表中，为空项填入错误处理动作：

  • 插入缺失的符号
  • 删除多余的符号
  • 给出有用的错误提示

错误产生式

策略：在文法中添加错误产生式，识别常见错误。

示例：

stmt : IF '(' expr ')' stmt
     | IF '(' expr stmt    // 错误：缺少 ')'
       { yyerror("缺少 ')'"); }
     ;

本章小结：

LR 分析是自底向上语法分析的核心方法，特别是 LALR(1) 是现代编译器工具（Yacc、Bison）的理论基础。通过：

  • 优先级和结合性：处理二义性文法

我们可以为大多数实际编程语言构造高效的语法分析器。虽然 LR 分析的理论较为复杂，但工具的成熟使得实践中使用 LR 分析变得非常简单——只需编写文法规则和语义动作，Bison 会自动生成完整的分析器。

掌握 LR 分析原理，不仅有助于使用工具（理解冲突报告、调试文法），也为深入理解编译器的工作机制、优化编译器性能打下坚实基础。

例题

例 1：构造 LR 分析表并分析输入串

题目：文法 G[S]G[S]G[S]（定义二进制小数）：

S→L.L ∣ LL→LB ∣ BB→0 ∣ 1 \begin{aligned} S &\rightarrow L.L\ |\ L \\ L &\rightarrow LB\ |\ B \\ B &\rightarrow 0\ |\ 1 \end{aligned} SLB​→L.L ∣ L→LB ∣ B→0 ∣ 1​

（1）构造 LR 分析表，并说明属于哪类 LR 分析表。 （2）给出输入串 101.110101.110101.110 的分析过程。

第一步：增广文法与产生式编号

引入新开始符号 S′S'S′，增广文法共 7 条产生式：

编号 产生式
(0) S′→SS' \rightarrow SS′→S
(1) S→L.LS \rightarrow L.LS→L.L
(2) S→LS \rightarrow LS→L
(3) L→LBL \rightarrow LBL→LB
(4) L→BL \rightarrow BL→B

(6) B→1B \rightarrow 1B→1

注意：产生式 (1) 中的 . 是小数点终结符，不是 LR 项目中的点。
