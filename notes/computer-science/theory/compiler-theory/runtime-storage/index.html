运行时存储组织

2026-05-15

#编译原理

阅读线索

运行时存储把变量生命周期、函数调用和动态对象落实到内存。活动记录管理一次调用，静态链与动态链分别服务于不同的访问与返回关系。

运行时存储概述

程序运行时需要存储：变量的值、函数调用的上下文、动态分配的对象……运行时存储组织（Runtime Storage Organization）研究编译器如何规划和管理程序运行时的内存布局。

类比：运行时存储就像一栋大楼——代码段是写好的规程手册（不变），静态区是长期住户（生命周期=整个程序），栈是轮班工作人员（来了就用，走了就腾），堆是临时租户（随时入住，随时退房）。

运行时存储器的分区

一个典型程序的内存布局：

高地址
┌──────────────────┐
│       栈 Stack   │ ← 向下增长
│         ↓        │
│  （未使用空间）   │
│         ↑        │
│       堆 Heap    │ ← 向上增长
├──────────────────┤
│  BSS 段（未初始化）│
├──────────────────┤
│  数据段（已初始化）│
├──────────────────┤
│     代码段        │
└──────────────────┘
低地址

代码段（Code Segment / Text Segment）

  • 存储程序的机器指令
  • 通常只读（防止代码被意外修改）
  • 大小在编译时确定，运行时不变

静态数据段（Static Data Segment）

  • 存储全局变量、静态变量（static）和字符串常量
  • 生命周期 = 程序整个运行期间
  • 编译器在编译时为每个静态变量分配固定偏移

已初始化数据段（.data）：有初始值的全局/静态变量 未初始化数据段（.bss）：未初始化的全局/静态变量（程序启动时清零）

栈（Stack）

  • 用于函数调用：每次调用在栈上分配一个活动记录（Activation Record）
  • 后进先出（LIFO）：函数返回时，其活动记录被弹出
  • 由硬件和操作系统提供支持（rsp / sp 寄存器指向栈顶）

堆（Heap）

  • 用于动态内存分配（malloc、new）
  • 生命周期由程序员（或垃圾回收器）控制
  • 分配/释放顺序任意，管理复杂

三种存储分配策略

编译器为程序中的名字（变量、数组等）分配存储空间时，有三种基本策略：

静态分配（Static Allocation）

在编译时就确定所有名字的存储位置，运行时地址固定不变。

适用条件：

  • 变量的大小在编译时已知
  • 不需要支持递归（同一过程不能同时有多个活动实例）

特点：

  • 访问速度最快（直接用绝对地址）
  • Fortran 77 等早期语言采用纯静态分配

全局变量、静态局部变量（static 关键字）都使用静态分配。

栈式分配（Stack Allocation）

在运行时，随函数调用动态地在栈上分配活动记录，函数返回时自动释放。

适用条件：

  • 支持递归
  • 变量的生命周期与所在过程的活动期一致

特点：

  • 分配和释放都是 O(1)O(1)O(1)（只需移动栈指针）
  • 支持递归调用
  • C、C++、Java 的局部变量均采用栈式分配

堆式分配（Heap Allocation）

在运行时，从堆区按需申请，由程序员（或 GC）决定何时释放。

适用条件：

  • 对象的生命周期与调用者/被调用者的关系无关
  • 需要在函数返回后仍保持存活的数据

特点：

  • 灵活，但管理复杂，可能产生碎片
  • malloc/new 动态分配的对象使用堆式分配

三种策略对比

策略 分配时机 释放时机 支持递归 速度 典型用途
静态分配 编译时 程序结束 否 最快 全局变量、静态变量
栈式分配 调用时 返回时 是 快 局部变量、参数
堆式分配 申请时 手动/GC 是 慢 动态对象

活动树（Activation Tree）

什么是活动树

程序运行过程中，每次过程调用都产生一次活动（Activation）。所有活动之间的调用关系构成一棵树，称为活动树（Activation Tree）。

规则：

  • 每个节点代表过程的一次活动
  • 若过程 ppp 调用了过程 qqq，则 qqq 的活动节点是 ppp 的子节点
  • 同一过程 ppp 的多次活动，对应树中多个节点（支持递归）
  • 子节点的执行时间完全包含在父节点内（调用期间父节点处于等待）

关键性质：活动树上任意时刻从根到当前活动节点的路径，恰好对应运行时栈中从底到顶的活动记录序列。

示例

程序：

main()  调用 readarray()，再调用 quicksort(1,9)
quicksort(1,9)  调用 partition(1,9)，再递归调用 quicksort(1,3) 和 quicksort(4,9)

活动树（部分）：

              main
           /       \
     readarray   quicksort(1,9)
                  /           \
          partition(1,9)   quicksort(4,9)
                            /     \
                    partition(4,9)  ...

对应的运行时栈（执行到 partition(4,9) 时）：

栈底 → main → quicksort(1,9) → quicksort(4,9) → partition(4,9) ← 栈顶

活动树路径 main→quicksort(1,9)→quicksort(4,9)→partition(4,9) 与栈内容完全对应。

活动记录（Activation Record）

什么是活动记录

每次函数调用，都在栈上创建一个活动记录（Activation Record），也叫栈帧（Stack Frame）。它保存了这次函数调用所需的全部信息。

类比：函数调用就像派人去执行任务，活动记录是给这个人的“任务包”——包含任务所需的所有资料（参数、局部变量）和事后归还所需的信息（返回地址、上一级任务包的位置）。

活动记录的典型结构

┌───────────────────────────────┐ ← 高地址（调用者的栈帧底部）
│         实参（参数）            │  由调用者压入
├───────────────────────────────┤
│         返回地址               │  call 指令压入
├───────────────────────────────┤  ← 帧指针（fp / rbp）
│         旧帧指针（动态链）       │  保存调用者的帧指针
├───────────────────────────────┤
│         静态链                 │  指向外层过程的活动记录
├───────────────────────────────┤
│    局部变量（固定大小）          │  编译时确定偏移
├───────────────────────────────┤
│    临时变量 / 寄存器保存区       │
├───────────────────────────────┤ ← 栈指针（sp / rsp）低地址

各部分说明

区域 作用 谁负责
实参 传递参数给被调用函数 调用者（Caller）
返回地址 函数返回后应继续执行的地址 call 指令自动压入
旧帧指针（动态链） 恢复调用者的帧指针；沿链可找到调用链上的所有活动记录 被调用者（Callee）
静态链 指向词法上外层过程的活动记录，用于访问非局部变量 被调用者
局部变量 函数内声明的局部变量 被调用者
临时变量 编译器生成的中间结果 被调用者

帧指针与栈指针

  • 栈指针（Stack Pointer，sp/rsp）：始终指向栈顶，随压栈/弹栈移动
  • 帧指针（Frame Pointer，fp/rbp）：指向当前帧的固定位置（通常是旧帧指针处），用于稳定地寻址局部变量
局部变量 x 的地址 = fp - 4
局部变量 y 的地址 = fp - 8
参数 a 的地址    = fp + 16

静态作用域与动态作用域

核心问题

当过程 f 引用了一个非局部变量 x（不是自己声明的），运行时应该到哪个活动记录里去找 x？

  • 静态作用域：根据程序文本的嵌套结构找——x 在词法上属于哪个外层过程，就去那个过程的活动记录找
  • 动态作用域：根据运行时的调用链找——沿调用链向上找，第一个声明了 x 的活动记录就是答案

静态作用域（Static Scope）

又称词法作用域（Lexical Scope）：名字的绑定由程序文本的嵌套层次决定，在编译时就已确定，与运行时的调用顺序无关。

示例：

program main;
  var x: integer;       (* x 在 main 中声明，嵌套层次 1 *)

  procedure f;
  begin
    write(x)            (* f 引用 x，词法上 x 属于 main *)
  end;

  procedure g;
    var x: integer;     (* g 中声明了自己的 x，嵌套层次 2 *)
  begin
    x := 2;
    f                   (* 调用 f *)
  end;

begin
  x := 1;
  g                     (* 调用 g，g 调用 f *)
end.

f 里的 x 在文本上属于 main（f 的词法外层），所以静态作用域下 f 打印 1，不管调用链上有没有 g 声明的 x。

绑定确定时机：编译时——编译器在看到 f 中的 x 时，直接根据嵌套层次确定它来自 main，生成“沿静态链跳 1 次 + 偏移量”的访问代码。

动态作用域（Dynamic Scope）

名字的绑定由运行时的调用链决定——沿调用链向上找，第一个声明了该名字的活动记录就是绑定目标。

同样的示例，若采用动态作用域：

调用链为 main → g → f，f 中访问 x 时沿调用链向上找：

  • f 自己没有 x
  • g（调用者）有 x = 2，找到了！

动态作用域下 f 打印 2。

绑定确定时机：运行时——每次访问非局部变量都要沿动态链（调用链）向上搜索，直到找到声明。

对比

静态作用域 动态作用域
绑定依据 程序文本的嵌套层次 运行时的调用链
绑定时机 编译时确定 运行时确定
实现机制 静态链 动态链（沿调用栈查找）
可预测性 好，阅读代码即可确定 差，依赖调用关系
访问效率 高（编译时计算层次差） 低（运行时逐层查找）
典型语言 C、Java、Python、Go 早期 Lisp、某些 Shell

记忆口诀：静态看文本，动态看调用。

非局部变量的访问

动态链与静态链的区别

活动记录中有两个链，初学时容易混淆：

动态链（Dynamic Link） 静态链（Static Link）
别名 控制链（Control Link） 访问链（Access Link）
指向 调用者的活动记录 词法外层过程的活动记录
用途 函数返回时恢复调用者的帧指针 访问非局部变量
内容 反映运行时调用关系 反映程序文本嵌套关系
何时相同 当调用者恰好就是词法外层时，两者相同

类比：动态链是“你是谁叫来的（调用关系）”，静态链是“你的代码写在谁里面（文本关系）”。两者通常不同。

静态链（Static Link）

定义：每个活动记录中保存一个指针，指向词法上直接外层过程的最近一次活动记录。

访问非局部变量的步骤：

设当前过程嵌套层次为 dcd_cdc​，被访问变量所在过程嵌套层次为 dvd_vdv​，则层次差 k=dc−dvk = d_c - d_vk=dc​−dv​：

  1. 从当前活动记录出发，沿静态链跳 kkk 次
  2. 到达目标过程的活动记录
  3. 用变量的偏移量寻址
当前活动记录
  │静态链
  ↓
外层1的活动记录
  │静态链
  ↓
外层2的活动记录（目标）→ 变量偏移量 → 找到变量

静态链的设置：被调用过程进入时，将静态链设置为调用者的活动记录中，属于同一词法外层的那条链。

具体规则（设被调用过程嵌套层次为 ddd，调用者层次为 d′d'd′）：

  • 若 d′≥dd' \geq dd′≥d：调用者沿自己的静态链跳 d′−d+1d' - d + 1d′−d+1 次，所到达的记录就是新的静态链目标
  • 若 d′=d−1d' = d - 1d′=d−1：调用者本身的活动记录就是静态链目标（最常见情况）

示例：静态链的建立与使用

过程嵌套结构（Pascal 风格）：

program main (层次 0)
  procedure a (层次 1)
    procedure b (层次 2)
    end b
  end a
  procedure c (层次 1)
    procedure d (层次 2)
      ... 访问 a 中的变量 ...
    end d
  end c
end main

调用序列：main 调用 c，c 调用 d。

运行时栈与静态链：

┌──────────────┐
│   main (0)   │ ← 静态链=null（顶层）
├──────────────┤
│    c (1)     │ ← 静态链 → main（c 的词法外层是 main）
├──────────────┤
│    d (2)     │ ← 静态链 → c（d 的词法外层是 c）
└──────────────┘  ← 栈顶（当前）

注意：此处 d 的动态链指向 c（调用者），静态链也指向 c（词法外层），两者恰好相同——因为 d 就是在 c 内部定义的。

若 d 要访问 a 中的变量（层次差 k=2−1=1k = 2 - 1 = 1k=2−1=1，但 a 不是 d 的外层，实际上 d 无法直接访问 a 的局部变量，因为 a 不在 d 的静态链路径上）。

关键：静态链只能访问词法外层的变量，不能访问“词法上并列”的其他过程的变量。

动态链（Dynamic Link）

定义：每个活动记录中保存一个指针，指向调用者的活动记录（即旧帧指针）。

用途：

  • 函数返回时恢复调用者的帧指针（出栈操作）
  • 动态作用域下，沿动态链查找非局部变量

动态链体现的是运行时控制流，与程序文本结构无关。

同一个过程被不同过程调用时，动态链不同，但静态链不变（词法结构固定）。

静态链 vs 动态链：完整对比示例

程序：

main (层次0) 调用 a (层次1)
a (层次1) 调用 b (层次2)
b (层次2) 调用 c (层次1)   ← 注意：b 调用 c，但 c 是 main 的子过程

运行时栈：

┌──────────────┐
│   main (0)   │  动态链=null  静态链=null
├──────────────┤
│    a (1)     │  动态链→main  静态链→main
├──────────────┤
│    b (2)     │  动态链→a     静态链→a
├──────────────┤
│    c (1)     │  动态链→b     静态链→main  ← 两链不同！
└──────────────┘
  • c 的动态链指向 b（谁调用了 c）
  • c 的静态链指向 main（c 在文本上定义于 main 内）

此时若 c 访问 main 的变量，沿静态链跳 1 次即可到达 main；若按动态链跳 1 次则到 b，方向完全错误。

display 数组

思路：用一个全局数组 display[] 直接存储各嵌套层次的当前活动记录地址，避免多次指针跳转。

  • display[i]：第 iii 层嵌套的当前活动活动记录地址

访问第 iii 层的变量：直接用 display[i] 加偏移，一步到位。

维护规则：

  • 进入层次为 ddd 的过程时：将 display[d] 的旧值保存到当前活动记录中，再将 display[d] 更新为当前活动记录的地址
  • 退出时：从活动记录中恢复 display[d] 的旧值
方式 访问非局部变量 维护代价 适用场景
静态链 O(k)O(k)O(k)，跳 kkk 次 低 嵌套层次浅
display O(1)O(1)O(1)，直接寻址 较高（进出过程都要更新） 嵌套层次深、频繁访问非局部变量

调用序列与返回序列

调用序列（Call Sequence）

函数调用时，调用者和被调用者需要协作完成活动记录的建立。

调用者负责：

  1. 将实参压入栈（或存入寄存器）
  2. 执行 call 指令（压入返回地址，跳转到函数入口）

被调用者负责（函数序言 Prologue）：

  1. 保存旧帧指针（push rbp）
  2. 设置新帧指针（mov rbp, rsp）
  3. 为局部变量分配空间（sub rsp, N）
  4. 保存被调用者保存的寄存器
; x86-64 函数序言
f:
    push rbp         ; 保存旧帧指针
    mov  rbp, rsp    ; 设置新帧指针
    sub  rsp, 16     ; 为局部变量分配 16 字节
    ...

返回序列（Return Sequence）

被调用者负责（函数尾声 Epilogue）：

  1. 恢复被调用者保存的寄存器
  2. 恢复旧帧指针（pop rbp）
  3. 执行 ret 指令（弹出返回地址，跳转）

调用者负责：

  1. 清理压入的实参（某些调用约定）
  2. 取得返回值（通常在 rax 寄存器中）
; x86-64 函数尾声
    ...
    mov  rsp, rbp    ; 恢复栈指针
    pop  rbp         ; 恢复旧帧指针
    ret              ; 返回

参数传递机制

不同语言、不同场景下，参数传递方式不同。

传值（Call by Value）

机制：将实参的值复制给形参，函数内对形参的修改不影响实参。

void f(int x) { x = 100; }
int a = 1;
f(a);  // a 仍然是 1
  • C 语言、Java 基本类型默认传值
  • 安全，但大对象复制开销大

传引用（Call by Reference）

机制：将实参的地址传给形参，函数内对形参的修改直接影响实参。

void f(int &x) { x = 100; }
int a = 1;
f(a);  // a 变为 100
  • C++ 引用参数、Fortran 默认方式
  • 效率高（不复制大对象），但有副作用风险

传名（Call by Name）

机制：将实参的表达式（文本替换）传入，每次使用形参时重新求值实参表达式。

类似宏替换，在 Algol 60 中使用。

swap(i, a[i]) 实际展开为：
    temp = i; i = a[i]; a[i] = temp;
    → 但 a[i] 中的 i 在第二步已经变了，导致结果错误！
  • 现代语言几乎不用传名（行为难以预测）
  • 惰性求值语言（Haskell）有类似机制

传值-结果（Call by Value-Result）

机制：进入时传值（复制），返回时将形参的值写回实参。

也叫 Copy-In/Copy-Out，是传引用的近似，但在并发时行为不同。

对比

机制 传入内容 副作用 典型语言
传值 值的副本 无 C（基本类型）、Java
传引用 变量地址 有 C++（&）、Fortran
传名 表达式文本 复杂 Algol 60
传值-结果 值，返回时写回 有（返回时） Ada

堆的动态内存分配

堆的特点

  • 动态申请：malloc(n) / new
  • 任意时刻释放：free(p) / delete
  • 分配和释放顺序任意（不像栈的 LIFO）

内存分配算法

首次适应（First Fit）

从空闲链表头开始，找到第一个足够大的空闲块分配。

  • 速度快，但会在低地址产生碎片

最优适应（Best Fit）

找最小的足够大的空闲块分配，减少浪费。

  • 减少大碎片，但产生大量小碎片

最差适应（Worst Fit）

找最大的空闲块分配，剩余部分还可继续用。

  • 减少小碎片，但破坏大的连续空间

内存碎片

  • 外部碎片：空闲空间存在，但不连续，无法满足大块申请
  • 内部碎片：分配的块比实际需要大，多出的部分浪费

解决方案：内存紧缩（Compaction）——移动已分配块，合并空闲空间（代价高，通常配合 GC 使用）。

垃圾回收基础

什么是垃圾回收

当程序不再需要某块内存（不可达对象），如果不手动 free，就会内存泄漏。垃圾回收（Garbage Collection，GC）由运行时自动识别并回收这些内存。

引用计数（Reference Counting）

每个对象记录被引用的次数：

  • 新引用建立：计数 +1
  • 引用消失：计数 -1
  • 计数变为 0：立即回收

优点：实时回收，暂停时间短 缺点：无法处理循环引用（A 引用 B，B 引用 A，计数永不为 0）

Python 使用引用计数 + 循环检测器来处理循环引用。

标记-清除（Mark-and-Sweep）

标记阶段：从根集合（全局变量、栈上变量）出发，遍历所有可达对象，标记为“存活”。

清除阶段：扫描整个堆，回收所有未标记的对象。

优点：能处理循环引用 缺点：需要 Stop-the-World（暂停程序），产生外部碎片

复制式收集（Copying Collection）

将堆分为两半（From 空间和 To 空间）：

  1. 将 From 空间中的存活对象复制到 To 空间（同时紧缩）
  2. From 空间整体回收

优点：自动消除碎片，分配极快（只需移动指针） 缺点：只能使用一半内存

分代收集（Generational GC）

观察：大多数对象“朝生暮死”——新创建的对象很快就不用了，而活得久的对象往往活得更久。

将堆分为年轻代（Young Generation）和老年代（Old Generation）：

  • 频繁回收年轻代（Minor GC）：速度快
  • 偶尔回收老年代（Major GC / Full GC）：代价高

Java（JVM）、Python、Go 均使用分代收集或类似策略。

一个典型程序的内存布局：

高地址

│       栈 Stack   │ ← 向下增长
│         ↓        │
│  （未使用空间）   │
│         ↑        │
│       堆 Heap    │ ← 向上增长
├──────────────────┤
│  BSS 段（未初始化）│
├──────────────────┤

├──────────────────┤

└──────────────────┘
低地址

代码段（Code Segment / Text Segment）

  • 存储程序的机器指令
  • 通常只读（防止代码被意外修改）
  • 大小在编译时确定，运行时不变

静态数据段（Static Data Segment）

  • 存储全局变量、静态变量（static）和字符串常量
  • 生命周期 = 程序整个运行期间
  • 编译器在编译时为每个静态变量分配固定偏移

已初始化数据段（.data）：有初始值的全局/静态变量 未初始化数据段（.bss）：未初始化的全局/静态变量（程序启动时清零）

栈（Stack）

  • 用于函数调用：每次调用在栈上分配一个活动记录（Activation Record）
  • 后进先出（LIFO）：函数返回时，其活动记录被弹出
  • 由硬件和操作系统提供支持（rsp / sp 寄存器指向栈顶）

堆（Heap）

  • 用于动态内存分配（malloc、new）
  • 生命周期由程序员（或垃圾回收器）控制
  • 分配/释放顺序任意，管理复杂

活动记录（Activation Record）

什么是活动记录

每次函数调用，都在栈上创建一个活动记录（Activation Record），也叫栈帧（Stack Frame）。它保存了这次函数调用所需的全部信息。

类比：函数调用就像派人去执行任务，活动记录是给这个人的“任务包”——包含任务所需的所有资料（参数、局部变量）和事后归还所需的信息（返回地址、上一级任务包的位置）。

活动记录的典型结构

┌───────────────────────────────┐ ← 高地址（调用者的栈帧底部）
│         实参（参数）           │  由调用者压入
├───────────────────────────────┤
│         返回地址               │  call 指令压入
├───────────────────────────────┤  ← 帧指针（fp / rbp）
│         旧帧指针               │  保存调用者的帧指针
├───────────────────────────────┤
│    局部变量（固定大小）         │  编译时确定偏移
├───────────────────────────────┤
│    临时变量 / 寄存器保存区      │
├───────────────────────────────┤ ← 栈指针（sp / rsp）低地址

各部分说明

区域 作用 谁负责
实参 传递参数给被调用函数 调用者（Caller）
返回地址 函数返回后应继续执行的地址 call 指令自动压入
旧帧指针 恢复调用者的帧指针 被调用者（Callee）
局部变量 函数内声明的局部变量 被调用者
临时变量 编译器生成的中间结果 被调用者

帧指针与栈指针

  • 栈指针（Stack Pointer，sp/rsp）：始终指向栈顶，随压栈/弹栈移动
  • 帧指针（Frame Pointer，fp/rbp）：指向当前帧的固定位置（通常是旧帧指针处），用于稳定地寻址局部变量
局部变量 x 的地址 = fp - 4
局部变量 y 的地址 = fp - 8
参数 a 的地址    = fp + 16

静态作用域与动态作用域

静态作用域

静态作用域（Static Scope）又称词法作用域（Lexical Scope）：名字的绑定由程序文本的嵌套结构决定，在编译时就能确定。

绝大多数现代语言（C、Java、Python、Go）采用静态作用域。

示例（C 语言）：

int x = 1;
void f() { printf("%d", x); }  // 引用全局 x = 1
void g() {
    int x = 2;
    f();  // f 仍然打印 1，不受 g 中 x=2 的影响
}

实现：在活动记录中保存静态链（Static Link / Access Link），指向外层过程的活动记录，从而访问外层的局部变量。

动态作用域

动态作用域（Dynamic Scope）：名字的绑定由运行时的调用链决定，在运行时才能确定。

较少见（早期 Lisp、某些 Shell 脚本）。

同样示例，若采用动态作用域：

int x = 1;
void f() { printf("%d", x); }
void g() {
    int x = 2;
    f();  // 动态作用域下，f 打印 2（沿调用链找到 g 中的 x）
}

实现：沿动态链（Dynamic Link / Control Link）向上查找，动态链指向调用者的活动记录。

对比 静态作用域 动态作用域
绑定时机 编译时 运行时
实现 静态链 动态链
可读性 好（易预测） 差（难预测）
主流程度 现代语言主流 较少见

调用序列与返回序列

调用序列（Call Sequence）

函数调用时，调用者和被调用者需要协作完成活动记录的建立。

调用者负责：

  1. 将实参压入栈（或存入寄存器）
  2. 执行 call 指令（压入返回地址，跳转到函数入口）

被调用者负责（函数序言 Prologue）：

  1. 保存旧帧指针（push rbp）
  2. 设置新帧指针（mov rbp, rsp）
  3. 为局部变量分配空间（sub rsp, N）
  4. 保存被调用者保存的寄存器
; x86-64 函数序言
f:
    push rbp         ; 保存旧帧指针
    mov  rbp, rsp    ; 设置新帧指针
    sub  rsp, 16     ; 为局部变量分配 16 字节
    ...

返回序列（Return Sequence）

被调用者负责（函数尾声 Epilogue）：

  1. 恢复被调用者保存的寄存器
  2. 恢复旧帧指针（pop rbp）
  3. 执行 ret 指令（弹出返回地址，跳转）

调用者负责：

  1. 清理压入的实参（某些调用约定）
  2. 取得返回值（通常在 rax 寄存器中）
; x86-64 函数尾声
    ...
    mov  rsp, rbp    ; 恢复栈指针
    pop  rbp         ; 恢复旧帧指针
    ret              ; 返回

参数传递机制

不同语言、不同场景下，参数传递方式不同。

传值（Call by Value）

机制：将实参的值复制给形参，函数内对形参的修改不影响实参。

void f(int x) { x = 100; }
int a = 1;
f(a);  // a 仍然是 1
  • C 语言、Java 基本类型默认传值
  • 安全，但大对象复制开销大

传引用（Call by Reference）

机制：将实参的地址传给形参，函数内对形参的修改直接影响实参。

void f(int &x) { x = 100; }
int a = 1;
f(a);  // a 变为 100
  • C++ 引用参数、Fortran 默认方式
  • 效率高（不复制大对象），但有副作用风险

传名（Call by Name）

机制：将实参的表达式（文本替换）传入，每次使用形参时重新求值实参表达式。

类似宏替换，在 Algol 60 中使用。

swap(i, a[i]) 实际展开为：
    temp = i; i = a[i]; a[i] = temp;
    → 但 a[i] 中的 i 在第二步已经变了，导致结果错误！
  • 现代语言几乎不用传名（行为难以预测）
  • 惰性求值语言（Haskell）有类似机制

传值-结果（Call by Value-Result）

机制：进入时传值（复制），返回时将形参的值写回实参。

也叫 Copy-In/Copy-Out，是传引用的近似，但在并发时行为不同。

传值-结果 值，返回时写回 有（返回时） Ada

各活动记录 SL 位置保存的旧 Display 值：

进入层次为 ddd 的过程时，将当时 display[ddd] 的旧值存入 SL 位置，再将 display[ddd] 更新为当前活动记录地址。退出时从 SL 恢复旧值。

规律：同层次的活动记录 SL 位置形成一条“历史链”——每个 AR 保存自己进入前的旧值，退出时恢复，使 display 始终指向各层次最新的活动记录。
