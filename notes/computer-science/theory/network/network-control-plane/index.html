网络层：控制平面

2024-11-21

#计算机网络

阅读线索

控制平面计算路由并维护网络状态。链路状态和距离向量使用不同信息，OSPF 面向自治系统内部，BGP 则把跨域可达性与策略连接起来。

概述

控制平面负责计算、维护和安装转发表/流表，使数据报能从源主机正确路由到目的主机。

两种控制方案：

方案 描述
每路由器控制 每台路由器自己运行路由选择算法，与邻居路由器交互，自行计算转发表（传统 OSPF、BGP）
逻辑集中式控制（SDN） 远程控制器统一计算并向每台路由器下发转发表，路由器中的控制代理（CA）只负责执行命令

路由选择算法

路由选择算法：在路由器网络中，确定从发送方到接收方的最低开销路径。

用图 G=(N,E)G=(N,E)G=(N,E) 建模：节点为路由器，边为物理链路，边的权值为开销（距离/速率/费用等）。

c(x,y)c(x,y)c(x,y)：节点 xxx 到邻居节点 yyy 的边的开销。

算法分类

分类维度 类型 特点
信息来源 集中式（LS） 需要全局完整网络信息（全图）
分散式（DV） 只需直连邻居信息，逐步迭代
时变性 静态 人工调整，变化慢
动态 自动响应拓扑/负载变化，可能引起振荡
负载感知 负载敏感 开销反映链路当前拥塞
负载迟钝 开销不反映当前拥塞（因特网的 RIP/OSPF/BGP 均如此）

链路状态路由选择算法（LS / Dijkstra）

每个节点广播链路状态（与哪些节点相连、各链路开销），使全网所有节点都有完整的网络拓扑图，然后各自运行 Dijkstra 算法计算最短路径树。

Dijkstra 算法步骤（从源节点 uuu 出发）：

  1. 初始化：D(u)=0D(u)=0D(u)=0，其他节点 D(v)=∞D(v)=\inftyD(v)=∞
  2. 找当前未确定最短路径中距离最小的节点 www，加入已确定集合
  3. 更新 www 的邻居节点 vvv 的最短距离：D(v)=min⁡{D(v), D(w)+c(w,v)}D(v) = \min{D(v),\ D(w)+c(w,v)}D(v)=min{D(v), D(w)+c(w,v)}
  4. 重复直到所有节点确定

算法复杂度：O(∣V∣2)O(|V|^2)O(∣V∣2)，优化后 O(∣E∣log⁡∣V∣)O(|E|\log|V|)O(∣E∣log∣V∣)

距离向量路由选择算法（DV / Bellman-Ford）

分散式、迭代式、异步：每个节点只知道直连链路开销，通过与邻居交换距离向量迭代收敛。

Bellman-Ford 方程（dx(y)d_x(y)dx​(y)：节点 xxx 到 yyy 的最短路径开销）：

dx(y)=min⁡v{ c(x,v)+dv(y)}d_x(y) = \min_v\{\ c(x,v) + d_v(y) \}dx​(y)=vmin​{ c(x,v)+dv​(y)}

工作流程：

  1. 初始化：每个节点 xxx 构造距离向量（到所有已知目标的距离估计）
  2. 向所有邻居发送自己的距离向量
  3. 收到邻居 vvv 的距离向量后，更新自己的距离估计
  4. 若距离发生变化，再次向邻居广播；否则停止（自我终止）

链路开销变化与路由选择环路

链路开销降低时，DV 快速收敛（好消息传播快）。

链路开销升高时，可能引发无穷计数问题（路由选择环路）：

  • yyy 认为可以通过 zzz 到达 xxx，zzz 认为可以通过 yyy 到达 xxx → 无限循环

解决：毒性逆转（Poisoned Reverse）

  • 如果 zzz 通过 yyy 路由到 xxx，则 zzz 向 yyy 通告“我到 xxx 的距离是无穷大”
  • 这样 yyy 就不会以为可以经过 zzz 到达 xxx

注意：毒性逆转只能解决两节点间的环路，无法完全解决多节点场景。

AS 内部路由选择：OSPF

自治系统（AS）

将因特网分组织为自治系统（Autonomous System，AS）：

  • 每个 AS 是一组统一管理的路由器集合
  • AS 内部所有路由器运行相同的路由选择协议（AS 内部协议）

OSPF（开放最短路优先）

OSPF 是链路状态协议，基于 Dijkstra 算法：

  • 每台路由器向AS 内所有路由器广播链路状态信息（不只是邻居）
  • 链路状态变化时立即广播；即使未变化，每 30 分钟也周期性广播
  • OSPF 报文直接由 IP 承载（协议号 89）

OSPF 的优点

  1. 安全：路由器间可配置 MD5 鉴别，防止恶意注入
  2. 等价多路径：多条相同开销的路径可同时使用，分担流量
  3. 支持多播路由（MOSPF）
  4. 层次化结构：AS 内可划分多个区域，区域间通过主干区域互联，减小每个路由器的拓扑规模

ISP 间路由选择：BGP

当分组需要跨越多个 AS 时，使用BGP（Border Gateway Protocol，边界网关协议）——因特网唯一的 AS 间路由选择协议。

BGP 的作用

  1. 从邻居 AS 获得前缀的可达性信息：让整个因特网知道某子网的存在
  2. 确定到该前缀的“最好路由”：综合策略和可达性信息做决策

BGP 路由器类型

  • 网关路由器（gateway router）：位于 AS 边缘，直连其他 AS 的路由器
  • 内部路由器（internal router）：只连接本 AS 内部节点

BGP 连接类型

  • eBGP（外部 BGP）：跨越两个 AS 的 BGP 连接（网关路由器间）
  • iBGP（内部 BGP）：同一 AS 内路由器间的 BGP 会话（不必须是物理直连）

BGP 使用 TCP 179 端口的半永久连接。

BGP 路由通告

以前缀 xxx 的可达性通告为例：

  1. AS3 的网关路由器 3a 向 AS2 的网关路由器 2c 发 eBGP 报文：AS3 x
  2. AS2 的 2c 通过 iBGP 通告 AS2 内所有路由器（含网关 2a）：AS3 x
  3. AS2 的 2a 向 AS1 的 1c 发 eBGP 报文：AS2 AS3 x
  4. AS1 的 1c 通过 iBGP 通告 AS1 内所有路由器：AS2 AS3 x

BGP 属性

路由通告时包含BGP 属性（BGP attributes）：

属性 含义
AS-PATH 通告已经经过的 AS 列表（如 AS2 AS3），用于防环检测（若看到自己的 ASN 则拒绝）
NEXT-HOP AS-PATH 起始路由器接口的 IP 地址，用于 AS 内路由选择协议与 BGP 协同工作

完整 BGP 路由表项格式：NEXT-HOP AS-PATH; 目的前缀

热土豆路由选择

当有多条路径可达某前缀时，路由器选择NEXT-HOP 中 AS 内路由开销最小的路径（尽快将数据“扔出”本 AS），忽略 AS 间开销。

比喻：像接力赛跑，每个选手尽快把“土豆”（分组）传递给下一个选手，不管下一段有多难跑。

SDN 控制平面

SDN 四大特征

  1. 基于流的转发：基于多个首部字段值（L2/L3/L4）做转发决策，而不只是目的 IP
  2. 数据平面与控制平面分离：网络交换机只执行转发，控制逻辑在远程服务器上
  3. 网络控制功能位于数据平面交换机外部：SDN 控制器（网络操作系统）+ 网络控制应用程序
  4. 可编程的网络：通过控制器的 API 定义转发规则，实现路由、防火墙、负载均衡等

SDN 控制器三层结构

网络控制应用程序（路由、负载均衡、防火墙...）
         ↑↓ 北向 API
    SDN 控制器（网络操作系统）
    ┌──────────────────────┐
    │ 网络范围状态管理层     │  维护链路/主机/交换机/流表的最新状态
    │ 通信层（南向接口）     │  与受控网络设备通信（如 OpenFlow 协议）
    └──────────────────────┘
         ↕ 南向接口（OpenFlow 等）
    SDN 使能的网络交换机（只做转发）
层 功能
通信层（南向） 控制器与交换机之间传递流表、状态和事件
网络范围状态管理层 维护全网拓扑、链路状态、流表、统计数据
北向 API 供网络控制应用程序读取网络状态、安装流表规则

SDN 控制器逻辑上集中，实际通常分布式部署在多台服务器上，保证高可用性。

ICMP：因特网控制报文协议

ICMP 用于主机和路由器之间沟通网络层信息，典型用途是差错报告。

  • ICMP 报文封装在 IP 分组中（上层协议编码为 1）
  • 位于 IP 之上，但又承载在 IP 数据报中（跨越网络层边界的协议）

常用 ICMP 报文：

类型 编码 说明
0 0 回显回答（ping 响应）
3 0 目的网络不可达
3 1 目的主机不可达
3 3 目的端口不可达
4 0 源抑制（拥塞控制，实践中少用）
8 0 回显请求（ping 请求）
11 0 TTL 过期
12 0 IP 首部损坏

ping 工作原理：发送 ICMP 类型 8 编码 0 → 目的主机回复类型 0 编码 0。

网络管理与 SNMP

网络管理框架五要素

组件 说明
管理服务器 运行于网络运营中心（NOC），负责收集、处理、控制网络信息
被管设备 网络中受管理的设备（路由器、交换机等）
被管对象 设备中的具体硬件/配置，如网卡、路由协议参数
MIB（管理信息库） 存储被管对象的信息，由 SMI 语言定义，具有正式语法
网络管理代理 运行在被管设备中，响应管理服务器命令
网络管理协议 管理服务器与代理之间的通信协议（如 SNMP）

SNMP（简单网络管理协议）

应用层协议，用于传递网络管理控制报文。

两种工作模式：

  1. 请求-响应：管理服务器发请求，代理执行并回复（查询/设置 MIB 对象值）
  2. 陷阱报文（Trap）：代理主动向管理服务器报告异常事件

SNMPv2 PDU 类型：

PDU 类型 方向 说明
GetRequest 管理者 → 代理 获取一个或多个 MIB 对象值
GetNextRequest 管理者 → 代理 获取列表中下一个 MIB 对象值
GetBulkRequest 管理者 → 代理 批量获取（如大表中的值）
InformRequest 管理者 → 管理者 向远程管理者通知 MIB 值
SetRequest 管理者 → 代理 设置 MIB 对象值
Response 代理 → 管理者 对请求的响应
SNMPv2-Trap 代理 → 管理者 主动通报异常事件
