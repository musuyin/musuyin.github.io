网络层：数据平面

2024-11-09

#八股#计算机网络

阅读线索

数据平面根据转发表处理每个分组，路由器内部结构和排队决定转发成本。IP 编址、分片、NAT 与 IPv6 则规定分组在网络中的表示和转发边界。

概述

网络层的两大功能

功能 描述 实现
转发（forwarding） 将分组从入链路接口移到适当的出链路接口（局部动作） 数据平面，硬件实现（纳秒级）
路由选择（routing） 确定分组从源到目的地的端到端路径（全局过程） 控制平面，软件实现（毫秒级）

转发表（forwarding table）：路由器用于查找出链路的数据结构，由路由选择协议或远程 SDN 控制器计算和维护。

数据平面 vs 控制平面

  • 数据平面：每台路由器的本地功能 → 执行转发
  • 控制平面：网络范围的全局逻辑 → 计算路径、生成转发表

两种控制平面方案：

  1. 传统方式（每路由器控制）：每台路由器自己运行路由选择算法（OSPF、BGP 等），与邻居路由器交换信息，自行计算转发表
  2. SDN 方式（逻辑集中式控制）：远程控制器计算并下发转发表，路由器只负责执行转发

网络服务模型

因特网的网络层提供尽力而为服务（best-effort service）：

  • 不保证按序到达
  • 不保证最终交付
  • 不保证端到端时延
  • 不保证最小带宽

看似什么都不保证，但配合足够带宽，已足以支撑绝大多数应用。

分组交换机分类

类型 转发依据
链路层交换机 链路层帧的首部字段（MAC 地址）
路由器 网络层数据报的首部字段（IP 地址）

路由器工作原理

四大核心部件

输入端口 → 交换结构 → 输出端口
              ↑
         路由选择处理器（控制平面）
部件 功能
输入端口 物理层/链路层处理；查询转发表确定输出端口
交换结构 将分组从输入端口转发到输出端口（路由器内部的“网络”）
输出端口 缓存分组，执行调度，通过物理层/链路层发送
路由选择处理器 运行路由协议、维护转发表（传统）；或与远程控制器通信（SDN）

基于目的地的转发

IP 地址 32 位，逐一列举不可行，采用前缀匹配：

  • 路由器用目的地址的前缀与转发表中表项匹配
  • 多个表项都匹配时，使用最长前缀匹配规则（Longest Prefix Matching）

例：目的地址 11001000.00010111.00010110.10100001

  • 前缀 /21 匹配 → 转发到对应接口
  • 前缀 /24 也匹配且更长 → 选 /24

为在纳秒级完成查找，使用专用硬件：TCAM（三态内容可寻址存储器），基本常数时间返回结果。

三种交换结构

类型 原理 特点
经内存交换 CPU 控制，分组先存入内存再发出 简单，受内存带宽限制，同时只能转发 B/2B/2B/2 个分组
经总线交换 分组经共享总线直达输出端口 不需要 CPU 介入，但总线同时只能传一个分组
经互联网络交换 纵横式交换机，N 路输入×N 路输出 非阻塞，不同输入输出对可并行传输，性能最好

输入端口处理

  • 输入端口维护分组队列
  • 线路前部（HOL）阻塞：队列头部的分组争抢同一输出端口时，后面等待其他输出端口的分组也被阻塞，降低吞吐量

输出端口处理与排队

  • 交换结构比输出链路快 NNN 倍，但 NNN 个输入端口同时向同一输出端口发送，一个周期内积累 NNN 个分组 → 输出队列增长
  • 缓存满时采用**主动队列管理（AQM）**算法：
    • 弃尾（drop-tail）：丢弃新到达分组
    • 随机早期检测（RED）：提前随机丢弃，提示发送方降速

经验公式：缓冲大小 B=RTT×CB = RTT \times CB=RTT×C（CCC 为链路容量）

分组调度

算法 描述
FIFO 按到达顺序传输
优先权排队 不同优先级的队列，先处理高优先级；非抢占式：当前分组传完才处理高优先级
循环排队（Round Robin） 轮流服务各优先级队列
加权公平排队（WFQ） 每类按权重 wi/∑wjw_i/\sum w_jwi​/∑wj​ 分配带宽，保证最小服务比例

网际协议 IP

IPv4 数据报格式

+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|版本(4)|首部长度(4)|服务类型(8)    |总长度(16)                   |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|标识(16)                         |标志(3)|片偏移(13)             |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|TTL(8)          |协议(8)         |首部检验和(16)                 |

关键字段说明：

字段 说明
版本 4 bits，当前 IPv4=4
首部长度 4 bits，通常 5（即 20 字节）；含选项时更长
服务类型（TOS） 区分实时流量和普通流量
总长度 16 bits，最大 65535 字节（实际很少超过 1500）
TTL（寿命） 每经过一台路由器减 1，降为 0 则丢弃（防止无限循环）
协议 指示上层协议：6=TCP，17=UDP
首部检验和 每经路由器需重新计算（TTL 字段改变）
标识、标志、片偏移 用于 IP 分片重组

IP 分片

不同链路有不同的 MTU（最大传输单元）。当数据报超过出链路的 MTU 时，路由器将其分片（fragment）：

  • 每个片有相同的源/目的地址和标识号
  • 标志位 MF（More Fragments）：最后一片 MF=0，其他片 MF=1
  • 片偏移（offset）：该片在原始数据报中的位置，以 8 字节为单位

重组只在目的主机完成，不在中间路由器。

例：4000 字节数据报（20B 首部 + 3980B 数据），MTU=1500B：

片 数据大小 偏移 offset MF
1 1480B 0 1
2 1480B 185（1480/8） 1
3 1020B 370（2960/8） 0

IPv4 编址

IP 地址

  • 每个 IP 地址 32 位，全球约 40 亿个，以点分十进制表示（如 192.168.1.1）
  • IP 地址与**接口（interface）**关联，而非主机或路由器
  • 路由器有多个接口，每个接口有独立 IP 地址

子网（Subnet）

  • 同一子网内的接口 IP 地址具有相同的高位前缀，无需路由器即可互联
  • 子网地址表示：a.b.c.d/x，x 为子网掩码（网络部分位数）

识别子网：断开所有主机-路由器接口，每一个孤立网络岛即为一个子网。

CIDR（无类别域间路由选择）

  • a.b.c.d/x：前 x 位为网络前缀（可任意长度，不限于 8/16/24）
  • 地址聚合（路由聚合）：一个前缀代表多个子网，缩减路由表规模
ISP: 200.23.16.0/20  →  代表了 200.23.16.x ～ 200.23.31.x 内的所有组织

特殊地址

地址 用途
255.255.255.255 广播地址，发给同网络所有主机
0.0.0.0 DHCP 发现时使用的源地址
每子网最后一个地址 该子网广播地址
10.x.x.x / 192.168.x.x / 172.16-31.x.x 私有地址（不在公网路由）

DHCP（动态主机配置协议）

DHCP 自动为主机分配 IP 地址（即插即用协议）。

四步过程：

  1. Discover：客户端广播（源 0.0.0.0，目的 255.255.255.255，端口 67）寻找 DHCP 服务器
  2. Offer：服务器广播提供 IP 地址、子网掩码、默认网关、DNS 服务器、租用期
  3. Request：客户端选择一个提供并请求确认（广播，允许多个服务器知道选择结果）
  4. ACK：服务器确认，客户端正式使用该地址

DHCP 缺陷：节点移动到新子网需重新获取 IP，无法维持 TCP 连接。

NAT（网络地址转换）

允许私有网络（内网）使用同一个公网 IP 地址接入因特网。

工作原理（以请求 Web 服务为例）：

  1. 内网主机 10.0.0.1:3345 发送数据报
  2. NAT 路由器将源地址替换为公网 IP 138.76.29.7，端口替换为新端口 5001，并记录到 NAT 转换表
  3. 服务器响应发往 138.76.29.7:5001
  4. NAT 路由器查转换表，将目的改为 10.0.0.1:3345，转发到内网

NAT 转换表：(外网IP:外端口) ↔ (内网IP:内端口)

  • 最多支持约 60000 个并发连接（16 位端口）
  • NAT 对外像“单一设备”，隐藏了内网细节

IPv6

IPv6 改进

改进 说明
地址长度 32 → 128 位，几乎无限地址
简化首部 定长 40 字节，去掉分片字段、检验和、选项（选项用“下一首部”扩展）
流标签 标识特定流，支持 QoS 和实时服务
任播地址 发给“一组中最近的”一台主机

IPv6 数据报格式（主要字段）

字段 说明
版本（4 bits） 值为 6
流量类型（8 bits） 类似 IPv4 TOS
流标签（20 bits） 标识特定数据流
有效载荷长度（16 bits） 40B 首部之后的字节数
下一个首部（8 bits） 标识上层协议（TCP=6，UDP=17）或扩展首部
跳限制（8 bits） 类似 IPv4 TTL，路由器每过一跳减 1
源/目的地址（各 128 bits）

IPv6 去掉了哪些字段

  • 分片/重组：只在端系统进行，路由器不分片，直接丢弃过大数据报并发 ICMP 差错报文
  • 首部检验和：传输层和链路层已有检验，去掉节省每台路由器的重算开销
  • 选项：通过“下一个首部”链指向扩展首部

IPv4 → IPv6 迁移：建隧道（Tunneling）

将 IPv6 数据报整体封装在 IPv4 数据报的有效载荷中，穿越 IPv4 路由器组成的“隧道”。

  • 隧道两端都是 IPv6 路由器
  • IPv4 协议字段值为 41，表示载荷是 IPv6 数据报

通用转发与 SDN

匹配加动作（Match-Plus-Action）

传统 IP 转发：匹配目的 IP → 转发到某出口。

通用转发更强大：可匹配多个首部字段（L2/L3/L4），动作更丰富：

动作 示例
转发 发往指定端口，或多播
丢弃 防火墙功能
修改字段 NAT 改写地址/端口，TTL 递减
封装转发 发往远程控制器处理

流表（flow table）（OpenFlow）：表项包含：

  • 首部字段匹配集合（支持通配符 *，有优先级）
  • 计数器（统计匹配次数、时间等）
  • 动作集合

OpenFlow 可匹配的 11 个字段：入端口、以太网源/目地址、以太类型、VLAN ID、IP 源/目地址、IP 协议、TCP/UDP 源/目端口。

通用转发交换机既能充当路由器（按 IP 转发），又能充当交换机（按 MAC 转发），还能实现防火墙、负载均衡、NAT 等中间盒功能。
