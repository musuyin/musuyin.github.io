传输层

2024-10-14

#计算机网络

阅读线索

传输层把主机通信分解到进程，并在需要时提供可靠传输。停止等待、流水线、重传与窗口机制逐步连接到 TCP，流量控制和拥塞控制则约束不同资源。

传输层概述

传输层位于应用层和网络层之间，是 OSI 体系结构中端到端的最底层次。

  • 向上：为运行在不同主机上的应用进程提供逻辑通信（好像两个进程直接相连）
  • 向下：依赖网络层提供主机间的逻辑通信

传输层协议只运行在端系统，不在路由器中：

  • 发送方：将应用报文分段封装后传给网络层
  • 接收方：将网络层上传的报文段重组后交给应用层

路由器只处理网络层字段，不识别传输层信息。

传输层 vs 网络层

对比 网络层 传输层
通信范围 主机之间 进程之间（应用程序到应用程序）
协议位置 主机 + 路由器 只在端系统

传输层可以在不可靠的网络层之上提供可靠传输（如 TCP over IP）。

因特网传输层协议

协议 全称 特点
UDP 用户数据报协议 不可靠、无连接
TCP 传输控制协议 可靠、面向连接、拥塞控制

分组术语：

  • 传输层分组 → 报文段（segment）
  • 网络层分组 → 数据报（datagram）

多路复用与分解

基本概念

将网络层提供的“主机到主机”交付，扩展为“进程到进程”的交付。

  • 多路复用（发送方）：从多个套接字收集数据，封装首部，生成报文段传给网络层（多对一）
  • 多路分解（接收方）：根据报文段中的字段，将数据送到正确的套接字（一对多）

端口号

端口号是 16 位字段（0～65535）：

  • 0～1023：周知端口号，保留给固定应用（HTTP:80，SMTP:25，FTP:21）
  • 1024～65535：应用程序自由使用

UDP 的多路复用与分解（无连接）

  • UDP 套接字由**二元组（目的 IP, 目的端口）**标识
  • 不同源但相同目的端口的 UDP 报文段 → 送到同一个套接字（多对一）
  • 源端口号作为回复时的返回地址

TCP 的多路复用与分解（面向连接）

  • TCP 套接字由**四元组（源 IP, 源端口, 目的 IP, 目的端口）**标识
  • 不同源的 TCP 报文段 → 送到不同套接字（一对一）
  • Web 服务器可为每个连接创建新进程或线程（轻量级子进程）
  • 持久 HTTP：同一套接字复用；非持久 HTTP：每次请求创建新连接

可靠数据传输原理

可靠传输要求：数据不出错、不丢失、按发送顺序到达。

rdt1.0：完全可靠信道

假设信道完全可靠，发送方直接发，接收方直接收，无需任何反馈。

rdt2.0：有比特差错，无丢包

引入**自动重传请求（ARQ）**协议：

  • 差错检测：添加校验和（checksum）字段
  • 接收方反馈：ACK（确认）或 NAK（否认）
  • 重传：收到 NAK 则重传

停等（stop-and-wait）协议：发完一个分组后等待确认，再发下一个。

问题：若 ACK/NAK 本身受损，发送方不知道是否成功。

解决：给分组添加序号字段（停等协议只需 1 bit，0 和 1 交替）。

rdt2.1 / rdt2.2

  • rdt2.1：处理受损的 ACK/NAK；接收方丢弃乱序或受损分组并回发 ACK
  • rdt2.2：去掉 NAK，改为对最后正确接收的分组发冗余 ACK（代替 NAK）

rdt3.0：有比特差错 + 丢包

增加超时重传机制：

  • 发送方启动倒计时定时器
  • 超时未收到 ACK → 重传分组
  • 用序号区分新分组和重传分组

rdt3.0 解决了所有基本问题，但效率低（停等模式）。

停等协议的性能

发送方利用率：

Usender=L/RL/R+RTTU_{sender} = \frac{L/R}{L/R + RTT}Usender​=L/R+RTTL/R​

例：1Gbps 链路，RTT=30ms，L=1000B → 利用率仅约 0.027%，极度浪费。

流水线协议

允许发送方连续发送多个分组而无需等待，利用率提升为：

Usender=N⋅L/RL/R+RTTU_{sender} = N \cdot \frac{L/R}{L/R + RTT}Usender​=N⋅L/R+RTTL/R​

两种流水线协议：

GBN（回退 N 步，Go-Back-N）

基本思想：

  • 发送方可连续发送窗口内的多个分组
  • 接收方按序接收，出错时从出错分组开始全部丢弃，不发 ACK
  • 发送方超时后从出错分组重传后续所有分组

发送窗口：

范围 含义
[0, base-1] 已发送并已确认
[base, nextseqnum-1] 已发送但未确认
[nextseqnum, base+N-1] 即将发送
[base+N, ∞] 暂不可用
  • 接收窗口大小 WR=1W_R = 1WR​=1（只按序接收）
  • 序号位数 kkk 位，最大发送窗口 WT=2k−1W_T = 2^k - 1WT​=2k−1
  • 使用累积确认：ACK(n) 表示 n 及 n 之前所有分组均已收到
  • 只用一个定时器，超时重传所有未确认分组

SR（选择性重传，Selective Repeat）

基本思想：

  • 只重传出错的那个分组（不重传后续分组）
  • 接收方不按序接收，将失序分组缓存，待出错分组补齐后统一交付

发送/接收窗口：

  • 序号位数 kkk 位，发送窗口和接收窗口最大均为 2k−12^{k-1}2k−1（序号空间的一半）

接收方动作：

  • 序号在接收窗口内的分组：缓存，回发 ACK；若序号等于接收基序号，则将连续已缓存的分组一起交付，滑动窗口
  • 序号在接收基序号之前的分组：重发 ACK（防止发送方窗口无法前移）

三种协议比较

协议 发送方 接收方 发送窗口 WTW_TWT​ 接收窗口 WRW_RWR​
停等 发 1 个，重发出错分组 按序接收，丢弃出错/重复 1 1
GBN 连发 N 个，从出错处全重发 按序接收，从出错处全丢 ≤2k−1\leq 2^k - 1≤2k−1 1
SR 连发 N 个，只重发出错分组 不按序，只丢出错分组 ≤2k−1\leq 2^{k-1}≤2k−1 ≤2k−1\leq 2^{k-1}≤2k−1

可靠传输机制总结

机制 作用
校验和 检测比特差错
定时器/超时重传 检测丢包和 ACK 丢失
序号 区分新分组与重传分组，检测丢失/重复
确认（ACK） 告知发送方哪些分组已正确接收
否认（NAK） 告知发送方哪些分组出错（可用冗余 ACK 代替）
窗口/流水线 提高信道利用率

拥塞控制原理

拥塞：发送方发送速率过快，超过网络处理能力 → 路由器缓冲区溢出（丢包）和长排队时延。

拥塞控制 ≠ 流量控制：前者针对网络全局，后者针对发送方与接收方之间的速率匹配。

拥塞的代价

  • Case 1（无限缓存路由器）：吞吐量最大只有 R/2R/2R/2，但排队时延随发送速率增大而剧增
  • Case 2（有限缓存，重传）：最大吞吐量降至 R/3R/3R/3（重传消耗带宽）
  • Case 3（超时重传 + 重复分组）：最大吞吐量降至 R/4R/4R/4

拥塞控制方法

方法 原理
端到端拥塞控制 端系统通过丢包、时延观察推断拥塞（TCP 采用此方式）
网络辅助拥塞控制 路由器直接向发送方反馈拥塞信息（如 ATM ABR）

ATM ABR 拥塞控制

ATM（异步传输模式）：基于虚电路（VC）的快速分组交换，每台交换机维护 VC 状态。

ABR（可用比特率）：弹性服务，轻载时充分利用空闲带宽，拥塞时降至最低速率。

RM（资源管理）信元：散布在数据信元中，用于传递拥塞信息。

拥塞通知字段：

  • EFCI 比特：交换机设为 1 告知目的端拥塞；目的端将 RM 信元中的 CI 位置 1 回送发送方
  • CI（拥塞指示）：严重拥塞时置 1
  • NI（无增长）：轻度拥塞时置 1
  • ER（显式速率）：路径上最小支持速率，拥塞交换机降低 ER 值，发送方据此调整速率

面向连接的传输：TCP

TCP 采用：差错检测、重传、累积确认、定时器、序号和确认号。

TCP 连接管理

三次握手（建立连接）

  1. 客户端 → SYN 报文段：SYN=1，序号=client_isn（随机选择）
  2. 服务器 → SYNACK 报文段：SYN=1，确认号=client_isn+1，序号=server_isn；分配缓存和变量
  3. 客户端 → 第三个报文段：SYN=0，确认号=server_isn+1；可携带应用层数据；分配缓存和变量

四次挥手（释放连接）

  1. 客户端发送 FIN=1 报文段
  2. 服务器回复 ACK
  3. 服务器发送 FIN=1 报文段
  4. 客户端回复 ACK

TCP 报文段结构

字段 大小 说明
源端口 / 目的端口 各 16 bits 多路复用/分解
序号 32 bits 该报文段首字节的字节流编号
确认号 32 bits 期望收到的下一个字节的编号
接收窗口 16 bits 流量控制：接收方愿意接受的字节数
首部长度 4 bits TCP 首部长度（×4 字节，典型值 20B）
标志字段 6 bits ACK/SYN/FIN/RST/CWR/ECE/PSH/URG
检验和 16 bits 差错检测

序号：基于字节流，而非报文段。例如 500,000 字节文件（MSS=1000B）：第 1 个报文段序号 0，第 2 个 1000，以此类推。

确认号：期望收到的下一字节序号，使用累积确认（只确认第一个丢失字节之前的数据）。

往返时间估计与超时

EstimatedRTT（指数加权移动平均）：

EstimatedRTT=(1−α)⋅EstimatedRTT+α⋅SampleRTT(α=1/8)\text{EstimatedRTT} = (1-\alpha) \cdot \text{EstimatedRTT} + \alpha \cdot \text{SampleRTT} \quad (\alpha = 1/8)EstimatedRTT=(1−α)⋅EstimatedRTT+α⋅SampleRTT(α=1/8)

DevRTT（RTT 偏差，反映波动程度）：

DevRTT=(1−β)⋅DevRTT+β⋅∣SampleRTT−EstimatedRTT∣(β=1/4)\text{DevRTT} = (1-\beta) \cdot \text{DevRTT} + \beta \cdot |\text{SampleRTT} - \text{EstimatedRTT}| \quad (\beta = 1/4)DevRTT=(1−β)⋅DevRTT+β⋅∣SampleRTT−EstimatedRTT∣(β=1/4)

超时间隔：

TimeoutInterval=EstimatedRTT+4⋅DevRTT\text{TimeoutInterval} = \text{EstimatedRTT} + 4 \cdot \text{DevRTT}TimeoutInterval=EstimatedRTT+4⋅DevRTT

TCP 可靠数据传输

TCP 在不可靠的 IP 层上实现可靠传输，保证数据无损坏、无间隙、非冗余、按序。

使用单一重传定时器（绑定最早未确认报文段）：

  • 收到上层数据 → 封装报文段，若定时器未运行则启动
  • 定时器超时 → 重传引起超时的报文段，重启定时器
  • 收到 ACK(y) → 若 y > SendBase，更新 SendBase；若仍有未确认报文段，重启定时器

超时间隔加倍

超时后，下次超时间隔加倍（指数增长），避免网络已拥塞时持续重传加剧拥塞。

快速重传

收到**3 个冗余 ACK（duplicate ACK）**时，在定时器过期前立即重传丢失报文段。

收到冗余 ACK 说明：该 ACK 编号之后的报文段已到达接收方，但中间有报文段丢失。

差错恢复机制

TCP 是 GBN 和 SR 的混合体：

  • 使用选择确认（selective acknowledgment），接收方有选择地确认失序报文段
  • 跳过已被接收方选择性确认的报文段，只重传真正丢失的

流量控制

TCP 接收方在首部**接收窗口（rwnd）**字段通告剩余缓存空间，发送方不超过 rwnd 发送，防止接收方缓存溢出。

面试追问：端口与请求回包

端口由哪层提供

端口是传输层（TCP/UDP）用来把 IP 主机上的报文交付给正确进程的逻辑编号；IP 负责定位主机，端口定位主机内的套接字/应用。严格说，端口号位于 TCP/UDP 首部，由操作系统网络栈维护。

同一路由器的多台电脑如何收到各自回包

路由器做 NAT 时为每条出站连接维护映射，例如 192.168.1.10:52341 → 公网IP:40001。服务器回包目标是公网 IP 和临时端口；NAT 依表项改写为内网源 IP、源端口，随后二层用 MAC/ARP 交付给正确主机。即使访问同一服务器，也由四元组（源 IP、源端口、目的 IP、目的端口）区分连接。

TCP 拥塞控制

TCP 使用端到端拥塞控制，通过丢包/冗余 ACK 推断拥塞，动态调整发送速率（拥塞窗口 cwnd）。
