链路层和局域网

2024-12-14

#八股#计算机网络

阅读线索

链路层负责相邻节点间的帧传输，共享介质还需要决定谁能发送。差错检测、多路访问、MAC 寻址与交换共同组成局域网数据传递过程。

概述

两类链路层信道

类型 描述 典型场景
广播信道（broadcast channel） 多台主机连接到同一信道，需要**媒体访问协议（MAC）**协调传输 有线局域网、WiFi、HFC 接入网
点对点链路（point-to-point link） 链路两端各一个节点，无需竞争 路由器间长距离链路、主机到以太网交换机

节点（node）：运行链路层协议的任何设备，包括主机、路由器、交换机和 WiFi 接入点。

链路（link）：连接相邻节点的通信信道。数据报从源到目的，要经过多段链路逐跳传输——每段链路可能是不同类型（WiFi、以太网等）。

链路层提供的服务

服务 说明
成帧（framing） 将网络层数据报封装为链路层帧（frame），附加首部和尾部字段
链路接入（link access） MAC 协议规定帧在链路上的传输规则，协调多节点竞争
可靠交付（reliable delivery） 通过确认和重传保证帧无差错通过链路（常用于高差错率的无线链路；有线链路通常不提供，因为开销不必要）
差错检测与纠正 接收方检测（并可能纠正）比特翻转差错

链路层在哪里实现

链路层的主体在网络适配器（网卡，NIC）中实现，其核心是链路层控制器芯片（硬件实现）。

  • 发送端：控制器从内存取出数据报 → 封装成帧 → 遵循链路接入协议发送到链路
  • 接收端：控制器接收帧 → 提取数据报 → 若开启差错检测则执行校验 → 传递给网络层

链路层是协议栈中硬件与软件的交接处：底层由硬件实现，高层功能（如寻址信息组装、中断处理）由运行在 CPU 上的驱动程序实现。

差错检测和纠正技术

发送方在数据 DDD 后附上差错检测和纠正比特（EDC），接收方收到 D′D'D′ 和 EDC′EDC'EDC′ 后，判断 D′D'D′ 是否等于原始 DDD。

注意：任何差错检测方案都可能存在未检出差错，需要在开销和可靠性之间权衡。

三种技术，复杂度和可靠性依次递增：

技术 典型应用层次
奇偶校验 概念演示
检验和（Checksum） 传输层（因特网检验和）
循环冗余检测（CRC） 链路层（网卡硬件）

奇偶校验（Parity Check）

一维奇偶校验

  • 偶校验：添加 1 个校验位，使得 d+1d+1d+1 位中 1 的个数为偶数
  • 奇校验：使得 1 的个数为奇数

接收方计数收到的 1 的个数，与预期奇偶性不符即检测出差错。

局限：只能检测奇数个比特差错；若出现偶数个差错，则无法检出。突发差错场景下，漏检率高达 50%。

二维奇偶校验（前向纠错）

将 ddd 个比特排列为 iii 行 jjj 列的矩阵，对每行每列分别计算奇偶位，共产生 i+j+1i+j+1i+j+1 个校验位。

优点：

  • 能检测单比特差错，还能定位出错的行和列 → 直接纠正该比特（无需重传）
  • 这种能力称为前向纠错（Forward Error Correction，FEC）

检验和方法（Checksum）

将数据视为若干 kkk 位整数序列，求和后取反码作为校验字段（因特网检验和：以 16 位字为单位求和）。

接收方对收到的所有数据（含检验和）求和，若结果为全 1 则无差错。

特点：计算简单，软件实现；检测能力比 CRC 弱，主要用于传输层和网络层。

循环冗余检测（CRC）

CRC 又称多项式编码（polynomial code），是链路层硬件中使用最广泛的差错检测技术。

核心思想：

  1. 发送方和接收方约定一个 r+1r+1r+1 位的生成多项式 GGG（最高位为 1）
  2. 发送方在数据 DDD（ddd 位）后面附加 rrr 位的 CRC 码 RRR，使得 D⋅2r⊕RD \cdot 2^r \oplus RD⋅2r⊕R 能被 GGG 整除（模 2 算术）
  3. 接收方用 GGG 除收到的 d+rd+rd+r 位，余数为 0 则无差错

模 2 算术规则：加法和减法都等价于按位异或（XOR），不进位不借位。

CRC 计算示例

已知：原始数据 D=1101011011D = 1101011011D=1101011011，生成多项式 G=10011G = 10011G=10011（5 位，r=4r=4r=4）

步骤：

  1. 在 DDD 后补 4 个 0：1101011011 00001101011011\ 00001101011011 0000
  2. 用模 2 除法除以 GGG，得余数 R=1110R = 1110R=1110
  3. 实际发送：1101011011 11101101011011\ 11101101011011 1110

校验：接收方用 100111001110011 除 1101011011 11101101011011\ 11101101011011 1110，余数为 0 → 无差错。

CRC 检测能力（rrr 位生成多项式）：

  • 检测所有 ≤r\leq r≤r 位的突发差错
  • 以概率 1−0.5r1 - 0.5^r1−0.5r 检测长于 r+1r+1r+1 位的突发差错
  • 检测所有奇数个比特差错

实践中，CRC-32（32 位生成多项式）被多种以太网 IEEE 协议采用。

多路访问链路和协议

多路访问问题（multiple access problem）：多个节点共享同一广播信道时，如何协调传输，避免碰撞？

碰撞（collision）：两个或多个节点同时传输，信号叠加，所有接收方均无法正确解读。

理想的多路访问协议（信道速率 RRR bps）应满足：

  1. 只有一个节点活跃时，它的吞吐量为 RRR
  2. MMM 个节点活跃时，每个节点平均吞吐量为 R/MR/MR/M
  3. 完全分散，无单点故障
  4. 实现简单

三类协议：

类型 原理 代表
信道划分协议 预先分配时间/频率/编码 TDM、FDM、CDMA
随机接入协议 碰撞后随机等待重传 ALOHA、CSMA、CSMA/CD
轮流协议 有序传递发送权 轮询、令牌传递

信道划分协议

TDM（时分多路复用）

将时间划分为固定时间帧，每帧再分为 NNN 个时隙，每个节点固定占用一个时隙。

  • 优点：无碰撞，每个节点公平地获得 R/NR/NR/N 的速率
  • 缺点：节点有数据要发时，最坏情况要等待 N−1N-1N−1 个时隙；信道空闲时不能被其他节点利用

FDM（频分多路复用）

将 RRR bps 信道划分为 NNN 个 R/NR/NR/N bps 的频段，每个节点分配一个频段。优缺点与 TDM 相同。

CDMA（码分多址）

每个节点分配唯一的编码（码片序列），所有节点可同时在同一信道传输，接收方用对应编码解出发送方的数据。前提：各节点的编码需精心设计（正交），以避免相互干扰。

随机接入协议

随机接入协议：节点总以信道全速率 RRR 发送，碰撞后等待随机时延再重传。

比喻：就像多人在一个会议室抢着发言——谁先开口就说，冲突了就都停下来，等一段随机时间后再试。

时隙 ALOHA（Slotted ALOHA）

假设：所有帧等长 LLL 位，时间划分为 L/RL/RL/R 秒的时隙，节点只在时隙起点开始传输，且节点同步。

规则：有帧要发 → 在下一时隙发送；碰撞 → 以概率 ppp 在后续每个时隙重传，直到成功。

效率分析（NNN 个节点，每个以概率 ppp 传输）：

效率=Np(1−p)N−1\text{效率} = Np(1-p)^{N-1}效率=Np(1−p)N−1

当 N→∞N \to \inftyN→∞ 时，最大效率为 1e≈37%\dfrac{1}{e} \approx 37%e1​≈37%。

即最多只有 37% 的时隙在做有用的工作，其余时隙要么碰撞，要么空闲。

纯 ALOHA（Pure ALOHA）

无时隙同步，帧一到达就立刻发送，碰撞后以概率 ppp 立刻重传。

由于发送时刻不同步，一帧可能与前一帧的末尾或后一帧的开头相互干扰，碰撞概率更高：

最大效率=12e≈18.4%\text{最大效率} = \frac{1}{2e} \approx 18.4\%最大效率=2e1​≈18.4%

刚好是时隙 ALOHA 的一半。

CSMA（载波侦听多路访问）

载波侦听（carrier sensing）：发送前先“听”信道，若信道忙则等待，空闲再发。

比喻：就像礼貌交谈——先听别人说完，再开口。

为什么还会碰撞？ 信号传播有时延（传播时延），节点 A 开始发送后，信号还没到达节点 D 时，D 侦听到信道空闲，也开始发送 → 碰撞。传播时延越大，碰撞概率越高。

CSMA/CD（带碰撞检测的 CSMA）

在 CSMA 基础上增加碰撞检测（collision detection）：

  • 发送时持续监听信道
  • 一旦检测到碰撞（同时收到其他信号），立即中止发送，不再浪费信道

CSMA/CD 运行步骤：

  1. 从网络层获取数据报，封装成帧放入缓存
  2. 侦听信道空闲 → 开始发送；信道忙 → 等待
  3. 发送过程中持续监听，检测碰撞
  4. 若无碰撞，完成发送
  5. 若检测到碰撞，中止传输，等待随机时间后回到步骤 2

二进制指数退避（binary exponential backoff）：

经历 nnn 次碰撞后，从 {0,1,…,2n−1}{0, 1, \ldots, 2^n - 1}{0,1,…,2n−1} 中随机选一个整数 KKK，等待 K×512K \times 512K×512 比特时间（以太网），nnn 最大取到 10。碰撞越多，等待范围越大——避免节点持续同时重传。

CSMA/CD 效率（dpropd_{\text{prop}}dprop​：最大传播时延，dtransd_{\text{trans}}dtrans​：最大帧传输时延）：

效率=11+5dprop/dtrans\text{效率} = \frac{1}{1 + 5d_{\text{prop}}/d_{\text{trans}}}效率=1+5dprop​/dtrans​1​

传播时延趋近 0 或帧传输时间很大时，效率趋近 1。

轮流协议（Taking-Turns Protocol）

ALOHA/CSMA 能满足“单节点活跃时吞吐量为 RRR”，但多节点时效率低。轮流协议两个条件都能满足：

轮询协议（Polling Protocol）

主节点依次轮询每个从节点，告知它能发送多少帧。从节点发完后，主节点轮询下一个。

  • 优点：无碰撞，高效
  • 缺点：主节点故障 → 整个网络瘫痪；轮询本身引入时延

令牌传递协议（Token-Passing Protocol）

一个特殊的令牌帧在节点间按固定顺序传递（如 1→2→3→…→N→1）。

  • 节点收到令牌 → 有帧要发：发送最多允许数目的帧，再传递令牌；没有帧：直接传递令牌
  • 优点：分散化，高效
  • 缺点：一个节点故障或令牌丢失可能导致网络崩溃，需要恢复机制

交换局域网

链路层寻址和 ARP

MAC 地址

MAC 地址（又称 LAN 地址、物理地址）是网络适配器（网卡）的地址，不是主机或路由器的地址。

特点 说明
长度 6 字节（48 位），共 2482^{48}248 个可能地址
表示 十六进制，如 1A-2F-BB-76-09-AD
结构 扁平结构，全球唯一，不随移动地点而改变
分配 IEEE 统一管理：前 24 位由 IEEE 分配给厂商，后 24 位由厂商自行分配
广播地址 FF-FF-FF-FF-FF-FF（48 个全 1），发送给局域网所有设备

对比：IP 地址是层次结构（网络部分 + 主机部分），主机移动时 IP 地址需要改变；而 MAC 地址是扁平的，就像人的身份证号，去哪里都不变。

链路层交换机没有 MAC 地址，因为它透明地转发帧，主机无需知道交换机的存在。

ARP（地址解析协议）

问题：主机知道目的 IP 地址，但要在链路层发帧，需要目的 MAC 地址 → ARP 负责这个翻译。

ARP 之于链路层，就像 DNS 之于应用层：一个解析 IP→MAC，一个解析域名→IP。区别在于：ARP 只能解析同一子网内的地址。

ARP 表：每台主机/路由器内存中维护一张 IP→MAC 的映射表，每条表项有 TTL（通常 20 分钟），过期自动删除。

ARP 查询流程（主机 A 要向 IP 为 xxx 的主机 B 发帧，但 ARP 表中没有 xxx 的记录）：

  1. A 构造 ARP 查询分组（含自己的 IP/MAC，目的 IP = xxx，目的 MAC = 广播地址）
  2. A 用广播地址 FF-FF-FF-FF-FF-FF 封装为帧，发送到局域网
  3. 子网内所有设备收到并解析 ARP 分组，匹配 IP = xxx 的主机 B 发送 ARP 响应（单播，含自己的 MAC）
  4. A 收到响应，更新 ARP 表，然后正式发送数据帧

特点：ARP 是即插即用的，表自动建立，无需手动配置。

发送数据报到子网之外

当目的主机与发送方不在同一子网时（需要路由器转发）：

  1. 发送方查询路由表，找到第一跳路由器接口的 IP 地址（如 111.111.111.110）
  2. 用 ARP 解析该路由器接口的 MAC 地址
  3. 将帧的目的 MAC 设为路由器接口的 MAC，IP 目的地址仍为最终目的主机的 IP
  4. 路由器收到帧 → 解析 IP 目的地址 → 查转发表 → 向下一跳发出（此时目的 MAC 改为下一跳的 MAC）
  5. 重复直到到达目的子网，最后一跳路由器用 ARP 获取目的主机 MAC，直接投递

每过一跳，链路层帧的 MAC 地址（源/目的）都在变化，但 IP 数据报中的 IP 地址始终不变。

以太网（Ethernet）

以太网是目前最主流的有线局域网技术，经历了从总线拓扑 → 集线器星形 → 交换机星形的演进。

集线器（hub）：物理层设备，把收到的比特放大并转发到所有接口 → 共享介质，所有节点在同一碰撞域。

交换机（switch）：取代集线器，每个接口独立，无碰撞，性能大幅提升（详见下节）。

以太网帧结构

| 前同步码(8B) | 目的MAC(6B) | 源MAC(6B) | 类型(2B) | 数据(46~1500B) | CRC(4B) |
字段 大小 说明
前同步码（Preamble） 8 字节 前 7 字节为 10101010，用于唤醒接收方并同步时钟；第 8 字节为 10101011，标志帧内容开始
目的 MAC 地址 6 字节 目的适配器 MAC，或广播地址
源 MAC 地址 6 字节 发送适配器 MAC
类型字段 2 字节 上层协议标识（IP=0x0800，ARP=0x0806），用于多路分解
数据字段 46～1500 字节 IP 数据报（MTU=1500B）；最小 46 字节，不足需填充（padding）
CRC 4 字节 循环冗余校验，接收方检测差错，出错则丢弃

以太网服务特性：

  • 无连接：发送前不握手，直接发帧
  • 不可靠：不发 ACK，出错直接丢弃，依赖上层（TCP）负责端到端可靠性

以太网标准命名规则示例：100BASE-T → 100Mbps、基带传输、双绞铜线（T = twisted pair）。

链路层交换机

交换机对主机/路由器透明：它们只知道目的地址，不知道中间经过了哪台交换机。

转发与过滤

交换机依靠**交换机表（switch table）**工作，表项包含：MAC 地址、对应接口、放入时间。

收到目的 MAC 为 DD-DD-DD-DD-DD-DD 的帧时：

情况 动作
表中无该 MAC 广播：转发到除入接口外的所有接口
表中该 MAC 对应入接口本身 过滤：丢弃（目的已在同一网段）
表中该 MAC 对应另一接口 yyy 转发：发往接口 yyy

自学习（Self-Learning）

交换机表由交换机自动建立，无需手动配置：

  1. 初始时交换机表为空
  2. 每收到一帧，将源 MAC 地址和入接口记入表，并打上时间戳
  3. 超过**老化期（aging time）**未收到来自某 MAC 的帧，则删除该表项

这就像餐厅服务员记住常客的座位一样——每次看到他从某个门进来，就记下他在那个位置；如果很久没来，就忘掉了。交换机也是如此，零配置、即插即用。

交换机 vs 路由器

对比维度 链路层交换机 路由器
工作层次 第 2 层（链路层，MAC 地址） 第 3 层（网络层，IP 地址）
即插即用 是 否（需配置 IP 地址）
拓扑限制 受**生成树（STP）**限制，防广播环路 无生成树限制，支持冗余路径
广播风暴 无保护，广播帧无限转发 路由器隔离广播域，提供保护
ARP 开销 大型网络中 ARP 表庞大，开销大 每个子网独立，ARP 开销小
适用规模 小型网络（数百台主机） 大型网络（数千台主机）

虚拟局域网（VLAN）

问题：传统交换机局域网中，广播流量（ARP、DHCP 等）会扩散到所有主机，且不同部门间难以隔离流量或灵活管理用户移动。

解决方案：VLAN（Virtual Local Area Network）

  • 在一台物理交换机上划分多个逻辑局域网（虚拟局域网）
  • 不同 VLAN 间流量相互隔离（就像连接到不同的物理交换机）
  • VLAN 内广播只在本 VLAN 扩散，不跨越 VLAN 边界

基于端口的 VLAN

网络管理员将交换机接口划分到不同 VLAN 组：

  • 接口 2～8：EE（电气工程系）VLAN
  • 接口 9～15：CS（计算机科学系）VLAN

EE VLAN 的帧只在接口 2～8 中转发，CS 的帧只在接口 9～15 中转发，互不干扰。

VLAN 间通信：需要经过路由器，将一个接口配置为同属两个 VLAN，流量先跨越 VLAN→路由器→另一 VLAN。

VLAN 干线连接（VLAN Trunking）

多台 VLAN 交换机互联时，用**干线端口（trunk port）**代替每个 VLAN 单独一条链路，实现扩展性：

  • 干线端口属于所有 VLAN，所有 VLAN 的帧都通过干线链路传输
  • 为了让接收方识别帧属于哪个 VLAN，使用 802.1Q 标准在帧中加入 VLAN 标签

802.1Q 帧格式（在标准以太网帧首部加入 4 字节 VLAN 标签）：

| 目的MAC(6B) | 源MAC(6B) | TPID(2B=0x8100) | 优先级(3bit)+VLAN ID(12bit) | 类型(2B) | 数据 | CRC |
字段 说明
TPID 2 字节，固定值 0x8100，标识这是 802.1Q 帧
优先级 3 位，类似 IP 数据报的 TOS，用于 QoS
VLAN ID 12 位，标识帧所属的 VLAN（最多 4094 个 VLAN）

VLAN 标签在发送侧交换机加入，在接收侧交换机解析后删除，对端节点透明。
