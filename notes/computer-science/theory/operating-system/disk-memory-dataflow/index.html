硬盘与内存之间的数据流动

2026-08-26

阅读线索

磁盘与内存之间的数据流要同时看硬件搬运和操作系统缓存。读路径先查页缓存，写路径可能先形成脏页；完成系统调用与真正持久化是不同阶段。

硬件层：数据是怎么物理传输的

存储介质读取原理

HDD（机械硬盘）

  • 磁头悬浮在旋转盘片上方，通过电磁感应读取磁性信号
  • 寻道（seek）= 磁头移到目标磁道，延迟约 5–10ms
  • 旋转等待（rotational latency）= 等扇区转到磁头下方，平均约 4ms
  • 数据以 512B 或 4KB 扇区 为最小单位读取

SSD（固态硬盘）

  • NAND Flash 存储，无机械运动
  • 内部有 FTL（Flash Translation Layer） 做逻辑地址到物理页的映射
  • 最小读写单位：页（Page）= 4KB~16KB，擦除单位：块（Block）= 128~512 页

数据传输通道

存储介质
   │
   ▼
存储控制器（SSD主控 / HDD控制芯片）
   │  接口协议：NVMe（PCIe）/ SATA / SAS
   ▼
主机总线适配器 / PCIe控制器
   │
   ▼
CPU南桥 / PCH（Platform Controller Hub）
   │  系统总线
   ▼
内存控制器（集成在CPU内）
   │
   ▼
DRAM（内存）

DMA（Direct Memory Access）是关键：

  • 磁盘控制器通过 DMA 直接将数据写入内存，CPU 不参与数据搬运本身
  • CPU 只负责下达命令（写 I/O 寄存器）和处理完成中断
  • 数据路径：磁盘 → DMA 控制器 → 内存总线 → DRAM

I/O 完成通知

方式 原理 场景
轮询（Polling） CPU 反复查询状态寄存器 NVMe 高性能场景（io_uring）
中断（IRQ） 设备完成后发硬件中断 传统 HDD/SATA
MSI-X PCIe 消息中断，支持多队列 NVMe SSD

操作系统层：软件如何管理

页缓存（Page Cache）

Linux 内核在内存中维护一个 Page Cache，所有文件 I/O 默认经过它：

用户进程 read(fd)
      │
      ▼
  VFS（虚拟文件系统）
      │
      ▼
  Page Cache 命中？
   ├── 是 → 直接 memcpy 到用户空间（零磁盘 I/O）
   └── 否 → 触发缺页 / 预读，从磁盘加载到 Page Cache，再返回

Page Cache 的本质：

  • 每个文件的内容被拆成 4KB 页 缓存在内存
  • 用 基数树（radix tree）/ XArray 以文件偏移为索引组织
  • 读命中率极高时，大量 I/O 其实只是内存操作

读流程（磁盘 → 内存）

① 进程调用 read(fd, buf, n)
② 系统调用进入内核，VFS 查 Page Cache
③ 未命中 → 分配物理页，构造 bio（块 I/O 请求）
④ bio 送入 I/O 调度器队列
⑤ I/O 调度器合并/排序请求，发给块设备驱动
⑥ 驱动向磁盘控制器写命令寄存器
⑦ 磁盘控制器 DMA 把数据写入步骤③分配的物理页
⑧ 磁盘发中断通知 CPU 完成
⑨ 中断处理：唤醒阻塞的进程
⑩ 内核从 Page Cache 页 memcpy 到用户缓冲区

写流程（内存 → 磁盘）

写有两种模式：

写回（Write-back，默认）

write(fd) → 修改 Page Cache 中的页，标记为 dirty
                        │
                        （稍后异步刷盘）
                        ▼
              pdflush / writeback 线程
                        │
              满足条件时下刷到磁盘

写穿（Write-through / O_SYNC）

write(fd) → 修改 Page Cache → 立即同步写磁盘 → 返回

dirty 页的刷盘触发条件（Linux 内核）：

条件 参数 默认值
dirty 数据超过内存比例 dirty_background_ratio 10%
dirty 数据绝对量 dirty_background_bytes —
强制刷盘阈值（触发阻塞） dirty_ratio 20%
页面“脏龄”超时 dirty_expire_centisecs 3000（30s）
定期唤醒 writeback dirty_writeback_centisecs 500（5s）

writeback 的优先级逻辑：

  1. 最老的 dirty 页优先（按 dirtied 时间戳排序）
  2. 超过 dirty_ratio 时，发起 write 的进程本身会被阻塞来做 writeback（back-pressure）
  3. 内存压力大时，kswapd 会触发更激进的回收，也包括刷 dirty 页

I/O 调度器：请求怎么排序

内核在把 bio 发给驱动前会经过 I/O 调度器：

调度器 策略 适用场景
None 直接 FIFO NVMe SSD（本身并发，无需调度）
mq-deadline 按截止时间调度，防饥饿 SATA SSD、通用
BFQ 按进程分配带宽，类 CFQ 桌面、交互场景
Kyber 低延迟优先 高性能 SSD

HDD 时代的 CFQ/Elevator 算法（电梯调度）会把随机请求排序成顺序访问，大幅减少寻道时间——SSD 无机械结构，随机访问无差别，所以现代 SSD 用 None 或 mq-deadline。

内存回收：Page Cache 怎么被驱逐

内存不足时，内核用 LRU 双链表（active list + inactive list）管理页面：

新读入的页 → inactive list
多次访问后 → 提升到 active list
内存紧张时 → 从 inactive list 尾部驱逐

dirty 页被驱逐前必须先刷盘（writeback）
clean 页可直接丢弃（反正磁盘上有）
  • kswapd：后台内核线程，周期性扫描 LRU，提前回收，避免同步等待
  • OOM Killer：实在没内存时，按启发式算法杀进程

完整路径

用户进程
  │  系统调用（read/write/mmap）
  ▼
VFS（统一文件接口）
  │
  ▼
Page Cache（4KB页，基数树索引）
  │   命中 → 直接返回/修改（纯内存操作）
  │   未命中 / dirty刷盘
  ▼
块设备层（bio 构造）
  │
  ▼
I/O 调度器（合并、排序、限流）
  │
  ▼
块设备驱动（NVMe / SATA / SCSI）
  │   写命令寄存器，触发 DMA
  ▼
DMA 控制器 ←──────────────────┐
  │                           │
  │   数据直接在内存↔设备间流动  │
  ▼                           │
存储控制器（SSD主控 / HDD控制器）
  │
  ▼
物理存储介质（NAND Flash / 磁盘）

完成后 → 硬件中断 → 唤醒等待进程

关键优先级总结

优先级 处理逻辑
读请求 先查 Page Cache，命中则不碰磁盘
写请求 写 Page Cache（dirty），异步刷盘
内存回收 clean 页直接丢 > dirty 页先刷再丢
I/O 调度 SSD 直接下发；HDD 按截止时间/带宽公平调度
back-pressure dirty 超阈值时，写进程自己承担刷盘代价

核心设计思想：读靠缓存命中减少磁盘 I/O，写靠延迟合并批量下刷，DMA 让 CPU 从数据搬运中解放出来。
