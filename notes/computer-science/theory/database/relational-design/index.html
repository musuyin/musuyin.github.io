关系型数据库设计

2025-12-29

#数据库#数据库设计

阅读线索

关系设计以函数依赖表达数据约束，通过闭包识别码，再用范式与分解处理冗余。无损连接与依赖保持是两个不同目标，需要分别验证。

设计规范

有损分解

有损分解（lossy decomposition）不能保证用投影结果的自然连接精确恢复原关系。问题不一定表现为丢掉元组，也可能产生原本不存在的伪元组。

将 employee(ID, name, street, city, salary)分解为 employee_attr1(ID, name)和 employee_attr2(name, street, city, salary)

name 无法作为 employee_attr2 关系的主码，有可能会重名

无损分解

无损分解（lossless decomposition）要求将原关系投影到各子模式后，自然连接的结果恰好等于原关系：既不遗漏，也不增加元组。

r=∏A,B(r)⋈∏B,C(r)r=\prod_{A,B}(r)\bowtie \prod_{B,C}(r)r=A,B∏​(r)⋈B,C∏​(r)

函数依赖

成立条件

假设 r(R)r(R)r(R) 是一个关系模式，α⊆R,β⊆R\alpha\subseteq R,\beta\subseteq Rα⊆R,β⊆R，模式 RRR 上的函数依赖：

α→β\alpha \rightarrow \betaα→β

成立条件为：对于任意关系实例 rrr 中任意两个元组 t1t_1t1​ 和 t2t_2t2​，若两者的属性（集）α\alphaα 取值相同，那么它们的属性（集）β\betaβ 取值也相同，即：

t1[α]=t2[α]⇒t1[β]=t2[β]t_1[\alpha]=t_2[\alpha] \Rightarrow t_1[\beta]=t_2[\beta]t1​[α]=t2​[α]⇒t1​[β]=t2​[β]

称为 α\alphaα 函数确定 β\betaβ；β\betaβ 函数依赖于 α\alphaα

函数依赖和码

超码

在某个关系中，一个或多个元素的集合 {A1,A2,…,An}{A_1,A_2,\dots,A_n}{A1​,A2​,…,An​} 函数决定该关系中的其他全部属性，则称该属性为该关系的超码

若属性组 KKK 满足 K⇒RK\Rightarrow RK⇒R，则 KKK 是关系模式 RRR 的超码（KKK 函数确定 RRR）

候选码

若集合 {A1,A2,…,An}{A_1,A_2,\dots,A_n}{A1​,A2​,…,An​} 的任何真子集均不能函数决定该关系中的其他属性，则此时集合 {A1,A2,…,An}{A_1,A_2,\dots,A_n}{A1​,A2​,…,An​} 是最小的超码，即候选码

K→R 且不存在 α⊂K 满足 α→RK\rightarrow R\: \text{且不存在}\: \alpha\subset K\: \text{满足}\: \alpha \rightarrow RK→R且不存在α⊂K满足α→R

外码

若关系模式 RRR 中属性（组）XXX 是另一类关系模式的主码，则称 XXX 是 RRR 的外码

函数依赖是码的概化

概念 决定什么？ 形式
码（Key） 一个属性集  唯一确定整条记录 K→RK\rightarrow RK→R
函数依赖（FD） 一个属性集  唯一确定另一属性集 X→Y,其中Y⊆RX\rightarrow Y,\text{其中} Y\subseteq RX→Y,其中Y⊆R

函数依赖使用

函数依赖在关系实例和关系模式上的体现区别：

  • 如果关系实例 rrr 在函数依赖集 FFF 上合法，则称 rrr 满足 FFF
  • 如果模式 RRR 上的所有合法关系实例都满足函数依赖集 FFF，则 FFF 在关系模式 RRR 上成立

注意：即使函数依赖并没有对关系模式 r(R)r(R)r(R) 的所有合法实例成立，这个关系模式的其中一个具体实例 r 可能满足函数依赖

平凡

有些函数依赖被称为平凡(trivial)的，因为它们在所有关系中都是满足的（用于描述在函数依赖中一种必然成立、无需额外信息即可判断为真的情况）

例如：name -> name；ID, name -> ID

通常，如果 β⊆α\beta \subseteq \alphaβ⊆α，那么 α→β\alpha \rightarrow \betaα→β 是平凡的函数依赖

  • 若 α→β\alpha \rightarrow \betaα→β，则称 α\alphaα 为决定因素
  • 若 α→β\alpha \rightarrow \betaα→β 但 β⊈α\beta \not\subseteq \alphaβ⊆α，则 α→β\alpha \rightarrow \betaα→β 是非平凡的函数依赖

部分依赖：函数依赖 α→β\alpha \rightarrow \betaα→β 称为部分依赖的条件是：存在 α\alphaα 的真子集 γ\gammaγ，使得 γ→β\gamma \rightarrow \betaγ→β

  • 平凡的例子：

    • {A,B}→A{A, B} \rightarrow A{A,B}→A：因为 A⊆{A,B}A \subseteq {A, B}A⊆{A,B}，所以这是平凡的。
    • {A,B,C}→{B,C}{A, B, C} \rightarrow {B, C}{A,B,C}→{B,C}：右边是左边的子集，平凡。
    • A→AA \rightarrow AA→A：最简单的平凡依赖。

  • 非平凡的例子：

    • {A,B}→C{A, B} \rightarrow C{A,B}→C：如果 C∉{A,B}C \notin {A, B}C∈/{A,B}，这就是非平凡的函数依赖。
    • A→BA \rightarrow BA→B（且 B≠AB \neq AB=A）：也是非平凡的。

  • 完全非平凡（有时也称“真正非平凡”）：

    • 如果 α∩β=∅\alpha \cap \beta = \emptysetα∩β=∅（即左右两边没有公共属性），则称为完全非平凡的函数依赖
    • 例如：{学号}→{姓名}{\text{学号}} \rightarrow {\text{姓名}}{学号}→{姓名}，通常学号和姓名无交集，属于完全非平凡。

  • 平凡的函数依赖总是成立，无论数据内容如何。它们不携带任何关于数据语义的有用信息。

  • 在研究函数依赖的推理（如 Armstrong 公理）、计算闭包或进行规范化时，我们主要关注非平凡的函数依赖，因为它们反映了数据之间的实际约束。

  • 数据库设计和规范化过程中，可以忽略平凡依赖，重点分析非平凡依赖是否导致冗余或异常。

平凡函数依赖 = 右边 ⊆ 左边 → 必然成立，无信息量。

非平凡函数依赖 = 右边 ⊈ 左边 → 可能反映真实业务规则，需重点关注。

闭包

函数依赖的闭包（Closure）是关系数据库规范化理论中的一个核心概念，主要用于：

  • 判断某个函数依赖是否被隐含（即是否可以从已知依赖推导出来）；
  • 计算属性集的“决定能力”；
  • 求候选码；
  • 进行模式分解等。

闭包分为两类：

  • 函数依赖集的闭包 F+F^+F+
  • 属性集的闭包 X+X^+X+

函数依赖集的闭包

给定一个关系模式 RRR 和其上的一组函数依赖 FFF，F+F^+F+（读作 “F plus”）表示  由 FFF 逻辑蕴含（可推导出）的所有函数依赖的集合。

换句话说，F+F^+F+ 是在 Armstrong 公理系统下，从 FFF 出发能推导出的所有合法函数依赖的全集。

  • F⊆F+F \subseteq F^+F⊆F+
  • F+F^+F+ 可能非常大（指数级），通常不显式计算整个 F+F^+F+。
  • 实际应用中更常使用 属性集的闭包 来间接判断某个 FD 是否属于F+F^+F+。

属性集的闭包

这是最常用、最实用的闭包概念。

给定属性集 X⊆RX \subseteq RX⊆R 和函数依赖集 FFF，X+X^+X+（读作 “X plus”）表示 在 FFF 的约束下，由 XXX 函数决定的所有属性的集合。

即：

X+={A∈R∣X→A 被 F 逻辑蕴含}X^+ = \{ A \in R \mid X \rightarrow A \text{ 被 } F \text{ 逻辑蕴含} \}X+={A∈R∣X→A 被 F 逻辑蕴含}

逻辑蕴含

函数依赖的逻辑蕴含（Logical Implication of Functional Dependencies）回答了这样一个问题：给定一组已知的函数依赖  FFF ，能否推导出另一个函数依赖  X→YX\rightarrow YX→Y

如果能，就认为：FFF 逻辑蕴含 X→YX\rightarrow YX→Y

记作：

F⊨X→YF \models X \rightarrow YF⊨X→Y

推理规则

Armstrong 公理：

  • 自反律：如果 β⊆α\beta \subseteq \alphaβ⊆α，则有 α→β\alpha \rightarrow \betaα→β
  • 增补律：如果 α→β\alpha \rightarrow \betaα→β，则有 γα→γβ\gamma \alpha \rightarrow \gamma\betaγα→γβ
  • 传递律：如果 α→β\alpha\rightarrow\betaα→β 且 β→γ\beta\rightarrow\gammaβ→γ，则有 α→γ\alpha\rightarrow\gammaα→γ

可以使用 Armstrong 公理推导函数依赖集的闭包

  • F+F^+F+：相当于可达边集
  • X+X^+X+：相当于可达点集

计算 F+F^+F+

  • 从 FFF 出发
  • 遍历现有函数依赖集中的单个函数依赖，应用自反律和增补律
  • 遍历现有函数依赖集中的一对函数依赖，应用传递律（if can）
  • 重复，直到结果不再变化

二级定理：

  • 合并律：若有 α→β\alpha\rightarrow\betaα→β 且 α→γ\alpha\rightarrow\gammaα→γ，则有 α→βγ\alpha\rightarrow\beta\gammaα→βγ
  • 分解律：若有 α→βγ\alpha\rightarrow\beta\gammaα→βγ，则有 α→β\alpha\rightarrow\betaα→β 且 α→γ\alpha\rightarrow\gammaα→γ
  • 伪传递律：若有 α→β\alpha\rightarrow\betaα→β 且 γβ→δ\gamma\beta\rightarrow\deltaγβ→δ，则有 αγ→δ\alpha\gamma\rightarrow\deltaαγ→δ

计算 X+X^+X+

遍历函数依赖集 FFF，所有出现在 FFF 中的函数依赖（记为 α→β\alpha\rightarrow\betaα→β），若 α\alphaα 出现在给定的属性集 XXX 中，则将其加入 X+X^+X+

result := x
while (result is changed) {
	for each a->b in F {
		if a in result {
			result += b
		}
	}
}
return result

用途
  • 判断超码：如果 X+X^+X+ 包含 RRR 中所有属性，则 XXX 为超码
  • 验证函数依赖：
    • 检验函数依赖 α→β\alpha\rightarrow\betaα→β 是否成立（即是否在 F+F^+F+ 中）
    • 只需计算 X+X^+X+，查看是否包含 β\betaβ
  • 计算 FFF 闭包：
    • 对于 α⊆R\alpha\subseteq Rα⊆R，计算闭包 α+\alpha^+α+
    • 遍历 α+\alpha^+α+（即对任意 β⊆α+\beta\subseteq\alpha^+β⊆α+），输出一个函数依赖 α→β\alpha\rightarrow\betaα→β

规范化（Normalization）

目标

在关系模式不是“好”的情况下，将其分解为关系模式集 {R1,R2,…,Rn}{R_1,R_2,\dots,R_n}{R1​,R2​,…,Rn​}，关系模式集满足：

  • 每个关系模式都是“好”的：无数据冗余，符合一定范式
  • 分解是无损连接分解
  • 最好能使分解保持依赖

范式 Normal Form

5NF⊂4NF⊂BCNF⊂3CNF⊂2NF⊂1NF5NF\subset 4NF \subset BCNF \subset 3CNF \subset 2NF \subset 1NF5NF⊂4NF⊂BCNF⊂3CNF⊂2NF⊂1NF

某一关系模式 RRR 最高属于第 nnn 范式，则可称为 R∈nNFR\in nNFR∈nNF

第一范式

  • 如果某个域的元素被认为是不可分的单元，那么这个域就是原子的
  • 如果一个关系模式 RRR 的所有属性域都是原子的，称关系模式 RRR 属于第一范式
  • 非原子的值会造成复杂存储和数据冗余

第二范式

建立在第一范式（1NF）的基础上，旨在消除部分函数依赖，从而减少数据冗余和更新异常

  • 若关系模式 R∈1NFR\in 1NFR∈1NF，且在 F+F^+F+ 中每一个非主属性完全函数依赖于候选码，则 R∈2NFR\in 2NFR∈2NF

部分依赖
  • 如果主键是复合的（比如由两个或更多属性组成），
  • 而某个非主属性只由主键的一部分决定，而不是整个主键，
  • 这就是“部分依赖”。

选课(学号, 课程号, 学生姓名, 课程名称, 成绩)

候选码：{学号，课程号}；非主属性：学生姓名、课程名称、成绩

  • {学号，课程号}->成绩：完全依赖
  • 学号->学生姓名：部分依赖
  • 课程号->课程名称：部分依赖

问题：

  • 学生姓名随学号重复存储（选了多门课就存多次）→ 数据冗余
  • 修改学生姓名需更新多行 → 更新异常
  • 删除某门课可能误删学生信息 → 删除异常

第三范式

在第二范式（2NF）的基础上进一步消除传递函数依赖，从而更有效地减少数据冗余和更新异常

对 F+F^+F+ 中所有形如 α→β\alpha\rightarrow\betaα→β 的函数依赖中，至少有以下条件之一成立：

  • α→β\alpha\rightarrow\betaα→β 是一个平凡的函数依赖（即 β⊆α\beta\subseteq\alphaβ⊆α）
  • α\alphaα 是 RRR 的一个超码
  • β−α\beta-\alphaβ−α 中的每个属性 AAA 都包含在 RRR 的候选码中（可能包含在不同的候选码）

第三个条件是 BCNF 的一个最小放宽：3NF 允许主属性被非超码决定，而 BCNF 不允许。

Student(学号, 姓名, 系名, 系主任)

函数依赖：

  • 学号->系名
  • 系名->系主任

学号是候选码，系名、系主任是非主属性。系主任不直接依赖于候选码，而是通过系名传递依赖于候选码

这种依赖会导致：

  • 同一系的所有学生都重复存储“系主任” → 冗余；
  • 更换系主任需更新多行 → 更新异常。

Boyce-Codd 范式（BCNF）

BC 范式比第三范式（3NF）更严格，旨在彻底消除由函数依赖引起的冗余和异常。不仅处理非主属性，还要确保所有属性（包括主属性）  都不会因非超码的决定因素而产生冗余。

一个关系模式  RRR 属于  BCNF，当且仅当：对于 RRR  上的每一个非平凡的函数依赖 X→YX \rightarrow YX→Y （即  Y⊈XY \not\subseteq XY⊆X）

  • XXX 必须是  RRR  的一个超码
特性 第三范式（3NF） BCNF
要求 对每个 FD X→AX \rightarrow AX→A，满足：
1. XXX 是超码，或
2. AAA 是主属性（属于某个候选码）		 对每个 FD X→AX \rightarrow AX→A，必须满足：
XXX 是超码
宽松程度 较宽松（允许主属性被非超码决定） 更严格（不允许任何非超码作为决定因素）
冗余控制 可能仍有少量冗余（主属性间） 基本消除所有由 FD 引起的冗余

函数依赖理论

正则覆盖

  • 函数依赖集可能存在冗余依赖（这些依赖可以从其他依赖中推导出来）
  • 函数依赖集的一部分也可能是冗余的

令 FFF 的正则覆盖 FcF_cFc​ 没有任何冗余依赖或存在冗余部分的依赖

FcF_cFc​ 具有和 FFF 相同的函数依赖集闭包。其意义在于：验证 FcF_cFc​ 比验证 FFF 更加容易、3NF 算法必备

{A→B,B→C,A→C}{A\rightarrow B,B\rightarrow C, A\rightarrow C}{A→B,B→C,A→C}

其中 A→CA\rightarrow CA→C 是冗余的，可以由另两个函数依赖推出

{A→B,B→C,A→CD}{A\rightarrow B,B\rightarrow C, A\rightarrow CD}{A→B,B→C,A→CD}

可以简化为 {A→B,B→C,A→D}{A\rightarrow B,B\rightarrow C, A\rightarrow D}{A→B,B→C,A→D}

{A→B,B→C,AC→D}{A\rightarrow B,B\rightarrow C, AC\rightarrow D}{A→B,B→C,AC→D}

可以简化为 {A→B,B→C,A→D}{A\rightarrow B,B\rightarrow C, A\rightarrow D}{A→B,B→C,A→D}

无关属性

如果去除函数依赖中的一个属性不改变该函数依赖集的闭包，则称该属性是无关属性（extraneous）

形式化定义：考虑函数依赖集 FFF 及 FFF 中的函数依赖 α→β\alpha\rightarrow\betaα→β

  • 如果 A∈αA\in \alphaA∈α 且 FFF 逻辑蕴含(F−{α→β})∪{(α−A)→β}(F-{\alpha\rightarrow \beta})\cup {(\alpha-A)\rightarrow \beta}(F−{α→β})∪{(α−A)→β}，则属性 AAA 在 α\alphaα 中是无关的
  • 如果 A∈βA\in \betaA∈β 且函数依赖集 (F−{α→β})∪{α→(β−A)}(F-{\alpha\rightarrow \beta})\cup {\alpha\rightarrow (\beta-A)}(F−{α→β})∪{α→(β−A)} 逻辑蕴含 FFF，则 AAA 在 β\betaβ 中是无关的

也就是去掉该函数依赖，或者去掉函数依赖一侧的元素 AAA，这样形成的函数依赖仍然能保持闭包不变

给定 F={A→C,AB→C}F={A\rightarrow C, AB\rightarrow C}F={A→C,AB→C}

对于 AB→CAB\rightarrow CAB→C 去掉 BBB，得到 A→CA\rightarrow CA→C，因为 {A→C,AB→C}{A\rightarrow C, AB\rightarrow C}{A→C,AB→C} 逻辑蕴含 A→CA\rightarrow CA→C，所以 BBB 是 AB→CAB\rightarrow CAB→C 中的无关属性

给定 F={A→C,AB→CD}F={A\rightarrow C, AB\rightarrow CD}F={A→C,AB→CD}

对于 AB→CDAB\rightarrow CDAB→CD，去掉 CCC 得到 AB→DAB\rightarrow DAB→D，再加上原来的 {A→C}{A\rightarrow C}{A→C}，得到的新函数依赖集逻辑蕴含 FFF，即 CCC 是 AB→CDAB\rightarrow CDAB→CD 的无关属性

无关属性的验证

考虑函数依赖集 FFF 及 FFF 中的函数依赖 α→β\alpha\rightarrow\betaα→β

验证属性 A∈αA\in \alphaA∈α

  • 使用 FFF 中的函数依赖计算属性集闭包 (α−A)+(\alpha-A)^+(α−A)+
  • 如果该属性集闭包中包含 β\betaβ，则 AAA 在 α\alphaα 中是多余属性

验证属性 A∈βA\in \betaA∈β

  • 使用函数依赖集 F′=(F−{α→β})∪{α→(β−A)}F'=(F-{\alpha\rightarrow\beta})\cup {\alpha\rightarrow (\beta-A)}F′=(F−{α→β})∪{α→(β−A)} 计算 α′+\alpha'^+α′+
  • 如果 α+\alpha^+α+ 包含 AAA，则 AAA 在 β\betaβ 中是多余属性

正则覆盖的计算

Fc = F
do {
	使用合并律将 Fc 中的 a1->b1 和 a1->b2 替换为 a1->b1b2（寻找左侧相同）
	在 Fc 中找出在 a 或 b 中含无关属性的函数依赖 a->b
	若发现无关属性，将其从 Fc 的 a->b 中删除
} while (Fc is changed);

FFF 的正则覆盖 FcF_cFc​ 是一个函数依赖集，具有如下特性：

  • FFF 逻辑蕴涵 FcF_cFc​ 中的所有函数依赖
  • FcF_cFc​ 逻辑蕴涵 FFF 中的所有函数依赖
  • FcF_cFc​ 中任何函数依赖都不含无关属性
  • FcF_cFc​ 中函数依赖的左半部都是不同的

示例：R=(A,B,C),F={A→BC，B→C，A→B，AB→C}R = (A, B, C),F = { A \rightarrow BC，B \rightarrow C，A \rightarrow B，AB \rightarrow C }R=(A,B,C),F={A→BC，B→C，A→B，AB→C}

初始化 Fc=F={A→BC，B→C，A→B，AB→C}F_c=F={ A \rightarrow BC，B \rightarrow C，A \rightarrow B，AB \rightarrow C}Fc​=F={A→BC，B→C，A→B，AB→C}

寻找无关属性，先尝试删去左侧元素，再删去右侧元素

  • 对于 AB→CAB\rightarrow CAB→C，α=AB,β=C\alpha=AB,\beta=Cα=AB,β=C

无损分解

对于 R=(R1,R2)R=(R_1,R_2)R=(R1​,R2​)，要求模式 RRR 上的所有可能关系 rrr 都有：

r=∏R1(r)⋈∏R2(r)r=\prod_{R_1}(r)\bowtie \prod_{R_2}(r)r=R1​∏​(r)⋈R2​∏​(r)

如果下面的依赖中至少有一个属于 F+F^+F+，那么将 RRR 分解为 R1R_1R1​ 和 R2R_2R2​ 是无损连接分解：

  • R1∩R2→R1R_1\cap R_2\rightarrow R_1R1​∩R2​→R1​
  • R1∩R2→R2R_1\cap R_2\rightarrow R_2R1​∩R2​→R2​
  • R1∩R2R_1\cap R_2R1​∩R2​ 是 R1R_1R1​ 或 R2R_2R2​ 的超码

上述函数依赖测试只是无损连接分解的一个充分条件；只有当所有约束都是函数依赖时，它才是必要条件

R={A,B,C},F={A→B,B→C}R={A,B,C},F={A\rightarrow B, B\rightarrow C}R={A,B,C},F={A→B,B→C}

方式一：R1=(A,B),R2=(B,C)R_1=(A,B),R_2=(B,C)R1​=(A,B),R2​=(B,C)

  • 检验：R1∩R2={B},B→BCR_1\cap R_2={B},B\rightarrow BCR1​∩R2​={B},B→BC

方式二：R1=(A,B),R2=(A,C)R_1=(A,B),R_2=(A,C)R1​=(A,B),R2​=(A,C)

  • 检验：R1∩R2={A},A→ABR_1\cap R_2={A},A\rightarrow ABR1​∩R2​={A},A→AB

保持依赖

FFF 为模式 RRR 上的一个函数依赖集，R1,R2,…,RnR_1 ,R_2 , \dots, R_nR1​,R2​,…,Rn​ 为 RRR 的一个分解。FFF 在 RiR_iRi​ 上的限定是 F+F ^+F+ 中所有只包含 RiR_iRi​ 中属性的函数依赖的集合FiF_iFi​

令 F′=F1∩F2∩⋯∩FnF'=F_1\cap F_2\cap\dots\cap F_nF′=F1​∩F2​∩⋯∩Fn​，F′F'F′ 是模式 RRR 上的一个函数依赖集

  • 如果 (F′)+=F+(F')^+=F^+(F′)+=F+ 成立，则该分解是保持依赖的
  • 具有上述性质的分解称为保持依赖的分解

即不需要进行表的连接，就可以查询到每个函数依赖对应的数据

检验

当 RRR 分解成 R1,R2,…,RnR_1 ,R_2 , \dots, R_nR1​,R2​,…,Rn​ 后，验证每一个函数依赖 α→β\alpha\rightarrow\betaα→β 是否被保持：

result = a
while (result is changed) {
	for each Ri {
		t = (result ∩ Ri)^+ ∩ Ri
		result = result ∪ t
	}
}
  • 如果 result 包含 β\betaβ 中的所有属性，那么函数依赖 α→β\alpha\rightarrow\betaα→β 被保持

R={A,B,C},F={A→B,B→C}R={A,B,C},F={A\rightarrow B, B\rightarrow C}R={A,B,C},F={A→B,B→C}

方式一：R1=(A,B),R2=(B,C)R_1=(A,B),R_2=(B,C)R1​=(A,B),R2​=(B,C)，保持依赖

方式二：R1=(A,B),R2=(A,C)R_1=(A,B),R_2=(A,C)R1​=(A,B),R2​=(A,C)，不保持依赖

BCNF 分解算法

BCNF 是关系数据库规范化中的一种高级范式，用于消除函数依赖引起的冗余和异常。一个关系模式 RRR 属于 BCNF，当且仅当对于其每一个非平凡的函数依赖 X→YX \rightarrow YX→Y，XXX 都是 RRR 的超码。

当关系模式不满足 BCNF 时，可通过以下步骤进行无损连接的 BCNF 分解：

分解步骤

  • 输入：一个关系模式 RRR 及其函数依赖集 FFF

  • 输出：RRR 的一个 BCNF 分解 ρ=R1,R2,…,Rn\rho = {R_1, R_2, \dots, R_n}ρ=R1​,R2​,…,Rn​，满足无损连接性

  • 检查当前关系模式 RRR 是否满足 BCNF：

    • 对 F+F^+F+ 中的每一个非平凡函数依赖 X→YX \rightarrow YX→Y：
      • 若 XXX 不是 RRR 的超码，则 RRR 不满足 BCNF，需进行分解

  • 若 R 不满足 BCNF：

    • 找到一个违反 BCNF 的函数依赖 X→YX \rightarrow YX→Y（即 XXX 不是超码）
    • 将 RRR 分解为两个子模式：
      • R1=X∪YR_1 = X \cup YR1​=X∪Y
      • R2=R−(Y−X)R_2 = R − (Y − X)R2​=R−(Y−X)（即保留 XXX 和其余不在 YYY 中的属性）
    • 对 R1R_1R1​ 和 R2R_2R2​ 分别递归执行 BCNF 分解

  • 若 RRR 已满足 BCNF：

    • 将 RRR 加入结果分解集合 ρ\rhoρ

  • 最终得到的分解 ρ\rhoρ 满足：

    • 每个子模式都属于 BCNF
    • 分解具有无损连接性（但不一定保持函数依赖）

注意事项

  • BCNF 分解总是可以达到无损连接，但可能无法保持所有原始函数依赖
  • 分解结果可能不唯一，取决于选择违反 BCNF 的函数依赖的顺序
  • 实际应用中，若保持依赖更重要，可考虑使用 3NF 而非 BCNF

示例

R=(A,B,C,D,E),F={A→BC,CD→E,B→D,E→A}R=(A, B, C, D, E),F={A\rightarrow BC,CD\rightarrow E,B\rightarrow D,E\rightarrow A}R=(A,B,C,D,E),F={A→BC,CD→E,B→D,E→A}

对于每个函数依赖，判断左侧是否为 RRR 的超码

先找出所有超码：(A),(E),(CD)(A),(E),(CD)(A),(E),(CD)，就是判断能否从一个左侧元素集开始扩展到整个模式 RRR

所以只有 B→DB\rightarrow DB→D 左侧不是 RRR 的超码，不满足 BCNF，需要进行分解

分解为：

  • R1=X∪Y={B,D}R_1=X\cup Y={B,D}R1​=X∪Y={B,D}
  • R2=R−(Y−X)={A,B,C,E}R_2=R-(Y-X)={A,B,C,E}R2​=R−(Y−X)={A,B,C,E}

根据新的模式集和 FFF，判断是否满足 BCNF，注意此时的 FFF 需要根据新的模式集删去不存在的元素

如：

  • 对于 R1R_1R1​，F1={B→D}F_1={B\rightarrow D}F1​={B→D}，因为其他 A,C,EA,C,EA,C,E 都不存在了，而 BBB 是 F1F_1F1​ 的超码，所以 R1R_1R1​ 满足 BCNF，不需要再分解
  • 对于 R2R_2R2​，F2={A→BC,E→A}F_2={A\rightarrow BC, E\rightarrow A}F2​={A→BC,E→A}，可以发现 EEE 是超码，但是 AAA 不是，所以对于 A→BCA\rightarrow BCA→BC 还需要进行分解

分解：

  • R21=X∪Y={A,B,C}R_{21}=X\cup Y={A, B, C}R21​=X∪Y={A,B,C}，F21={A→BC}F_{21}={A\rightarrow BC}F21​={A→BC}，AAA 为超码，满足 BCNF
  • R22=R2−(Y−X)={A,E}R_{22}=R_{2}-(Y-X)={A,E}R22​=R2​−(Y−X)={A,E}，F22={E→A}F_{22}={E\rightarrow A}F22​={E→A}，EEE 为超码，满足 BCNF

所以综上，需要将 RRR 分解为：{(B,D),(A,B,C),(A,E)}{(B,D),(A,B,C),(A,E)}{(B,D),(A,B,C),(A,E)}

3NF 分解

第三范式（3NF）是关系数据库规范化中的一个重要级别，它在保留函数依赖的前提下，有效减少数据冗余和更新异常。一个关系模式 RRR 属于 3NF，当且仅当对于其每一个非平凡函数依赖 X→AX \rightarrow AX→A（其中 AAA 是单个属性），以下至少一项成立：

  • XXX 是 RRR 的超码，或
  • AAA 是主属性（即 AAA 属于某个候选码）

与 BCNF 不同，3NF 允许某些非超码决定主属性，因此更容易在保持函数依赖的同时实现无损连接分解。

分解目标

  • 输入：关系模式 RRR 及其函数依赖集 FFF
  • 输出：RRR 的一个分解 ρ={R1,R2,…,Rk}\rho = {R_1, R_2, \dots, R_k}ρ={R1​,R2​,…,Rk​}，满足：
    • 每个 RiR_iRi​ 属于 3NF
    • 分解具有无损连接性
    • 分解保持函数依赖

分解步骤（基于规范覆盖的合成算法）

  • 计算 FFF 的最小覆盖（也称规范覆盖）FcF_cFc​：

    • 合并右部相同的依赖（如 X→AX\rightarrow AX→A, X→BX\rightarrow BX→B 合并为 X→ABX\rightarrow ABX→AB）
    • 去除左部冗余属性（若 (X−A)→Y(X−A)\rightarrow Y(X−A)→Y 仍能推出原依赖，则 AAA 冗余）
    • 去除冗余依赖（若移除某依赖后 F+F^+F+ 不变，则该依赖冗余）

  • 对 FcF_cFc​ 中的每个函数依赖 X→A1A2…AnX \rightarrow A_1A_2\dots A_nX→A1​A2​…An​：

    • 创建一个关系模式 Ri=X∪{A1,A2,…,An}R_i = X \cup {A_1, A_2, \dots, A_n}Ri​=X∪{A1​,A2​,…,An​}

  • 检查是否已有模式包含 RRR 的某个候选键：

    • 若没有，则任选一个候选键 KKK，添加一个新关系模式 Rk=KR_k = KRk​=K

  • （可选）去除被其他模式包含的关系模式（即若 Ri⊆RjR_i \subseteq R_jRi​⊆Rj​，则删除 RiR_iRi​）

特点说明

  • 该算法保证分解结果既保持函数依赖又具有无损连接性
  • 所有生成的子模式自动满足 3NF
  • 最小覆盖确保了分解的简洁性和无冗余
  • 添加候选键是为了保证无损连接（因为仅靠依赖可能无法覆盖全部属性或重建原关系）
