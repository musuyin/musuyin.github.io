工厂方法模式（Factory Method Pattern）

2026-08-24

#设计模式#创建型

工厂方法把产品创建作为可被子类替换的扩展点。示例中要区分两个选择：应用入口选择哪一种物流创建者，创建者再通过工厂方法提供运输产品。入口的条件分支并不会因此自动消失。

定义

工厂方法模式定义一个创建对象的接口，由子类决定具体实例化哪个类。它将对象的创建延迟到子类，从而实现客户端与具体类的解耦。

问题场景

假设要开发一个物流系统，需要支持多种运输方式：

// ❌ 不使用工厂的做法
public class Logistics {
    public Shipment createShipment(String type) {
        if ("truck".equals(type)) {
            return new TruckShipment();
        } else if ("ship".equals(type)) {
            return new ShipShipment();
        } else if ("plane".equals(type)) {
            return new PlaneShipment();
        }
        return null;
    }
}

问题：

  • 每次新增运输方式都要修改 createShipment() 方法
  • 违反开闭原则（Open/Closed Principle）
  • 客户端代码与具体类紧耦合

解决方案

核心结构

      ┌─────────────────┐
      │  Creator        │
      ├─────────────────┤
      │ factoryMethod() │◄─── 抽象方法
      │ businessMethod()│
      └────────┬────────┘
               △
      ┌────────┴────────┐
      │                 │
┌─────┴─────┐    ┌─────┴──────┐
│ConcreteA  │    │ConcreteB   │
├───────────┤    ├────────────┤
│factoryM() │    │factoryM()  │
│  return A │    │  return B  │
└───────────┘    └────────────┘

标准实现

定义产品接口

// 抽象产品
public interface Transport {
    void deliver(String cargo);
}

// 具体产品 - 卡车
public class TruckTransport implements Transport {
    @Override
    public void deliver(String cargo) {
        System.out.println("卡车运送：" + cargo);
    }
}

// 具体产品 - 轮船
public class ShipTransport implements Transport {
    @Override
    public void deliver(String cargo) {
        System.out.println("轮船运送：" + cargo);
    }
}

// 具体产品 - 飞机
public class PlaneTransport implements Transport {
    @Override
    public void deliver(String cargo) {
        System.out.println("飞机运送：" + cargo);
    }
}

定义创建者抽象类

// 抽象创建者
public abstract class Logistics {
    
    // 抽象工厂方法 - 由子类决定创建什么
    public abstract Transport createTransport();
    
    // 业务方法 - 使用工厂方法
    public void planDelivery(String cargo) {
        Transport transport = createTransport();
        transport.deliver(cargo);
    }
}

定义具体创建者

// 具体创建者 - 陆运公司
public class RoadLogistics extends Logistics {
    @Override
    public Transport createTransport() {
        return new TruckTransport();
    }
}

// 具体创建者 - 海运公司
public class SeaLogistics extends Logistics {
    @Override
    public Transport createTransport() {
        return new ShipTransport();
    }
}

// 具体创建者 - 空运公司
public class AirLogistics extends Logistics {
    @Override
    public Transport createTransport() {
        return new PlaneTransport();
    }
}

客户端使用

public class Application {
    public static void main(String[] args) {
        Logistics logistics = chooseLogistics("sea");
        logistics.planDelivery("货物：电子产品");
    }
    
    private static Logistics chooseLogistics(String type) {
        switch (type) {
            case "road":
                return new RoadLogistics();
            case "sea":
                return new SeaLogistics();
            case "air":
                return new AirLogistics();
            default:
                throw new IllegalArgumentException("未知的运输方式");
        }
    }
}

输出：轮船运送：货物：电子产品

简化版本：静态工厂方法

当只有少数几个具体产品时，可以简化为静态工厂：

public class TransportFactory {
    public static Transport createTransport(String type) {
        switch (type) {
            case "truck":
                return new TruckTransport();
            case "ship":
                return new ShipTransport();
            case "plane":
                return new PlaneTransport();
            default:
                throw new IllegalArgumentException("未知的运输方式");
        }
    }
}

// 使用
Transport transport = TransportFactory.createTransport("ship");
transport.deliver("货物");

工厂方法 vs 抽象工厂

特性 工厂方法 抽象工厂
关注点 某类产品的创建扩展点 同一产品族内多类相关产品的创建
方法数 一个 factoryMethod() 多个工厂方法
复杂度 简单 复杂
适用场景 产品单一 产品族关联

工厂方法例子：日志记录器、数据库驱动 抽象工厂例子：UI 主题、数据库系统

真实应用案例

Java 的 Collection Framework

// 抽象方法
List<String> list1 = new ArrayList<>();  // 客户端显式选择 ArrayList
List<String> list2 = new LinkedList<>(); // 还是 LinkedList

// 这只展示面向接口编程，直接 new 不是工厂方法模式

JDBC 数据库驱动

// 不同数据库的驱动程序各自实现 Driver 接口
Connection conn = DriverManager.getConnection(url, user, password);
// DriverManager 根据 URL 自动选择对应的驱动

日志框架（SLF4J）

public class LoggerFactory {
    public static Logger getLogger(Class<?> clazz) {
        // 根据配置，返回 Log4j、Logback 或其他日志实现
        return new Log4jLogger(clazz);
        // 或 new LogbackLogger(clazz);
        // 或 new JdkLogger(clazz);
    }
}

优缺点分析

优点 ✅

  1. 低耦合：客户端只依赖产品接口和创建者抽象类，不依赖具体类
  2. 符合开闭原则：新增产品只需添加新的具体创建者，无需修改现有代码
  3. 符合单一职责原则：创建逻辑集中在一处
  4. 易于扩展：支持多种产品的创建

缺点 ❌

  1. 类数量增加：每种产品都需对应的具体创建者，代码量大
  2. 间接性：多层继承可能增加理解难度
  3. 简单场景过度设计：如果只有一两个产品，不必使用

使用建议

✅ 适合使用：

  • 系统不依赖产品的具体创建过程
  • 系统需要支持多种产品的创建
  • 产品有公共接口
  • 未来可能增加新的产品类型

❌ 不适合使用：

  • 只有一个产品类
  • 产品创建逻辑简单
  • 不需要解耦创建与使用

与其他模式的组合

组合模式 作用
+ 单例 确保工厂只有一个实例
+ 策略模式 工厂选择具体策略
+ 模板方法 工厂方法在模板中调用
+ 抽象工厂 工厂方法创建产品族
