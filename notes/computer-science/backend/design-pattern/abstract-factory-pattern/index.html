抽象工厂模式（Abstract Factory Pattern）

2026-08-24

#设计模式#创建型

抽象工厂围绕“同一套产品应当彼此兼容”组织创建接口。先分清产品等级（按钮、复选框、输入框）与产品族（Windows、macOS），再看为何切换一个工厂即可切换整套实现。

定义

抽象工厂模式提供一个创建一系列相关或相互依赖对象的接口，无需指定它们的具体类。它用于支持多个产品族，且这些产品族之间有相互的依赖关系。

工厂方法 vs 抽象工厂

工厂方法：              抽象工厂：
┌─────────────┐        ┌──────────────────┐
│Transport    │        │UIFactory         │
├─────────────┤        ├──────────────────┤
│Truck        │        │createButton()    │
│Ship         │        │createCheckbox()  │
│Plane        │        │createInput()     │
└─────────────┘        └──────────────────┘
  一种产品             多种相关产品族

问题场景

开发一个跨平台 UI 系统，需要支持 Windows 和 macOS 两个平台。每个平台有自己的按钮、复选框、文本框等控件：

Windows UI：
├─ Button（Windows 风格）
├─ Checkbox（Windows 风格）
└─ Input（Windows 风格）

macOS UI：
├─ Button（macOS 风格）
├─ Checkbox（macOS 风格）
└─ Input（macOS 风格）

需求：

  • 不同平台的 UI 控件外观不同但功能相同
  • 运行时决定使用哪个平台
  • 新增平台时易于扩展
  • 避免混用不同平台的控件

标准实现

定义抽象产品族

// 按钮接口
public interface Button {
    void click();
}

// 复选框接口
public interface Checkbox {
    void check();
}

// 输入框接口
public interface Input {
    void focus();
}

定义具体产品 - Windows

// Windows 按钮
public class WindowsButton implements Button {
    @Override
    public void click() {
        System.out.println("Windows 按钮被点击");
    }
}

// Windows 复选框
public class WindowsCheckbox implements Checkbox {
    @Override
    public void check() {
        System.out.println("Windows 复选框被选中");
    }
}

// Windows 输入框
public class WindowsInput implements Input {
    @Override
    public void focus() {
        System.out.println("Windows 输入框获得焦点");
    }
}

定义具体产品 - macOS

// macOS 按钮
public class MacButton implements Button {
    @Override
    public void click() {
        System.out.println("macOS 按钮被点击");
    }
}

// macOS 复选框
public class MacCheckbox implements Checkbox {
    @Override
    public void check() {
        System.out.println("macOS 复选框被选中");
    }
}

// macOS 输入框
public class MacInput implements Input {
    @Override
    public void focus() {
        System.out.println("macOS 输入框获得焦点");
    }
}

定义抽象工厂

// 抽象工厂接口 - 定义创建所有产品的方法
public interface GUIFactory {
    Button createButton();
    Checkbox createCheckbox();
    Input createInput();
}

定义具体工厂

// Windows 工厂
public class WindowsGUIFactory implements GUIFactory {
    @Override
    public Button createButton() {
        return new WindowsButton();
    }
    
    @Override
    public Checkbox createCheckbox() {
        return new WindowsCheckbox();
    }
    
    @Override
    public Input createInput() {
        return new WindowsInput();
    }
}

// macOS 工厂
public class MacGUIFactory implements GUIFactory {
    @Override
    public Button createButton() {
        return new MacButton();
    }
    
    @Override
    public Checkbox createCheckbox() {
        return new MacCheckbox();
    }
    
    @Override
    public Input createInput() {
        return new MacInput();
    }
}

应用程序

public class Application {
    private GUIFactory factory;
    private Button button;
    private Checkbox checkbox;
    private Input input;
    
    // 构造器注入工厂
    public Application(GUIFactory factory) {
        this.factory = factory;
    }
    
    public void initialize() {
        button = factory.createButton();
        checkbox = factory.createCheckbox();
        input = factory.createInput();
    }
    
    public void run() {
        button.click();
        checkbox.check();
        input.focus();
    }
}

客户端使用

public class Demo {
    public static void main(String[] args) {
        String osName = System.getProperty("os.name").toLowerCase();
        
        GUIFactory factory;
        if (osName.contains("win")) {
            factory = new WindowsGUIFactory();
        } else if (osName.contains("mac")) {
            factory = new MacGUIFactory();
        } else {
            throw new UnsupportedOperationException("不支持的操作系统");
        }
        
        Application app = new Application(factory);
        app.initialize();
        app.run();
    }
}

Windows 复选框被选中
Windows 输入框获得焦点

输出（macOS）：

macOS 按钮被点击
macOS 复选框被选中
macOS 输入框获得焦点

核心要点

产品族的一致性

抽象工厂的关键是产品族的协调：

WindowsGUIFactory 创建的是一个完整的 Windows 产品族
├─ WindowsButton ─┐
├─ WindowsCheckbox┼─ 风格一致！
└─ WindowsInput ──┘

MacGUIFactory 创建的是一个完整的 macOS 产品族
├─ MacButton ─┐
├─ MacCheckbox├─ 风格一致！
└─ MacInput ──┘

不能混用：❌ WindowsButton + MacCheckbox

真实应用案例

JDBC - 数据库驱动

// 抽象工厂 - DriverManager 选择合适的驱动
Connection conn = DriverManager.getConnection("jdbc:mysql://...", user, pwd);

// 不同数据库的驱动是一个产品族
// MySQL 驱动：
//   ├─ MySQLConnection
//   ├─ MySQLStatement
//   └─ MySQLResultSet

// PostgreSQL 驱动：
//   ├─ PostgreSQLConnection
//   ├─ PostgreSQLStatement
//   └─ PostgreSQLResultSet

AWT/Swing - Java UI 框架

// 不同平台的 Look and Feel
UIManager.setLookAndFeel("com.sun.java.swing.plaf.windows.WindowsLookAndFeel");
// 或
UIManager.setLookAndFeel("com.apple.laf.AquaLookAndFeel");

// 自动创建对应平台的 UI 组件
JButton button = new JButton("Click me");
JCheckBox checkbox = new JCheckBox("Check me");

AWS SDK - 云服务

// 不同区域的 AWS 服务是一个产品族
AWSFactory usEastFactory = new AWSFactory("us-east-1");
S3Client s3 = usEastFactory.createS3Client();
EC2Client ec2 = usEastFactory.createEC2Client();

AWSFactory euWestFactory = new AWSFactory("eu-west-1");
S3Client s3EU = euWestFactory.createS3Client();
EC2Client ec2EU = euWestFactory.createEC2Client();

优缺点分析

优点 ✅

  1. 产品族的一致性：确保同一工厂创建的产品协调一致
  2. 隔离具体类：客户端只依赖抽象工厂和抽象产品
  3. 易于切换产品族：只需更换工厂实现即可
  4. 符合开闭原则：新增产品族无需修改现有代码
  5. 单一职责：产品创建与业务逻辑分离

缺点 ❌

  1. 类数量爆炸：每新增产品，所有工厂都需要新方法
  2. 扩展困难：新增产品类型需要修改所有工厂类
  3. 过度设计：对简单场景可能是浪费
  4. 学习曲线陡：概念相对复杂

与工厂方法的比较

维度 工厂方法 抽象工厂
创建对象 单个产品 产品族
核心方法 factoryMethod() 多个 create*()
产品关系 无特殊关系 相互依赖/协调
扩展成本 低 高
适用场景 产品单一 产品相关联

扩展：新增 Linux UI

如果要支持 Linux 平台，只需：

// 1. 定义 Linux 具体产品
public class LinuxButton implements Button { ... }
public class LinuxCheckbox implements Checkbox { ... }
public class LinuxInput implements Input { ... }

// 2. 定义 Linux 工厂
public class LinuxGUIFactory implements GUIFactory {
    public Button createButton() { return new LinuxButton(); }
    public Checkbox createCheckbox() { return new LinuxCheckbox(); }
    public Input createInput() { return new LinuxInput(); }
}

// 3. 工厂选择逻辑添加一个分支即可
if (osName.contains("linux")) {
    factory = new LinuxGUIFactory();
}

使用建议

✅ 适合使用：

  • 系统需要支持多个产品族
  • 产品族内的产品相互依赖
  • 需要在运行时切换产品族
  • 产品可能频繁变化

❌ 不适合使用：

  • 只有一个产品族
  • 产品之间无依赖关系
  • 系统相对简单稳定

常见变体

配置文件驱动

// 配置文件：factory.properties
# factory.class=com.example.WindowsGUIFactory
# 或
# factory.class=com.example.MacGUIFactory

public class FactoryLoader {
    public static GUIFactory loadFactory() {
        String factoryClass = properties.getProperty("factory.class");
        return (GUIFactory) Class.forName(factoryClass).newInstance();
    }
}

注册表模式

public class GUIFactoryRegistry {
    private static Map<String, Class<?>> factories = new HashMap<>();
    
    static {
        factories.put("windows", WindowsGUIFactory.class);
        factories.put("mac", MacGUIFactory.class);
        factories.put("linux", LinuxGUIFactory.class);
    }
    
    public static GUIFactory getFactory(String os) {
        return (GUIFactory) factories.get(os).newInstance();
    }
}
