pprof

2026-09-11

#待处理

性能排障先根据现象选择 profile：CPU 高看 CPU，内存持续增长看存活堆与分配，goroutine 增长看栈，低 CPU 的延迟看阻塞和锁。采样窗口应覆盖可复现负载，前后比较保持条件一致。

Go 的 pprof​ 主要用来做性能分析：CPU 热点、内存分配、goroutine 泄漏、锁竞争、阻塞等。下面按“最快上手 → 常用场景 → 怎么看结果”讲。

最快上手：给 HTTP 服务加 pprof

只要你的程序本来就是 HTTP 服务，加一行匿名导入即可：

import (
    _ "net/http/pprof"
)

func main() {
    go func() {
        // 单独开一个端口，别和业务端口混在一起
        http.ListenAndServe("localhost:6060", nil)
    }()

    // 你的业务代码
}

然后访问：

  • 总览：http://localhost:6060/debug/pprof/
  • CPU：/debug/pprof/profile?seconds=30
  • 堆内存：/debug/pprof/heap
  • goroutine：/debug/pprof/goroutine
  • block：/debug/pprof/block
  • mutex：/debug/pprof/mutex
  • trace：/debug/pprof/trace?seconds=5

⚠️ 生产环境千万别把 6060 暴露公网，最好放内网 / 加鉴权 / 用环境变量开关。

采集并分析

CPU 分析

go tool pprof http://localhost:6060/debug/pprof/profile?seconds=30

采 30 秒 CPU 后进入交互式界面：

(pprof) top
(pprof) top -cum
(pprof) list HandlerName
(pprof) web        # 需要 graphviz

更推荐直接开网页 UI：

go tool pprof -http=:8081 http://localhost:6060/debug/pprof/profile?seconds=30

浏览器打开 http://localhost:8081，有：

  • Top
  • Graph
  • Flame Graph（火焰图，最直观）
  • Source（看具体哪行代码热）

怎么看 CPU 火焰图：

  • 横轴：占用 CPU 时间比例，越宽越热
  • 纵轴：调用栈深度
  • 底层是调用者，上层是被调用者
  • 宽且平的顶部函数 = 优化重点

内存分析

go tool pprof -http=:8081 http://localhost:6060/debug/pprof/heap

堆 profile 有 4 个核心指标：

指标 含义 用途
inuse_space 当前还在用的内存 查内存泄漏
inuse_objects 当前还在用的对象数 查对象堆积
alloc_space 累计分配过的内存 查 GC 压力
alloc_objects 累计分配过的对象数 查频繁分配

例子：

go tool pprof -inuse_space http://localhost:6060/debug/pprof/heap
go tool pprof -alloc_space  http://localhost:6060/debug/pprof/heap

经验：

  • inuse_space 一直涨 → 可能内存泄漏
  • alloc_space 很高但 inuse_space 不高 → 分配太频繁，GC 压力大

goroutine 泄漏

go tool pprof http://localhost:6060/debug/pprof/goroutine

或者直接看文本栈：

curl http://localhost:6060/debug/pprof/goroutine?debug=2

重点看：

  • goroutine 数量是不是一直涨
  • 大量 chan receive / select / semacquire / runtime.gopark
  • 谁 go func() 创建出来却没人回收

阻塞 / 锁竞争

这两个默认不采集，要先开：

import "runtime"

func init() {
    runtime.SetBlockProfileRate(1)        // 阻塞采样
    runtime.SetMutexProfileFraction(100)  // 1/100 的锁竞争采样
}

然后：

go tool pprof http://localhost:6060/debug/pprof/block
go tool pprof http://localhost:6060/debug/pprof/mutex

适合排查：

  • channel 等待
  • mutex 抢锁
  • 服务“CPU 不高但很慢”

不用 HTTP：写文件方式

f, _ := os.Create("cpu.prof")
pprof.StartCPUProfile(f)
defer pprof.StopCPUProfile()

// ... 跑业务

f2, _ := os.Create("mem.prof")
runtime.GC()
pprof.WriteHeapProfile(f2)
f2.Close()

然后：

go tool pprof cpu.prof
go tool pprof mem.prof

benchmark 里用

go test -bench=. -cpuprofile=cpu.prof -memprofile=mem.prof
go tool pprof cpu.prof
go tool pprof mem.prof

pprof 交互命令速查

top           # 按占用排序
top -cum      # 按累计占用排序
list Func     # 看某个函数的源码热点
web           # 生成调用图
png / svg     # 导出图片
base a.prof   # 和另一个 profile 做差

例如对比两次 heap：

go tool pprof -base heap1.prof heap2.prof

看“这段时间新增了什么”。

典型排障套路

CPU 高

  1. 采 30s CPU profile
  2. 看火焰图
  3. top -cum 找调用链
  4. list 函数名 定位到行

内存涨

  1. 隔 30s 采两次 heap
  2. inuse_space 看泄漏
  3. alloc_space 看分配压力
  4. 用 -base 看增量

goroutine 涨

  1. goroutine?debug=2
  2. 看状态：select / chan receive / semacquire
  3. 找创建 goroutine 的栈

服务慢但 CPU 不高

  1. block profile
  2. mutex profile
  3. trace：go tool trace trace.out

复习

  • inuse_space 与 alloc_space 能分别说明什么？
  • 为什么应结合两次采样和调用链判断疑似泄漏？
