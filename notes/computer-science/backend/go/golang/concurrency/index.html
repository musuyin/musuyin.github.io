#Go#并发

并发程序需要共同设计任务启动、状态同步和退出路径。goroutine 负责执行，channel 或锁负责协调，context 传播取消；协程池还需要容量、背压与关闭协议。

面试追问：goroutine 卡死不调度的排查

先区分“没被调度”“阻塞等待”“死锁”和“CPU 被打满”。开启 net/http/pprof 或导出 runtime/pprof 的 goroutine、CPU、mutex、block profile，结合 go tool trace 看 runnable/blocked、syscall、GC 和调度延迟；用 GOTRACEBACK=all 获取栈。重点检查 channel 无发送/无接收、未释放 mutex、WaitGroup 计数不匹配、context 未取消、网络 I/O 无 deadline、所有 P 被 CPU/cgo 占用及 goroutine 泄漏。修复应针对证据：补齐退出路径和 deadline、正确 close/Done、缩短临界区、限制并发或拆分 CPU 任务，不能用无条件 runtime.Gosched 掩盖问题。

goroutine

概述

Go 的并发基本单元是 goroutine，类似轻量级线程，但由 Go 运行时（runtime）管理，而不是操作系统。

  • 初始栈约 2KB，OS 线程通常固定 2MB，差距悬殊
  • 栈大小动态伸缩，最大可达 1GB，按需增长
  • 可以同时运行成千上万个 goroutine

比喻：goroutine 就像餐厅里的服务员——你可以同时雇很多人，每人处理不同的桌子，而不需要为每人单独开一家分店（线程）。

创建 goroutine

使用 go 关键字在新的 goroutine 中调用函数：

go funcName()         // 命名函数
go func() { ... }()   // 匿名函数

注意：主 goroutine（main）退出时，所有子 goroutine 会立即终止，无论它们是否执行完毕。

func worker() {
    for i := 0; ; i++ {
        fmt.Printf("worker: i = %d\n", i)
        time.Sleep(1 * time.Second)
    }
}

func main() {
    go worker()
    for i := 0; ; i++ {
        fmt.Printf("main: i = %d\n", i)
        time.Sleep(1 * time.Second)
    }
}

匿名函数 goroutine

goroutine 不能直接接收返回值（需要通过 channel），但可以传参：

go func(a, b int) {
    fmt.Println("a =", a, "b =", b)
}(10, 20)  // 立即传入参数并调用

runtime.Goexit() 退出当前 goroutine（仍会执行所有 defer），而 return 只退出当前函数。

GMP 调度模型

Go 运行时用 GMP 模型调度 goroutine，实现 m:n 调度（n 个 OS 线程上调度 m 个 goroutine）：

角色 含义
G（Goroutine） 并发执行单元
M（Machine） 系统线程
P（Processor） 逻辑处理器，持有本地 G 队列

核心策略：

  1. 复用线程：M 数量有限，P 在 M 上复用执行 G，避免线程频繁创建销毁
  2. 利用并行：多个 P 可同时在不同 M 上运行，充分利用多核 CPU
  3. 抢占调度：长时间运行的 G 会被强制切换，防止一个 G 独占 M
  4. Work Stealing：本地队列空时，P 从全局队列或其他 P 偷取 G

Go 调度器是用户态调度，切换 goroutine 不需要进入内核，代价远低于 OS 线程切换。

GOMAXPROCS

GOMAXPROCS 决定同时执行 Go 代码的 OS 线程数，默认等于 CPU 核心数：

runtime.GOMAXPROCS(2)  // 运行时设置
GOMAXPROCS=1 go run main.go  # 单线程，goroutine 串行切换
GOMAXPROCS=2 go run main.go  # 双线程，goroutine 真正并行

Goroutine 没有 ID

goroutine 故意没有可获取的 ID，以防止 thread-local storage 被滥用。Go 鼓励将所有影响函数行为的信息通过显式参数传递，而不是隐藏在“当前线程”的上下文中。

channel

概述

channel 是 goroutine 之间通信的管道，遵循 Go 的核心理念：

“不要通过共享内存来通信，而应通过通信来共享内存。”

ch := make(chan int)      // 无缓冲 channel，等价于 make(chan int, 0)
ch := make(chan int, 10)  // 有缓冲 channel，容量为 10

无缓冲 channel（Unbuffered Channel）

发送和接收必须同时就绪，否则先到的一方会阻塞等待。

c := make(chan int)  // == make(chan int, 0)

go func() {
    c <- 1234  // 阻塞，直到有人接收
    fmt.Println("sent")
}()

num := <-c  // 阻塞，直到有人发送
fmt.Println("received:", num)

无缓冲 channel 保证了 happens-before：接收者收到数据发生在唤醒发送方 goroutine 之前，两端严格同步。

有缓冲 channel（Buffered Channel）

内部有队列，发送方可先把数据放入缓冲区，不必立即等接收方：

状态 发送 接收
缓冲区未满 不阻塞 —
缓冲区已满 阻塞 —
缓冲区非空 — 不阻塞
缓冲区为空 — 阻塞

比喻：就像快递柜——快递员可以先把包裹放入柜子，不用等你在家；但柜子满了就得等有人取走才能继续放。

c := make(chan int, 3)

go func() {
    for i := 0; i < 3; i++ {
        c <- i
        fmt.Println("sent:", i, "len:", len(c), "cap:", cap(c))
    }
}()

for i := 0; i < 3; i++ {
    fmt.Println("received:", <-c)
}

关闭 channel

使用 close(ch) 关闭 channel：

  • 关闭后不能再发送数据（会 panic）
  • 关闭后仍可接收已缓冲的数据，队列清空后返回零值
  • nil channel（未 make）收发都会永久阻塞
  • 只有发送方应该关闭 channel，接收方不应关闭

接收时用第二个返回值判断是否已关闭：

data, ok := <-c
// ok == true：正常接收到数据
// ok == false：channel 已关闭且无数据
go func() {
    for i := 0; i < 5; i++ {
        c <- i
    }
    close(c)
}()

for {
    if data, ok := <-c; ok {
        fmt.Println(data)
    } else {
        break
    }
}

range 遍历 channel

for range 持续从 channel 读取，直到 channel 被关闭，是上面 ok 写法的简洁替代：

go func() {
    for i := 0; i < 5; i++ {
        c <- i
    }
    close(c)  // 必须关闭，否则 range 永久阻塞
}()

for data := range c {
    fmt.Println(data)
}

单向 channel（Directional Channel）

将 channel 作为函数参数时，通常限定方向，限制将在编译期检查：

  • chan<- int：只发送（write-only）
  • <-chan int：只接收（read-only）

只有发送方可以调用 close，对只接收的 channel 调用 close 是编译错误。

func counter(out chan<- int) {
    for x := 0; x < 100; x++ {
        out <- x
    }
    close(out)
}

func squarer(out chan<- int, in <-chan int) {
    for v := range in {
        out <- v * v
    }
    close(out)
}

func printer(in <-chan int) {
    for v := range in {
        fmt.Println(v)
    }
}

func main() {
    naturals := make(chan int)
    squares := make(chan int)
    go counter(naturals)
    go squarer(squares, naturals)
    printer(squares)
}

双向 channel 可以隐式转换为单向 channel，但反向转换不允许。

select 多路复用

select 同时监听多个 channel，类似 switch，但每个 case 必须是 channel 操作：

  • 有多个 case 就绪时，随机选择一个执行
  • 无 case 就绪且有 default 时，执行 default（非阻塞轮询）
  • 无 case 就绪且无 default 时，阻塞等待
select {
case v := <-ch1:
    fmt.Println("from ch1:", v)
case ch2 <- 42:
    fmt.Println("sent to ch2")
default:
    fmt.Println("no channel ready")
}

nil channel 在 select 中永远不会被选中，可以用来动态禁用某个 case。

select{}  // 空 select，永久阻塞，常用于防止 main 退出

用 select 生成 Fibonacci 数列：

func fibonacci(c, quit chan int) {
    x, y := 1, 1
    for {
        select {
        case c <- x:
            x, y = y, x+y
        case <-quit:
            fmt.Println("quit")
            return
        }
    }
}

func main() {
    c := make(chan int)
    quit := make(chan int)
    go func() {
        for i := 0; i < 6; i++ {
            fmt.Println(<-c)
        }
        quit <- 0
    }()
    fibonacci(c, quit)
}

并发的循环

启动多个 goroutine 并等待全部完成，最简单的方式是用一个 done channel 计数：

done := make(chan struct{})
for i := 0; i < N; i++ {
    go func() {
        // 大任务
        done <- struct{}{}
    }()
}
for range N {
    <-done
}

更推荐使用标准库的 sync.WaitGroup（见下文）。

channel 实现锁

package main

import (
   "fmt"
   "time"
)

func add(ch chan bool, num *int) {
   ch <- true
   *num = *num + 1
   <-ch
}

func main() {
   // 创建一个size为1的channel
   ch := make(chan bool, 1)

   var num int
   for i := 0; i < 100; i++ {
      go add(ch, &num)
   }

   time.Sleep(2)
   fmt.Println("num 的值：", num)
}

ch <- true 和 <-ch 实现了 sync.Lock() 的功能

共享变量 sync

竞态条件（Race Condition）

并发安全：函数在并发情况下依然能给出正确结果，无需调用方额外同步。

数据竞争：两个 goroutine 并发访问同一变量，且至少一个是写操作。

解决方法：

  1. 消除写操作：变量初始化后只读
  2. 单一 goroutine 访问：其他 goroutine 通过 channel 通信
  3. 互斥锁：允许多个 goroutine 访问，但同一时刻最多 1 个

检测竞态：在编译/运行/测试时加 -race 标记：

go run -race main.go
go test -race ./...

sync.Mutex 互斥锁

Lock 获取锁，Unlock 释放锁，两者之间的代码段称为临界区：

var (
    mu    sync.Mutex
    total int
)

func Add(n int) {
    mu.Lock()
    defer mu.Unlock()
    total += n
}

func Get() int {
    mu.Lock()
    defer mu.Unlock()
    return total
}

注意：sync.Mutex 不可重入。同一 goroutine 对已持有的锁再次 Lock 会死锁。解决方法是将加锁的逻辑和不加锁的内部逻辑拆分：

// 导出函数：负责加锁
func Withdraw(amount int) bool {
    mu.Lock()
    defer mu.Unlock()
    deposit(-amount)  // 调用不加锁的内部函数
    if balance < 0 {
        deposit(amount)
        return false
    }
    return true
}

// 内部函数：调用方需已持有锁
func deposit(amount int) { balance += amount }
func main() {
    var mu sync.Mutex
    mu.Lock()
    defer mu.Unlock()
    copyMutex(mu)
}

func copyMutex(mu sync.Mutex) {
    mu.Lock()
    defer mu.Unlock()
    fmt.Println("ok")
}

锁拷贝时会复制当前状态，拷贝一个 Lock() 的锁，该锁仍然为 Lock() 状态，所以会导致死锁，需要避免进行锁拷贝

sync.RWMutex 读写锁

允许多个读并发执行，但写独占（多读单写）：

var mu sync.RWMutex

func Get() int {
    mu.RLock()
    defer mu.RUnlock()
    return total
}

func Set(n int) {
    mu.Lock()
    defer mu.Unlock()
    total = n
}

RLock 只适用于临界区内没有写操作的情况。读多写少时，RWMutex 比 Mutex 性能更好。

  • 读写锁、写写锁互斥
  • 读读锁可同时加

sync.Once 惰性初始化

将高成本的初始化推迟到第一次使用时，且保证只执行一次、对所有 goroutine 可见：

var (
    loadOnce sync.Once
    data     map[string]string
)

func GetData(name string) string {
    loadOnce.Do(loadData)  // 只有第一次调用会执行 loadData
    return data[name]
}

Do 内部用互斥锁 + bool 标志实现：Go 1.9 起优先检查 bool 标志，避免每次都加锁。

init() 是其所在 package 首次加载时就执行，sync.Once 是第一次调用时才会出实话

sync.WaitGroup 等待组

比手写 done channel 更符合惯用法，用于等待一组 goroutine 全部完成：

func count(filenames <-chan string) int64 {
    sizes := make(chan int64)
    var wg sync.WaitGroup

    for f := range filenames {
        wg.Add(1)  // 必须在 go 语句之前调用
        go func(filename string) {
            defer wg.Done()  // == wg.Add(-1)
            // 处理文件...
            sizes <- size
        }(f)
    }

    go func() {
        wg.Wait()
        close(sizes)
    }()

    var total int64
    for size := range sizes {
        total += size
    }
    return total
}

wg.Add(1) 必须在启动 goroutine 之前调用，否则可能在 goroutine 还未注册时 Wait 就返回了。

  • (wg *WaitGroup) Add(delta int)：计数器加 delta
  • (wg *WaitGroup) Done(delta int)：计数器减一。不能令计数器小于 0，否则会产生 panic
  • (wg *WaitGroup) Wait(delta int)：阻塞代码运行直到计数器减为 0

sync.Map

普通 map 不能被多个 goroutine 同时读写，可以自行加锁封装函数，或者使用 sync.Map 并发安全的 Map

  • Store()
  • Load()
  • Range()
  • Delete()
  • LoadOrStore()
func main() {
	// 声明即可使用，不需要make分配
	var m sync.Map
	// 1. 写入
	m.Store("name", "musuyin")
	m.Store("age", 21)

	// 2. 读取
	age, _ := m.Load("age")
	fmt.Println(age.(int))

	// 3. 遍历
	m.Range(func(key, value interface{}) bool {
		fmt.Printf("key is:%v, val is:%v\n", key, value)
		return true
	})

	// 4. 删除
	m.Delete("age")
	age, ok := m.Load("age")
	fmt.Println(age, ok)

	// 5. 读取或写入
	m.LoadOrStore("name", "musuyin")
	name, _ := m.Load("name")
	fmt.Println(name)
}

没有原生 len() 方法，需要使用 Range() 配合函数获取数量

原子操作 sync/atomic

  • mutex 用于保护一段执行逻辑
    • 底层由操作系统调度器实现
  • atomic 对变量进行操作
    • 底层由硬件指令支持，保证在 CPU 上执行不中断

方法

// T的类型是int32、int64、uint32、uint64和uintptr中的任意一种
func AddT(addr *T, delta T)(new T)
func StoreT(addr *T, val T)
func LoadT(addr *T) (val T)
func SwapT(addr *T, new T) (old T)
func CompareAndSwapT(addr *T, old, new T) (swapped bool)
package main

import (
   "fmt"
   "sync"
   "sync/atomic"
)

func main() {

   var sum int32 =  0
   var wg sync.WaitGroup
   for i := 0; i < 100; i++ {
      wg.Add(1)
      go func() {
         defer wg.Done()
         atomic.AddInt32(&sum, 1)
      }()
   }
   wg.Wait()
   fmt.Printf("sum is %d\n",sum)
}

atomic.value

上面的方法只对基础基本类型做保护，使用 atomic.value 可以支持任意接口类型

方法 函数签名 作用
Load() func (v *Value) Load() (val any)
Store() func (v *Value) Store(val any)
Swap() func (v *Value) Swap(new any) (old any) 用 new 替换数据，返回 old
CompareAndSwap() func (v *Value) CompareAndSwap(old, new any) (swapped bool) 比较 value 中存储的数据和 old 是否相同，若相同则替换为 new 
package main

import (
    "fmt"
    "sync/atomic"
)

type Student struct {
    Name string
    Age  int
}

func main() {
    st1 := Student{
       Name: "zhangsan",
       Age:  18,
    }
    st2 := Student{
       Name: "lisi",
       Age:  19,
    }
    st3 := Student{
       Name: "wangwu",
       Age:  20,
    }
    var v atomic.Value
    v.Store(st1)
    fmt.Println(v.Load().(Student))

    old := v.Swap(st2)
    fmt.Printf("after swap: v=%v\n", v.Load().(Student))
    fmt.Printf("after swap: old=%v\n", old)

    swapped := v.CompareAndSwap(st1, st3)   // v中存储的和st1不相同，交换失败
    fmt.Println("compare st1 and v\n", swapped, v)

    swapped = v.CompareAndSwap(st2, st3)   // v中存储的和st2相同，交换成功，v中变为st3
    fmt.Println("compare st2 and v\n", swapped, v)
}

内存池 sync.Pool

  • 实现对象的复用，避免创建相同的对象，降低 GC 的消耗
  • 池子中的对象在一定随机时间后会被回收，不能进行持久化存储
  • 并发安全，支持多个 goroutine 同时读写数据

使用

方法 作用
New() sync.Pool 的构造函数，用于指定 sync.Pool 中缓存的数据类型，当调用 Get 方法时会从对象池中获取对象，如果
Get() 从对象池中获取对象
Put() 往对象池放对象，下次 Get 时可以复用 
package main

import (
    "fmt"
    "sync"
)

type Student struct {
    Name string
    Age  int
}

func main() {
    pool := sync.Pool{
       New: func() interface{} {
          return &Student{
             Name: "musuyin",
             Age:  21,
          }
       },
    }

    st := pool.Get().(*Student)
    println(st.Name, st.Age)
    fmt.Printf("addr is %p\n", st)

    pool.Put(st)

    st1 := pool.Get().(*Student)
    println(st1.Name, st1.Age)
    fmt.Printf("addr1 is %p\n", st1)
}

使用 Get 取出对象后，如果在 Put 前发生了修改，则需要执行 Reset 将对象的值复原，否则下次 Get 取出的对象就不是复用对象（从逻辑上来讲不是复用对象，因为各个 goroutine 之间获取对象包含的值就不同了，但获取的对象是同一个）

Context

Go 1.7 新增的标准库接口

type Context interface {
   Deadline() (deadline time.Time, ok bool)
   Done() <-chan struct{}
   Err() error
   Value(key interface{}) interface{}
}
方法 作用
Deadline 设置 context.Context 被取消的时间，即截止时间
Done 返回一个只读 channel，当 Context 被取消或者到达截止时间，就会关闭这个 channel，表示 Context 的链路结束，多次调用 Done 方法会返回同一个 channel
Err 返回 context.Context 结束的原因，只有在 Done 返回的 channel 被关闭时才会返回非空值
- 若 context.Context 被取消，返回 Canceled
- 若 context.Context 超时，返回 DeadlineExceeded
Value 从 context.Context 中获取键对应的值，对于同一个 context，多次调用 Value 并传入相同的 key 会返回相同的结果。如果没有对应的 key，则返回 nil。键值对是通过 WithValue 的方法写入的

创建 Context

根 Context 创建

context.Background()
context.TODO()

两种方法没有区别，都是返回一个空的 context（根 context）。一般如果没有上下文作为入参，都会使用 context.Background() 创建一个根 context 作为起始上下文向下传递

Context 派生

根 context 创建之后，还不具备任何功能，需要使用 WithXxx 系列函数来进行派生

func WithCancel(parent Context) (ctx Context, cancel CancelFunc)
func WithDeadline(parent Context, deadline time.Time) (Context, CancelFunc)
func WithTimeout(parent Context, timeout time.Duration) (Context, CancelFunc)
func WithValue(parent Context, key, val interface{}) Context

父 context 可以调用产生子 context，最后形成一棵 context 树

作用

  1. 并发控制，控制协程的优雅退出
  2. 上下文的信息传递

即用于父子 goroutine 之间进行值传递和 cancel 信号发送

并发控制

例如：对于一个需要长调用链条的服务，会创建很多 goroutine 进行处理，且各个 goroutine 之间存在依赖关系

当没有 context 时，则需要所有服务调用完毕，才会返回结果，如果中间链条发生错误，则会有时间浪费。

所以可以使用 context 提前结束

context.WithCancel

context.WithCancel 是一个取消控制函数

  • 只需要一个 context 作为参数，能够从 context.Context 中衍生出一个新的子 context 和取消函数 CancelFunc
  • 通过将这个子 context 传递到新的 goroutine 中来控制这些 goroutine 的关闭，一旦执行返回的取消函数，当前上下文及其子上下文都会被取消，所有 goroutine 都会同步收到取消信号
// func WithCancel(parent Context) (ctx Context, cancel CancelFunc)

package main

import (
	"context"
	"fmt"
	"time"
)

func main() {
	ctx, cancel := context.WithCancel(context.Background())
	go Watch(ctx, "goroutine1")
	go Watch(ctx, "goroutine2")

	time.Sleep(6 * time.Second) // 让goroutine1和goroutine2执行6s
	fmt.Println("end watching!!!")
	cancel() // 通知goroutine1和goroutine2关闭
	time.Sleep(1 * time.Second)
}

func Watch(ctx context.Context, name string) {
	for {
		select {
		case <-ctx.Done():
			fmt.Printf("%s exit!\n", name) // 主goroutine调用cancel后，会发送一个信号到ctx.Done()这个channel，这里就会收到信息
			return
		default:
			fmt.Printf("%s watching...\n", name)
			time.Sleep(time.Second)
		}
	}
}

context.WithDeadline

context.WithDeadline 也是一个取消控制函数

  • 方法有两个参数，第一个参数是一个 context，第二个参数是截止时间，同样会返回一个子 context 和一个取消函数 CancelFunc
  • 在使用的时候
    • 如果没有到截止时间，可以通过手动调用 CancelFunc 来取消子 context，控制子 goroutine 的退出
    • 如果到了截止时间都没有调用 CancelFunc，子 context 的 Done() 管道也会收到一个取消信号，用来控制子 goroutine 退出。
// func WithDeadline(parent Context, d time.Time) (Context, CancelFunc)

package main

import (
	"context"
	"fmt"
	"time"
)

func main() {
	ctx, cancel := context.WithDeadline(context.Background(), time.Now().Add(4*time.Second)) // 设置超时时间4当前时间4s之后
	defer cancel()
	go Watch(ctx, "goroutine1")
	go Watch(ctx, "goroutine2")

	time.Sleep(6 * time.Second) // 让goroutine1和goroutine2执行6s
	fmt.Println("end watching!!!")
}

func Watch(ctx context.Context, name string) {
	for {
		select {
		case <-ctx.Done():
			fmt.Printf("%s exit!\n", name) // 4s之后收到信号
			return
		default:
			fmt.Printf("%s watching...\n", name)
			time.Sleep(time.Second)
		}
	}
}

context.WithTimeout

context.WithTimeout 和 context.WithDeadline 的作用类似，都是用于超时取消子 context，只是传递的第二个参数有所不同，context.WithTimeout 传递的第二个参数不是具体时间，而是时间长度。

// func WithTimeout(parent Context, timeout time.Duration) (Context, CancelFunc)

package main

import (
	"context"
	"fmt"
	"time"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 4*time.Second)
	defer cancel()
	go Watch(ctx, "goroutine1")
	go Watch(ctx, "goroutine2")

	time.Sleep(6 * time.Second) // 让goroutine1和goroutine2执行6s
	fmt.Println("end watching!!!")
}

func Watch(ctx context.Context, name string) {
	for {
		select {
		case <-ctx.Done():
			fmt.Printf("%s exit!\n", name) // 主goroutine调用cancel后，会发送一个信号到ctx.Done()这个channel，这里就会收到信息
			return
		default:
			fmt.Printf("%s watching...\n", name)
			time.Sleep(time.Second)
		}
	}
}

context.WithValue

context.WithValue 函数从父 context 中创建一个子 context 用于传值，函数参数是父 context，key，val 键值对。返回一个 context。

项目中这个方法一般用于上下文信息的传递，比如请求唯一 id，以及 trace_id 等，用于链路追踪以及配置透传。

// func WithValue(parent Context, key, val interface{}) Context
package main

import (
   "context"
   "fmt"
   "time"
)

func func1(ctx context.Context) {
   fmt.Printf("name is: %s", ctx.Value("name").(string))
}

func main() {
   ctx := context.WithValue(context.Background(), "name", "zhangsan")
   go func1(ctx)
   time.Sleep(time.Second)
}

协程池

协程池模型

属性 作用
Pool 线程池
Task 具体的任务
Worker 执行任务的 goroutine

Pool

type Pool struct {
	RunningWorkers int64
	Capacity       int64      // goroutine数量
	JobCh          chan *Task // 用于worker取任务
	sync.Mutex
}
  • Capacity：Worker 数量
  • JobCh：任务队列

Task

type Task struct {
	f func() error
}

Worker

// p为Pool对象指针
for task := range p.JobCh {
    do ...
}

Worker 不断从任务队列中获取任务，然后执行

方法定义

NewTask 用于创建一个任务，参数是一个函数，返回值是一个 Task 类型。

func NewTask(funcArg func() error) *Task

NewPool 返回一个协程数量固定为 workerNum 协程池对象指针，其任务队列的长度为 taskNum。

func NewPool(Capacity int, taskNum int) *Pool

AddTask 方法是往协程池添加任务，如果当前运行着的 worker 数量小于协程池 worker 容量，则立即启动一个协程 worker 来处理任务，否则将任务添加到任务队列。

func (p *Pool) AddTask(task *Task)

Run() 将协程池跑起来，启动一个 worker 来处理任务。

func (p *Pool) Run()

实现示例

package main

import (
	"fmt"
	"sync"
	"sync/atomic"
	"time"
)

type Task struct {
	f func() error // 具体的任务逻辑
}

func NewTask(funcArg func() error) *Task {
	return &Task{
		f: funcArg,
	}
}

type Pool struct {
	RunningWorkers int64      // 运行着的worker数量
	Capacity       int64      // 协程池worker容量
	JobCh          chan *Task // 用于worker取任务
	sync.Mutex
}

func NewPool(capacity int64, taskNum int) *Pool {
	return &Pool{
		Capacity: capacity,
		JobCh:    make(chan *Task, taskNum),
	}
}

func (p *Pool) GetCap() int64 {
	return p.Capacity
}

func (p *Pool) incRunning() { // runningWorkers + 1
	atomic.AddInt64(&p.RunningWorkers, 1)
}

func (p *Pool) decRunning() { // runningWorkers - 1
	atomic.AddInt64(&p.RunningWorkers, -1)
}

func (p *Pool) GetRunningWorkers() int64 {
	return atomic.LoadInt64(&p.RunningWorkers)
}

func (p *Pool) run() {
	p.incRunning()
	go func() {
		defer func() {
			p.decRunning()
		}()
		for task := range p.JobCh {
			task.f()
		}
	}()
}

// AddTask 往协程池添加任务
func (p *Pool) AddTask(task *Task) {
	// 加锁防止启动多个 worker
	p.Lock()
	defer p.Unlock()

	if p.GetRunningWorkers() < p.GetCap() { // 如果任务池满, 则不再创建 worker
		// 创建启动一个 worker
		p.run()
	}

	// 将任务推入队列, 等待消费
	p.JobCh <- task
}

func main() {
	// 创建任务池
	pool := NewPool(3, 10)

	for i := 0; i < 20; i++ {
		// 任务放入池中
		pool.AddTask(NewTask(func() error {
			fmt.Printf("I am Task\n")
			return nil
		}))
	}

	time.Sleep(1e9) // 等待执行
}
