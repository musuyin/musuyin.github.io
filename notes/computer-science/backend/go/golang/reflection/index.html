Go 反射

2025-03-02

#Go#反射

反射让程序在运行时观察类型、字段与方法，并在值可设置时修改它。先掌握接口的动态类型和值，再按“接口到反射、反射到接口、可设置性”理解示例；运行时内部结构不等于语言规范承诺。

反射的基础：interface 的内部结构

Go 的 interface 底层有两种数据结构：eface 和 iface。

eface 是空 interface{}的实现，只包含两个指针：_type 指向类型信息，data 指向实际数据。这就是为什么空接口能存储任意类型值的原因，通过类型指针来标识具体类型，通过数据指针来访问实际值。

type eface struct {
   _type *_type
   data  unsafe.Pointer
}

iface 是带方法的 interface 实现，包含 itab 和 data 两部分。itab 是核心，它存储了接口类型、具体类型，以及方法表。方法表是个函数指针数组，保存了该类型实现的所有接口方法的地址。

type iface struct {
   tab  *itab
   data unsafe.Pointer
}

type itab struct {
   inter *interfacetype
   _type *_type
   hash  uint32 // copy of _type.hash. Used for type switches.
   _     [4]byte
   fun   [1]uintptr // variable sized. fun[0]==0 means _type does not implement inter.
}

区别

iface 和 eface 的核心区别在于是否包含方法信息。

  • eface 是空接口 interface{}的底层实现，结构非常简单，只有两个字段：_type 指向类型信息，data 指向实际数据。因为空接口没有方法约束，所以不需要存储方法相关信息。
  • iface 是非空接口的底层实现，结构相对复杂，包含 itab 和 data。关键是这个 itab，它不仅包含类型信息，还包含了一个方法表，存储着该类型实现的所有接口方法的函数指针。

使用

// a 的 pair: <type: string, value: "Musuyin">
var a string = "Musuyin"

// allType 的 pair: <type: nil, value: nil>
var allType interface{}

// 赋值时 pair 一并传递: <type: string, value: "Musuyin">
allType = a

// 类型断言：根据 pair 中的 type 取出 value
str, _ := allType.(string)
fmt.Println(str) // "Musuyin"

接口间的类型断言

当一个具体类型实现了多个接口时，pair 在接口变量之间传递不会丢失：

type Writer interface { WriteBook() }
type Reader interface { ReadBook() }

type Book struct{}
func (this *Book) WriteBook() { fmt.Println("WriteBook") }
func (this *Book) ReadBook()  { fmt.Println("ReadBook") }

func main() {
    // b 的 pair: <type: *Book, value: &Book{}>
    b := &Book{}

    var r Reader
    r = b           // r 的 pair: <type: *Book, value: &Book{}>
    r.ReadBook()

    var w Writer
    w = r.(Writer)  // 断言成功：pair 中的 *Book 实现了 Writer
    w.WriteBook()
}

类型转换、类型断言 本质都是把一个类型转换成另外一个类型。不同之处在于，类型断言是对接口变量进行的操作。对于类型转换而言，类型转换是在编译期确定的强制转换，转换前后的两个类型要相互兼容才行，语法是 T(value)。而类型断言是运行期的动态检查，专门用于从接口类型中提取具体类型，语法是 value.(T)

断言能否成功取决于 pair 中的具体类型是否实现了目标接口，而不是当前接口变量的声明类型。这就是为什么 r.(Writer) 能成功——因为 r 里装的是 *Book，而 *Book 同时实现了 Reader 和 Writer。

反射

反射是指计算机程序在运行时（Run time）可以访问、检测和修改它本身状态或行为的一种能力。用比喻来说，反射就是程序在运行的时候能够“观察”并且修改自己的行为。

reflect 包

reflect 包提供了在运行时检查 interface 内部 pair 的能力：

  • reflect.TypeOf(x) → 获取 type
  • reflect.ValueOf(x) → 获取 value

基本类型

func reflectNum(arg interface{}) {
    fmt.Println("value:", reflect.ValueOf(arg))  // 3.14159
    fmt.Println("type:", reflect.TypeOf(arg))    // float64
}

func main() {
    var num float64 = 3.14159
    reflectNum(num)
}

结构体的反射

对结构体可以遍历其字段和方法：

type User struct {
    Id   int
    Name string
    Age  int
}

func (this User) Call() {
    fmt.Println("user is called")
    fmt.Printf("%v\n", this)
}

获取字段

通过 reflect.Type 的 NumField() 遍历字段，通过 reflect.Value 的 Field(i).Interface() 获取字段值：

func DoFieldAndMethod(input interface{}) {
    inputType := reflect.TypeOf(input)
    inputValue := reflect.ValueOf(input)

    for i := 0; i < inputType.NumField(); i++ {
        field := inputType.Field(i)
        value := inputValue.Field(i).Interface()
        fmt.Printf("%s: %v = %v\n", field.Name, field.Type, value)
    }
}

输出：

Id: int = 1
Name: string = Musuyin
Age: int = 19

获取方法

通过 NumMethod() 遍历方法（只能获取导出方法）：

for i := 0; i < inputType.NumMethod(); i++ {
    m := inputType.Method(i)
    fmt.Printf("%s: %v\n", m.Name, m.Type)
}

输出：

Call: func(main.User)

注意：如果方法的 receiver 是指针类型（*User），那么传入 reflect.TypeOf 的也必须是指针，否则找不到这些方法。

对象比较

  • 用 reflect.DeepEqual，这是标准库提供的深度比较方法，能递归比较结构体、切片、map 等复合类型的所有字段和元素。比如 reflect.DeepEqual(obj1, obj2)，它会逐层比较内部所有数据，包括指针指向的值。
  • 对于简单类型可以直接用 == 操作符，但这只适合基本类型、数组、结构体等可比较类型。需要注意 slice、map、function 这些类型是不能直接用 == 比较的，会编译报错。
  • 实际项目中更推荐自定义 Equal 方法，根据业务需求定义相等的标准。比如对于用户对象，可能只需要比较 ID 和关键字段，而不需要比较时间戳这种辅助字段。这样既提高了性能，又符合业务语义。

结构体标签（Struct Tag）

结构体标签是附加在字段上的元数据字符串，通过反射读取。主要用途：

  • JSON 序列化是最常见的应用，像 encoding/json 包通过反射动态获取结构体字段信息，实现任意类型的序列化和反序列化。这也是为什么我们能直接用 json.Marshal 处理各种自定义结构体的原因。
  • ORM 框架是另一个重点应用，比如 GORM 通过反射分析结构体字段，自动生成 SQL 语句和字段映射。它能动态读取 struct tag 来确定数据库字段名、约束等信息，大大简化了数据库操作。
  • Web 框架的参数绑定也大量使用反射，像 Gin 框架的 ShouldBind 方法，能够根据请求类型自动将 HTTP 参数绑定到结构体字段上，这背后就是通过反射实现的类型转换和赋值。
  • 还有配置文件解析、RPC 调用、测试框架等场景。比如 Viper 配置库用反射将配置映射到结构体，gRPC 通过反射实现服务注册和方法调用。

标签的读取

标签格式为 `key:"value" key2:"value2"`，通过反射的 Tag.Get(key) 读取：

type resume struct {
    Name   string `info:"name" doc:"myName"`
    Gender string `info:"sex"`
}

func findTag(str interface{}) {
    t := reflect.TypeOf(str).Elem()
    for i := 0; i < t.NumField(); i++ {
        tagInfo := t.Field(i).Tag.Get("info")
        tagDoc := t.Field(i).Tag.Get("doc")
        fmt.Println("info:", tagInfo, "doc:", tagDoc)
    }
}

func main() {
    var re resume
    findTag(&re)
}

输出：

info: name doc: myName
info: sex doc:

传入 &re（指针）是因为 Elem() 需要解引用——它从指针类型获取其指向的元素类型。

JSON 中的标签应用

encoding/json 包通过 json 标签控制序列化/反序列化时的字段名：

type Movie struct {
    Title string `json:"title"`
    Year  int    `json:"year"`
}

func main() {
    movie := Movie{"BigBoss", 1099}

    // 结构体 → JSON
    jsonStr, err := json.Marshal(movie)
    // jsonStr = {"title":"BigBoss","year":1099}

    // JSON → 结构体
    var myMovie Movie
    err = json.Unmarshal(jsonStr, &myMovie)
    // myMovie = {BigBoss 1099}
}

常用 json 标签选项

标签 作用
`json:"name"` 指定 JSON 字段名
`json:"-"` 忽略该字段，不参与序列化
`json:"name,omitempty"` 零值时省略该字段
`json:",string"` 将数值类型序列化为字符串

反射的三大法则

  1. 从 interface 到反射对象：reflect.TypeOf / reflect.ValueOf 将 interface 转为反射对象
  2. 从反射对象到 interface：reflect.Value.Interface() 将反射对象转回 interface
  3. 修改反射对象的值必须可寻址：只有通过指针获取的 reflect.Value 才能调用 Set 方法修改值
// 法则3 示例：修改变量的值
var x float64 = 3.4
v := reflect.ValueOf(&x)  // 必须传指针
v.Elem().SetFloat(7.1)    // Elem() 获取指针指向的值
fmt.Println(x)            // 7.1

如果直接 reflect.ValueOf(x).SetFloat(7.1) 会 panic——因为传入的是值的副本，修改副本没有意义，Go 直接禁止了这种操作。
