#Go#测试

Go 测试通过 _test.go 文件和约定的函数签名接入工具链。表驱动测试组织输入与预期，覆盖率定位未执行路径，基准测试与 profile 解释性能；这些证据不能互相替代。

测试文件

go test 命令是 Go 语言内置的测试驱动程序。在包目录内，所有以 _test.go 为后缀的源文件都属于测试代码，不会被 go build 编译到最终的可执行文件中。

*_test.go 文件中有三种类型的函数：

类型 作用 函数前缀
单元测试函数 测试程序逻辑行为是否正确 Test
基准测试函数 测试函数的性能 Benchmark
示例函数 为文档提供使用示例 Example

go test 会遍历所有 *_test.go 文件中符合命名规则的函数，生成一个临时的 main 包来调用测试函数，构建并运行、报告结果，最后清理临时文件。

命名约束：

  1. 文件名必须以 _test.go 结尾
  2. 测试函数名必须匹配 Test[^a-z]（即 Test 后接大写字母）
  3. 参数必须是 t *testing.T

命令参数

go test [-c] [-i] [build flags] [packages] [flags for test binary]

常用参数：

参数 作用
-c 编译测试为可执行二进制文件，但不运行
-i 安装测试依赖包，但不运行
-v 打印每个测试函数的名字和运行时间
-run <regex> 只运行函数名匹配正则表达式的测试
-count N 运行测试 N 次（禁用缓存可用 -count=1）
-timeout 设置测试超时时间（默认 10 分钟）

例：只运行名字包含 “Add” 的测试：go test -v -run Add

测试函数

每个测试函数必须导入 testing 包：

func TestName(t *testing.T) {
    // ...
}

testing.T 的常用方法：

方法 作用 是否终止当前测试
t.Log(args...) 输出日志信息 否
t.Logf(fmt, args...) 格式化输出日志 否
t.Error(args...) 标记失败并记录日志 否
t.Errorf(fmt, args...) 标记失败并格式化记录 否
t.Fatal(args...) 标记失败并立即终止 是
t.Fatalf(fmt, args...) 标记失败并格式化记录后立即终止 是
t.Skip(args...) 跳过当前测试 是
t.Run(name, f) 运行子测试 否
t.Parallel() 标记为可并行执行 否

Error 系列会继续执行后续代码，适合一次性检查多个条件；Fatal 系列立即停止，适合前置条件失败后续无意义的场景。

测试方法

表驱动测试（Table-Driven Test）

将测试数据组织为一张表（slice of struct），循环遍历执行。这是 Go 中最推荐的测试模式：

func TestIsPalindrome(t *testing.T) {
    tests := []struct {
        input string
        want  bool
    }{
        {"", true},
        {"a", true},
        {"aa", true},
        {"ab", false},
        {"kayak", true},
        {"detartrated", true},
        {"palindrome", false},
    }
    for _, tt := range tests {
        if got := IsPalindrome(tt.input); got != tt.want {
            t.Errorf("IsPalindrome(%q) = %v, want %v", tt.input, got, tt.want)
        }
    }
}

表驱动测试的好处：新增用例只需要加一行数据，不需要改测试逻辑。就像一张试卷上的多道选择题，答题逻辑一致，只是输入不同。

结合子测试（Subtest）

使用 t.Run 可以为每个用例命名，失败时更容易定位：

for _, tt := range tests {
    t.Run(tt.input, func(t *testing.T) {
        if got := IsPalindrome(tt.input); got != tt.want {
            t.Errorf("got %v, want %v", got, tt.want)
        }
    })
}

随机测试

通过构造随机输入来探索函数边界行为。校验方式有两种：

  1. 对照函数法：用一个简单但正确的实现作为参考，比较两者输出
  2. 构造已知答案法：生成满足某种模式的输入，答案可以从生成过程推导
func randomPalindrome(rng *rand.Rand) string {
    n := rng.Intn(25)
    runes := make([]rune, n)
    for i := 0; i < (n+1)/2; i++ {
        r := rune(rng.Intn(0x1000))
        runes[i] = r
        runes[n-1-i] = r
    }
    return string(runes)
}

func TestRandomPalindromes(t *testing.T) {
    seed := time.Now().UTC().UnixNano()
    t.Logf("Random seed: %d", seed)
    rng := rand.New(rand.NewSource(seed))

    for i := 0; i < 1000; i++ {
        p := randomPalindrome(rng)
        if !IsPalindrome(p) {
            t.Errorf("IsPalindrome(%q) = false", p)
        }
    }
}

记录 seed 非常重要——一旦测试失败，可以用相同 seed 复现。

白盒测试（White Box / Clear Box）

  • 黑盒测试：只测试包的公开 API，不关心内部实现
  • 白盒测试：可以访问包内部的未导出函数和变量，测试内部逻辑

由于测试文件和被测代码在同一个包内，Go 天然支持白盒测试。

go test 命令不会并发执行同一个包内的多个测试函数（除非显式调用 t.Parallel()），因此在测试中修改包级全局变量是安全的。

外部测试包

当测试需要导入被测包的依赖包，而该依赖包又反过来依赖被测包时，会产生循环导入。解决方案是使用外部测试包：

// 文件：fmt_test.go
package fmt_test  // 注意：包名是 fmt_test，不是 fmt

import "fmt"

外部测试包特别适合编写集成测试。

测试覆盖率

go test -coverprofile=coverage.out    # 生成覆盖率数据
go tool cover -html=coverage.out      # 浏览器中查看可视化报告
go test -cover                        # 简单输出覆盖率百分比

覆盖率高不代表测试质量高——100% 覆盖率但只检查“不 panic”是不够的。关注的应该是断言的质量，而非行覆盖率数字。

基准测试

基准测试（Benchmark）用于测量函数在固定工作负载下的性能：

func BenchmarkIsPalindrome(b *testing.B) {
    for i := 0; i < b.N; i++ {
        IsPalindrome("A man, a plan, a canal: Panama")
    }
}

关键点：

  • 函数前缀为 Benchmark，参数为 *testing.B
  • b.N 由框架动态调整，保证运行足够长时间以获得稳定结果
  • 默认不运行，需要 -bench 标志
go test -bench=.                 # 运行所有基准测试
go test -bench=IsPalindrome      # 只运行匹配的基准测试
go test -bench=. -benchmem       # 同时报告内存分配信息

-bench 后的参数是正则表达式，. 表示匹配所有。不需要写 Benchmark 前缀。

性能剖析（Profiling）

Go 内置三种 profiling 模式：

类型 标志 检测目标
CPU 剖析 -cpuprofile=cpu.out 最耗 CPU 时间的函数
内存剖析 -memprofile=mem.out 最耗内存的语句
阻塞剖析 -blockprofile=block.out 阻塞 goroutine 最久的操作 
go test -cpuprofile=cpu.out
go tool pprof cpu.out            # 交互式分析

工作原理：

  • CPU 剖析：OS 每隔几毫秒中断一次，记录当前执行的函数调用栈
  • 内存剖析：平均每分配 512KB 内存记录一次调用栈
  • 阻塞剖析：记录 goroutine 被系统调用、channel、锁等阻塞的事件
