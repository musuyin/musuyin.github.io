Go 命令行工具

2025-02-15

#Go

初始化模块与整理依赖

在项目目录创建模块，模块路径通常对应代码导入路径：

go mod init github.com/username/project

通用形式是 go mod init module_path，会生成 go.mod。Go 1.11 引入 Modules；早期版本的启用行为与现代工具链不同。

go mod tidy              # 根据源码整理依赖
go mod download          # 下载依赖到本地缓存
go mod vendor            # 将依赖复制到 vendor 目录
go get package@version   # 添加或更新依赖版本

先在源码中声明所需导入，再用 tidy 补齐需求并清除未使用的模块需求。安装远程命令行工具则看后面的 go install。

运行与构建

开发时用 go run 完成临时编译并立即执行：

go run main.go
go run .
go run ./cmd/app
go run main.go arg1 arg2

其中 . 和 ./cmd/app 指向包目录，最后一行把参数传给程序。需要保留构建产物时使用 go build；以下命令以可执行的 main 包为前提：

go build
go build -o myapp
go build main.go

-o 指定输出名，-v 显示编译的包，-ldflags 把参数传给链接器。例如：

go build -ldflags="-s -w"

交叉编译

以下环境变量前缀语法适用于 Bash 等 shell；PowerShell 需要用自己的环境变量赋值语法：

GOOS=linux GOARCH=amd64 go build -o myapp-linux
GOOS=windows GOARCH=amd64 go build -o myapp.exe

目标平台、架构及 cgo 依赖可能影响交叉编译条件，应在目标环境验证产物。

安装工具与查询文档

go install
go install github.com/tool/cmd@latest

第二条中的路径是待替换的工具路径。可执行文件优先安装到 GOBIN，未设置时通常在 GOPATH/bin；把相应目录加入 PATH 才能直接调用。

go doc 打印实体声明与文档注释。原稿给出的查询示例为：

go doc ti

这里的 ti 需要是当前可解析的包或符号；实际使用时替换为要查的名称。

格式化、检查与测试

go fmt ./...
go vet ./...
go test ./...
go clean

fmt 格式化包源码，vet 做静态检查，test 执行测试。go clean 用于清理相关构建文件；清理构建缓存需要显式使用 go clean -cache，不能把无参数命令解释为清空所有缓存。

  • 跨平台输出成功后，为什么还需在目标环境验证？
