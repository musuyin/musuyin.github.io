L05-Kitex

2026-08-06

Kitex 的定位

Kitex 是 CloudWeGo 的 Go RPC 框架，用于服务之间调用。它围绕接口描述、代码生成、客户端与服务端组织开发，并提供超时、负载均衡、重试等治理能力。HTTP 入口可先参照 Hertz，再通过 RPC 调用内部服务。

原稿为空，本页为依据官方文档新增的入门内容，未声称完成部署或运行验证。

从接口契约开始

RPC 调用的双方先约定服务名、方法、请求和响应。例如，一个问候服务需要声明 Hello(name) 返回问候内容。使用 Thrift 或 Protobuf 等 IDL 后，代码生成工具产生相应的类型和服务代码；业务方填入方法实现，调用方通过生成的客户端发起调用。

  1. 准备 Go 环境与模块，按所选 IDL 安装官方要求的生成工具。
  2. 定义请求、响应与服务方法，并生成代码。
  3. 在服务端实现生成的接口，配置监听地址并启动。
  4. 在客户端配置服务地址或服务发现，调用同一契约中的方法。
  5. 验证成功、超时与错误响应，再逐步接入治理能力。

理解调用边界

本地函数调用成功与远端操作成功不是同一个事件。客户端超时后，服务端可能已经完成业务；因此不能无条件重试写操作。接口需要考虑幂等标识、错误语义和兼容演进。

入门时先用直连方式理解请求链路，再学习服务发现、负载均衡和中间件，避免把注册中心当成运行最小示例的必需条件。
