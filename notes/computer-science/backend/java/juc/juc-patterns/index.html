JUC 模式

2025-10-18

#Java#JUC#并发

并发模式将同步需求组织成可复用协议：保护性暂停交接一个结果，生产者消费者交接持续任务，两阶段终止先发出请求再清理资源。先确定参与者和状态，再核对每个等待者的唤醒与退出条件。

模式

同步模式

保护性暂停

即 Guarded Suspension，用在一个线程等待另一个线程的执行结果（需要强对应）

  • 有一个结果需要从一个线程传递到另一个线程，让他们关联同一个 GuardedObject
  • 如果有结果不断从一个线程到另一个线程那么可以使用消息队列（见生产者/消费者）
  • JDK 中，join 的实现、Future 的实现，采用的就是此模式
  • 因为要等待另一方的结果，因此归类到同步模式

实现

public class GuardedObject {
    // 存储结果
    private Object response;

    // 获取结果
    public Object get() {
        synchronized (this) {
            // 条件不足则等待
            while (response == null) {
                try {
                    this.wait();
                } catch (InterruptedException e) {
                    throw new RuntimeException(e);
                }
            }
            return response;
        }
    }

    // 存放结果
    public void set(Object response) {
        synchronized (this) {
            this.response = response;
            lock.notifyAll();
        }
    }
}

应用

public static void main(String[] args) {
    GuardedObject guardedObject = new GuardedObject();
    new Thread(() -> {
        Object response = guardedObject.get();
        LogUtil.log("Response: " + response);
    }).start();

    new Thread(() -> {
        guardedObject.set("Guarded Object");
    }).start();
}
  • ​join() ​需要等待整个线程运行结束；而这种方法不需要整个线程运行结束再响应
  • 可以各自创建局部变量，不需要全局变量进行传递

超时实现

public class GuardedObject {
    // 存储结果
    private Object response;

    // 获取结果
    public Object get(long timeout) {
        synchronized (this) {
            // 条件不足则等待
            // 开始时间
            long begin = System.currentTimeMillis();
            // 经历时间
            long passedTime = 0;
            while (response == null) {
                // 这一轮循环需要等待时间
                long waitTime = timeout - passedTime;
                // 经历时间超过最大等待时间，退出循环
                if (waitTime <= 0) {
                    break;
                }
                try {
                    this.wait(waitTime);
                } catch (InterruptedException e) {
                    throw new RuntimeException(e);
                }
                // 更新经历时间
                passedTime = System.currentTimeMillis() - begin;
            }
            return response;
        }
    }

    // 存放结果
    public void set(Object response) {
        synchronized (this) {
            this.response = response;
            this.notifyAll();
        }
    }
}

​wait() ​中不能填入 timeout​，因为会有虚假唤醒的情况，导致等待时间不变

犹豫模式 Balking

Balking（犹豫）模式用在一个线程发现另一个线程或本线程已经做了某一件相同的事，那么本线程就无需再做了，直接结束返回

public class MonitorService {
    private Thread monitorThread;

    private volatile boolean stopped = false;

	// 在synchronized中的可以保证可见性，但是如果在其他线程中使用，则不可见，所以还需要加上volatile
    private volatile boolean started = false;

    public void start() {
        LogUtil.log("Try to Start Monitor Service");
        synchronized (this) {
            if (started) {
                return;
            }
            started = true;
        }
        monitorThread = new Thread(() -> LogUtil.log("Starting Monitor Service"));
    }

    public void stop() {
        LogUtil.log("Try to Stop Monitor Service");
        stopped = true;
        monitorThread.interrupt();
    }
}

顺序控制

固定运行顺序

例如：先打印 1 再打印 2

wait/notify
public class Test3 {
    private final static Object lock = new Object();
    private static boolean flag = false;

    public static void main(String[] args) {
        new Thread(() -> {
            synchronized (lock) {
                try {
                    while (!flag) {
                        lock.wait();
                    }
                    t1();
                } catch (InterruptedException e) {
                    throw new RuntimeException(e);
                }
            }
        }, "t1").start();

        new Thread(() -> {
            synchronized (lock) {
                try {
                    while (flag) {
                        lock.wait();
                    }
                    t2();
                } catch (InterruptedException e) {
                    throw new RuntimeException(e);
                }
            }
        }, "t2").start();
    }

    private static void t1() {
        LogUtil.log("1");
        flag = false;
        lock.notifyAll();
    }

    private static void t2() {
        LogUtil.log("2");
        flag = true;
        lock.notifyAll();
    }
}
  1. 需要保证先 wait 再 notify，否则 wait 线程永远得不到唤醒。因此使用了运行标记来判断该不该wait
  2. 如果有些干扰线程错误地 notify 了 wait 线程，条件不满足时还要重新等待，使用了 while 循环来解决
  3. 唤醒对象上的 wait 线程需要使用 notifyAll，因为同步对象上的等待线程可能不止一个

交替输出

线程 1 输出 a 5 次，线程 2 输出 b 5 次，线程 3 输出 c 5 次。现在要求输出：abcabcabcabcabc

wait/notify

关键：使用整型变量来控制类型

public class WaitNotify {
    private int flag;
    private final int N;

    public WaitNotify(int n, int flag) {
        N = n;
        this.flag = flag;
    }

    public static void main(String[] args) {
        WaitNotify waitNotify = new WaitNotify(5, 0);
        new Thread(() -> {
            waitNotify.work(0, 1, "a");
        }).start();
        new Thread(() -> {
            waitNotify.work(1, 2, "b");
        }).start();
        new Thread(() -> {
            waitNotify.work(2, 0, "c");
        }).start();
    }

    private void work(int waitFlag, int nextFlag, String output) {
        for (int i = 0; i < N; i++) {
            synchronized (this) {
                while (this.flag != waitFlag) {
                    try {
                        this.wait();
                    } catch (InterruptedException e) {
                        throw new RuntimeException(e);
                    }
                }
                LogUtil.log(output);
                flag = nextFlag;
                this.notifyAll();
            }
        }
    }
}

Lock 条件变量

因为该例中，线程的唤醒是被控制的（即传入next参数），所以不需要signalAll()​，也就不会产生虚假唤醒了

public class AwaitSignal extends ReentrantLock {
    private final int loopNumber;

    public AwaitSignal(int loopNumber) {
        this.loopNumber = loopNumber;
    }

    public static void main(String[] args) throws InterruptedException {
        AwaitSignal awaitSignal = new AwaitSignal(5);
        Condition a = awaitSignal.newCondition();
        Condition b = awaitSignal.newCondition();
        Condition c = awaitSignal.newCondition();
        new Thread(() -> {
            awaitSignal.work("a", a, b);
        }).start();
        new Thread(() -> {
            awaitSignal.work("b", b, c);
        }).start();
        new Thread(() -> {
            awaitSignal.work("c", c, a);
        }).start();
        // 还需要一个发起者进行唤起
        Thread.sleep(1000);
        try {
            awaitSignal.lock();
            LogUtil.log("Wake up");
            a.signal();
        } finally {
            awaitSignal.unlock();
        }
    }

    public void work(String str, Condition current, Condition next) {
        for (int i = 0; i < loopNumber; i++) {
            lock();
            try {
                current.await();
                LogUtil.log(str);
                next.signal();
            } catch (InterruptedException e) {
                throw new RuntimeException(e);
            } finally {
                unlock();
            }
        }
    }
}

park/unpark

park/unpark以线程为目标

public class ParkUnpark {

    private final int loopNumber;

    public ParkUnpark(int loopNumber) {
        this.loopNumber = loopNumber;
    }

    static Thread t1, t2, t3;

    public static void main(String[] args) {
        ParkUnpark park = new ParkUnpark(5);
        t1 = new Thread(() -> {
            park.work("a", t2);
        });
        t2 = new Thread(() -> {
            park.work("b", t3);
        });
        t3 = new Thread(() -> {
            park.work("c", t1);
        });
        t1.start();
        t2.start();
        t3.start();
        LockSupport.unpark(t1);
    }

    public void work(String str, Thread next) {
        for (int i = 0; i < loopNumber; i++) {
            LockSupport.park();
            LogUtil.log(str);
            LockSupport.unpark(next);
        }
    }
}

必须将 t1​, t2​, t3​ 声明为 static​（或类字段），因为：

  • 你在 lambda 表达式中使用了它们；
  • 它们的赋值发生在 lambda 定义之后；
  • lambda 捕获局部变量时必须是（effectively）final，而类字段没有这个限制。

生产者消费者模式

  • 与前面的保护性暂停中的 GuardObject 不同，不需要产生结果和消费结果的线程一一对应
  • 消费队列可以用来平衡生产和消费的线程资源
  • 生产者仅负责产生结果数据，不关心数据该如何处理，而消费者专心处理结果数据
  • 消息队列是有容量限制的，满时不会再加入数据，空时不会再消耗数据
  • JDK 中各种阻塞队列，采用的就是这种模式

实现

// 线程间通信类
public class MessageQueue {
    public static final class Message {
        private final long id;
        private final Object value;

        public Message(long id, Object value) {
            this.id = id;
            this.value = value;
        }
    }

    // 双向队列存储信息
    private final Deque<Message> list = new LinkedList<>();
    // 队列容量
    private final int capacity;

    public MessageQueue(int capacity) {
        this.capacity = capacity;
    }

    // 获取消息
    public Message take() {
        // 检查对象是否为空
        synchronized (list) {
            while (list.isEmpty()) {
                try {
                    list.wait();
                } catch (InterruptedException e) {
                    throw new RuntimeException(e);
                }
            }
            Message message = list.removeFirst();
            list.notifyAll();
            return message;
        }
    }

    // 存入消息
    public void put(Message message) {
        synchronized (list) {
            while (list.size() >= capacity) {
                try {
                    list.wait();
                } catch (InterruptedException e) {
                    throw new RuntimeException(e);
                }
            }
            list.addLast(message);
            list.notifyAll();
        }
    }
}

终止模式

两阶段终止模式 Two Phase Termination

线程终止的错误思路：

  • ​stop()​

    • ​stop() ​会杀死线程，如果线程锁住了共享资源，那么杀死该线程之后就没有机会释放这些资源了，其他线程的运行会受到影响

  • ​System.exit(int)​

    • 会导致整个程序停止

两阶段终止模式流程：

使用 interrupt

public class Test7 {
    public static void main(String[] args) throws InterruptedException {
        TwoPhaseTermination termination = new TwoPhaseTermination();
        termination.start();
        Thread.sleep(3500);
        termination.stop();
    }
}

class TwoPhaseTermination {
    private Thread monitor;

    // 启动监控线程
    public void start() {
        monitor = new Thread(() -> {
            while (true) {
                Thread thread = Thread.currentThread();
                if (thread.isInterrupted()) {
                    System.out.println("interrupted, dealing with monitor");
                    break;
                }
                try {
                    Thread.sleep(1000);
                    System.out.println("执行监控记录");
                } catch (InterruptedException e) {
                    e.printStackTrace();
                    // 重新设置打断标记，下次再进入循环时就可以正常退出
                    thread.interrupt();
                }
            }
        });
        monitor.start();
    }

    public void stop() {
        monitor.interrupt();
    }
}

注意：sleep() ​被打断后会抛出异常，但是不会导致线程结束，仍会正常执行死循环，所以需要在处理异常时手动修改打断标记，这样才能在下次进入循环时正常退出

使用停止标记

使用 volatile​修饰停止标记——因为只有一个线程会进行写操作，所以只需考虑可见性即可，不用受原子性限制

public class TPTVolatile {
    private Thread thread;
    // 保证共享变量在多个线程之间的可见性
    private volatile boolean stop = false;

    public void start() {
        thread = new Thread(() -> {
            while (true) {
                Thread currentThread = Thread.currentThread();
                // 停止标记
                if (stop) {
                    LogUtil.log("End");
                    break;
                }
                try {
                    Thread.sleep(100);
                    LogUtil.log("Start");
                } catch (InterruptedException e) {
                    LogUtil.log("Interrupted");
                }
            }
        });
        thread.start();
    }

    public void stop() {
        stop = true;
        thread.interrupt();
    }

    public static void main(String[] args) throws InterruptedException {
        TPTVolatile t = new TPTVolatile();
        t.start();
        Thread.sleep(350);
        t.stop();
    }
}

单例模式

考虑在创建和获取单例对象时的线程安全问题

饿汉单例

类加载时就会创建该单例对象

  1. ​final​ 确保类不会被继承，不会被多个子类破坏单例
  2. ​readResolve()​解决反序列化问题：在反序列化对象时会调用该方法，返回创建好的单例模式
  3. 构造方法设为私有，防止直接调用new来创建，但是不能防止反射来创建新的实例
  4. 静态变量的初始化在类加载阶段完成，不会导致线程安全问题
  5. 将instance​设为私有并提供Getter方法：更好封装；懒初始化；泛型支持
public final class Singleton implements Serializable {
    private Singleton() {}
    
    private static final Singleton INSTANCE = new Singleton();
    
    public static Singleton getInstance() {
        return INSTANCE;
    }
    
    public Object readResolve() {
        return INSTANCE;
    }
}

懒汉单例

首次使用该对象时才会创建单例对象

使用 synchronized​修饰了整个方法，虽然保证了没有线程安全问题，但并发度低、效率低

public final class Singleton {
    private Singleton() {
    }

    private static Singleton INSTANCE = null;

    public static synchronized Singleton getInstance() {
        if (INSTANCE != null) {
            return INSTANCE;
        }
        INSTANCE = new Singleton();
        return INSTANCE;
    }
}

DCL

缩小synchronized​范围，提高效率

注意要为 INSTANCE​加上 volatile防止指令重排序，可见基础篇关于DCL的解释

public final class Singleton {
    private Singleton() {
    }

    private static volatile Singleton INSTANCE = null;

    public static Singleton getInstance() {
        if (INSTANCE != null) {
            return INSTANCE;
        }
        // 在创建时加锁
        synchronized (Singleton.class) {	// 会在这里等待锁，其他线程会创建实例
            // double check，可能在执行到这里时，之前有线程恰好创建了实例，防止重复创建
            if (INSTANCE != null) {
                return INSTANCE;
            }
            INSTANCE = new Singleton();
            return INSTANCE;
        }
    }
}

枚举单例

  1. 限制实例个数：枚举类本身特性，只会生成唯一对象（静态成员变量）
  2. 创建时：静态成员变量，在类加载阶段完成创建，无并发问题
  3. 不能使用反射创建，即不会被反射破坏单例
  4. 枚举类默认实现了序列化接口，可以被反序列化，但是保证了反序列化不会破坏单例
  5. 属于饿汉式：在加载时创建单例
  6. 枚举类可以使用构造方法，实现单例创建的初始化逻辑
public enum Singleton {
    INSTANCE;
}

静态内部类单例

  1. 懒汉式：内部类只有在被使用到时才会创建
  2. JVM 会保证创建时没有并发安全问题
public final class Singleton {
    private Singleton() {
    }

    private static class LazyHolder {
        static final Singleton INSTANCE = new Singleton();
    }

    public static Singleton getInstance() {
		// 第一次调用时，才会创建内部类
        return LazyHolder.INSTANCE;
    }
}
