黑马点评项目亮点

2025-05-30

#后端#Java#Project#SpringBoot#Redis

黑马点评的技术点可沿“身份 → 缓存 → 并发扣库存 → 异步消费 → 社交与统计”复习。每个组件都应对应明确的问题和失败路径，避免把使用 Redis 的功能名单直接当作稳定性证明。

  • Session 存储 cookie
  • 使用拦截器读取 Session 内容保存用户信息到 UserHolder
  • 拦截器的使用，因为拦截器是通过 new 获得的而不是 Spring 注入的，所以要通过构造方法将 StringRedisTemplate​ 传入
  • 使用 Redis 存储 token 实现 Session 共享
  • 使用拦截器实现登录状态刷新（刷新 token 的过期时间）
  • 使用 Redis 实现热点内容缓存，减小数据库压力
  • Redis 实现缓存时数据发生更新，如何保证双写一致性
    • 直接删除缓存数据
    • 确保数据库操作和缓存操作同时成功或失败（单体系统：事务；分布式系统：TCC，分布式事务）
    • 先操作数据库，再操作缓存
  • 解决缓存穿透：缓存空对象；布隆过滤
  • 解决缓存雪崩：TTL 添加随机值；Redis 集群；多级缓存
  • 解决缓存击穿（热点 key）
    • 互斥锁：tryLock + DoubleCheck；Redis setnx​
    • 逻辑过期：不设置实际过期时间，而是设置逻辑意义上的过期时间
  • 函数式编程实现 Redis 缓存工具类
  • 使用乐观锁解决库存超卖问题：判断之前查询得到的数据是否被修改过
    • 判断 version
    • 判断内容
  • 使用悲观锁（synchronized​）实现一人一单，使用 Spring 的事务控制，要用代理对象来操作事务
  • 集群下实现一人一单，使用 Redis 实现分布式锁
    • 处理锁误删的情况：添加唯一线程标识，释放锁之前进行判断是否为自己拥有的锁
    • 获取锁、判断锁和删除锁之间存在阻塞的情况：使用 Java 调用 Lua 脚本实现获取判断删除操作的原子性
    • 使用第三方分布式锁库 Redission：可重入；可重试；可超时释放；主从一致
      • 锁重试
      • WatchDog 机制
      • MultiLock
  • 在 Redis 中利用 Lua 脚本实现逻辑判断（判断秒杀名额）
  • 基于 Stream 实现 Redis 消息队列，实现异步秒杀
    • 重复消费问题：ACK 重试和幂等性处理；监控消费者组的 pending 消息数量；对于关键业务，考虑使用事务或两阶段提交；设置合理的消费者超时时间，平衡及时重试和误判风险
  • 使用 Redis SortedSet 实现排行榜功能
  • 数据库关系表实现关注功能
  • 使用 Redis Set 的交集功能实现共同关注
  • Feed 流，推模式实现 Timeline 类型推送
    • 利用 Redis ZSet 按发布时间顺序存储推送内容
    • 使用最小时间戳和偏移量实现分页查询（且不会出现重复查询）
  • 使用 Redis 的 GEO 数据结构实现附近商户功能
  • 使用 Redis 的 BitMap 数据结构实现用户签到记录功能，可计算用户连续登录天数
  • 使用 Redis 的 HyperLogLog 数据结构实现对用户的 UV 统计

复习

  • 库存不超卖、一人一单与消息幂等分别由什么约束保证？
  • token 共享与线程本地用户上下文的生命周期有何不同？
