Kafka

2026-08-31

#待处理

Kafka 的顺序保证以 partition 为单位。设计时同时约束生产路由、重试行为和消费处理顺序；顺序读取、顺序完成与提交进度是三个不同事件。

Kafka 面试要点

消息顺序

Kafka 只保证同一 partition 内按 offset 追加和被单个消费者顺序读取；跨 partition 没有全局顺序。生产和消费的观察顺序也并非天然一致：重试可能乱序，消费并发处理/异步提交也会乱序。

要保证某业务实体的顺序，使用稳定 key（如订单 ID）让它落到同一 partition，生产端开启幂等 enable.idempotence=true 并限制 max.in.flight.requests.per.connection 在幂等语义下的安全范围；消费端让同一 partition 同时只由一个 consumer/顺序 worker 处理，成功后再提交 offset。消费者扩容上限受 partition 数限制；失败重试、死信和幂等消费仍不可省略。

复习

  • 为什么同一个业务键应稳定映射到同一 partition？
  • 消费异步并行时，为什么 offset 顺序不能直接证明副作用顺序？
