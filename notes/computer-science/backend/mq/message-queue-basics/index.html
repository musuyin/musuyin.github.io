消息队列解决什么问题

消息队列在生产者和消费者之间保存待处理消息，让提交任务与完成业务分开。适合异步任务、削峰和多个下游订阅；代价是出现重复、积压和跨系统一致性问题。

原稿只有元信息，以下为本次新增的基础导航。概念与示例可继续阅读 消息队列基本概念。

一条消息的生命周期

  1. 生产者构造含稳定事件 ID 的消息并发布。
  2. Broker 接收并按路由规则保存到队列或日志。
  3. 消费者获取消息，执行业务。
  4. 业务成功后确认处理结果，失败则按规则重试或隔离。

业务写入成功但确认前宕机，可能导致重复投递。因此 ACK 不等于业务幂等；需要以稳定业务键、唯一约束或状态机防止重复副作用。详见 可靠消费与幂等。

队列与日志

传统 RabbitMQ 队列更关注单条任务的投递与确认；Kafka 分区日志将保留与消费位置分离，适合回放与多下游独立消费。选型先明确保留、顺序和确认需求，再比较吞吐。

来源：RabbitMQ 确认机制。
